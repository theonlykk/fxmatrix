## Background

The design spec was closed after six DeepSeek adversarial audit
rounds, two scope decisions (Option B abandoned after its real
coverage proved worthless in practice; Option A — full CloseBy
`DEAL_ORDER` mapping — adopted and empirically verified against 129
real CloseBy events on the live account), and two Gemini policy
rulings (cap-GV sentinel fail-closed semantics; the crash-without-
restart staleness gap accepted as a residual risk rather than solved).
This ADR records what was actually built from that closed design, not
the design rationale itself — see the spec for that.

## Implementation

### Phase A — pure logic (`ea/fxmatrix_v2_state_reconstruction.mqh`)

Side-effect-free implementation of the full v8 design: tiered exit-order
matching (interval-bounded eligibility, global one-to-one assignment),
anchor-finding over entry-magic position IDs, the hedge-to-entry
`DEAL_ORDER` mapping algorithm with its price-consistency check,
path-dependent state replay (`current_add_pips`, `last_exit_valid`,
`last_exit_price`), the full 30-item ambiguity checklist, and
reconstruction validation. 19 unit tests, each tracing to a specific
finding from the design's six-round audit sequence.

Four real bugs were found and fixed during implementation testing, not
caught by compilation alone:

- **Tier-2 matching had no price constraint at all.** The most
  serious of the four — this reopened the same wrong-but-unique
  misassignment risk class the design's tiered approach exists to
  close, via a different path than the one the design audit had
  already closed. Fixed with a bounded rollover tolerance plus
  exclusion of any price that exact-matches a *different* position's
  formula target.
- A global search-abort flag was incorrectly set by an optional
  exploratory branch of the exit-matching recursion, poisoning an
  already-valid result found on an earlier branch — caused a runtime
  crash on the first real exercise of the matching logic.
- The anchor-finding walk evaluated `CloseBy` deal pairs individually
  rather than atomically, producing a false remnant-halt when the two
  legs of a single CloseBy shared a timestamp.
- A general per-order pending-comment check fired before a more
  specific stack-level check could, reporting a technically-valid but
  imprecise halt reason for two of the design's specified cases.

### Phase B — OnInit orchestration (`ea/fxmatrix_v2_sre_oninit.mqh`)

Wires the approved ten-step sequence into `OnInit` for all three
production files (`fxmatrix_v2.mq5`, `fxmatrix_v2_eurusd.mq5`,
`fxmatrix_v2_eurgbp.mq5`), replacing the previous unconditional
"any open position under this side's magic halts" behavior with an
attempt at reconstruction, falling back to an equivalent halt whenever
reconstruction cannot proceed confidently. Implemented as a single,
side-parameterized shared routine per spec §6, not three near-
duplicates. The cap-GV sentinel is written before any deal history is
read; validation is a hard backstop even after every prior check
passes — no partial resume under any circumstance.

`V2_SRE_RunOnInitSidePair` aggregates both sides' results into the
final `OnInit` return value by calling the pre-existing
`V2_OnInitResultFromOrphanFlags` function — the INIT_SUCCEEDED/
INIT_FAILED decision logic itself was not reimplemented, only fed
SRE-derived flags instead of orphan-check-derived ones.

**Alert signature change — flagged explicitly for Pipshed telemetry:**
production `OnInit` halts now emit `ALERT V2_STATE_RECONSTRUCTION_HALT
| instance=<tag> reason=<HALT_NN_REASON> count=<n> tickets=<...>`,
replacing the previous `ALERT V2_ORPHANED_POSITIONS_DETECTED`. The
specific reason enum (one of 30 named values in
`V2SREHaltReason`, `ea/fxmatrix_v2_state_reconstruction.mqh`) is now
included directly in the alert, which the old signature never
provided. The old orphan-guard unit tests still pass because they
exercise the original helper function in isolation — that function is
no longer called by any production `OnInit` path. Any telemetry
consumer or dashboard still matching on the old alert string will not
see this new one.

Testing: 5 aggregation-level test scenarios (both-halt, either-side-
only, both-flat, both-commit), each parameterized across all three
pairs — added specifically to close a gap where the SRE orchestrator's
per-side correctness was proven but the top-level `OnInit` aggregation
wiring was not, the same coverage the old orphan-guard family provided
for the old path.

### Final verification state

552/553 tests passing. The single failure
(`ab ac bid-only equals ac close fallback`) is a pre-existing L0
signal-core test/implementation mismatch, unrelated to this
initiative, predating it, and requiring its own separate decision at
some point — not fixed or altered here.

## Authorization Scope

**This ADR authorizes:**

- The State Reconstruction Engine's existence on disk, in
  `main`, as tested, working code.
- Continued reference to this implementation as the basis for the
  live/demo reattach drill spec §7 requires.

**This ADR does NOT authorize:**

- VPS deployment of any file this initiative touched.
- Attaching any EA build containing this code to a live or demo
  chart.
- Replacing, relaxing, or otherwise modifying the flat-chart
  precondition (see ARCHITECT.md's Operational Safety Rules), which
  remains 100% active regardless of this code's test results.

**Production replacement of the flat-chart precondition requires:**

1. The live/demo reattach drill (design spec §7), proving successful
   reconstruction through real CloseBy history and correct halting on
   deliberately introduced non-standard closures and mismatched
   pairings — not achievable in Strategy Tester by construction.
2. A separate, explicit decision after that drill passes — this ADR
   is not that decision.

Gate 2 (the reattach drill) remains blocked on the same condition it
has been blocked on throughout this initiative: no spare isolated
demo account is currently available.

## Consequences

- Every future OnInit-adjacent change to any of the three production
  files must account for the SRE sequence now running there — this is
  no longer a simple orphan-halt check.
- Pipshed and any other telemetry/alerting consumer needs to be
  updated to recognize `V2_STATE_RECONSTRUCTION_HALT` and its 30
  possible reason codes, not just the old orphan signature.
- The `ab ac bid-only equals ac close fallback` mismatch remains an
  open, tracked item, unrelated to and unaffected by this work.
