# ADR-094 — Restore `open_depth` + `entry_time` to Phase-1 `*_ref` Layer Structs

**Status:** Pending

**Date:** 2026-07-24

---

## Context

Phase-1 parameterized EAs (`fxmatrix_v2_ref.mq5`, `fxmatrix_v2_eurusd_ref.mq5`, `fxmatrix_v2_eurgbp_ref.mq5`) share the same layer struct/array names as production (`LongV2Layer`, `ShortV2Layer`, `g_long_layers[]`, `g_short_layers[]`) but omitted two fields present on the production path:

- `open_depth` — the 0-based stack index at layer **append** time (L0 = 0, first add = 1, …). Set once, never reassigned.
- `entry_time` — the layer open timestamp, set at append via `TimeCurrent()`.

ADR-093 merged carry port + API counter rewire into `_ref`. That pass required `V2EmitScalpClosed`’s 15th argument (`open_depth`) for compile compatibility. Because `_ref` structs lacked the field, all six exit-fill call sites passed a **literal `0`** as a compile-prerequisite stopgap. `_ref` also derived `layer_entry_time` exclusively from `PositionGetInteger(POSITION_TIME)` at exit-fill time, with no struct-first read and silent default to `0` when position resolution failed.

Per Gemini’s ruling, ADR-094 restores production semantics for both fields on the `_ref` path only. Production `.mq5` files are **not** modified.

Read-only confirmation this session (direct reads of `fxmatrix_v2.mq5`, `fxmatrix_v2_eurusd.mq5`, `fxmatrix_v2_eurgbp.mq5`):

- Append functions are named `Long_AppendLayer` / `Short_AppendLayer` with local index `n = ArraySize(g_*_layers)` before `ArrayResize`.
- Production sets `g_*_layers[n].open_depth = n` and `g_*_layers[n].entry_time = TimeCurrent()` once at append.
- Compaction (`Long_RemoveLayerAt` / `Short_RemoveLayerAt`) shifts structs with `g_*_layers[i] = g_*_layers[i + 1]` — `open_depth` moves with the struct unchanged; no reassignment on compaction.
- `_ref` uses the same append function names and the same full-struct copy compaction pattern.

---

## Decision

### 1. Struct fields (all three `_ref` files)

Add to both `LongV2Layer` and `ShortV2Layer`:

```mq5
int      open_depth;   // 0=L0 at fill (Python sim parity; stable after compaction)
datetime entry_time;   // layer open time for resolution metrics
```

No default initializer in the struct — values are set at append, matching production.

### 2. Append wiring

In `Long_AppendLayer` / `Short_AppendLayer`, immediately after `exit_escalated` assignment:

```mq5
g_long_layers[n].open_depth = n;
g_long_layers[n].entry_time = TimeCurrent();
```

(mirrored for `g_short_layers`).

### 3. Exit-fill read logic (six sites: long + short × three files)

Replace lookup-only `entry_time` resolution:

```mq5
datetime layer_entry_time = 0;
if(orig_pos > 0 && PositionSelectByTicket(orig_pos))
   layer_entry_time = (datetime)PositionGetInteger(POSITION_TIME);
```

with production’s struct-first pattern:

```mq5
datetime layer_entry_time = g_long_layers[layer_idx].entry_time;
if(layer_entry_time <= 0 && orig_pos > 0 && PositionSelectByTicket(orig_pos))
   layer_entry_time = (datetime)PositionGetInteger(POSITION_TIME);
```

(mirrored for `g_short_layers` on the short side).

Replace the ADR-093 literal-0 stopgap with a real read:

```mq5
int open_depth = g_long_layers[layer_idx].open_depth;
// ...
V2EmitScalpClosed(..., layer_depth, stack_depth, open_depth);
```

### 4. Fallback-zero logging (Gemini mandate)

Immediately after `layer_entry_time` resolution:

```mq5
if(layer_entry_time <= 0)
   Print("WARNING [ADR-094] layer_entry_time unresolved (both struct "
         "and POSITION_TIME fallback failed). symbol=", _Symbol,
         " layer_idx=", layer_idx);
```

Fires only when both struct value and `POSITION_TIME` fallback yield `<= 0`.

### 5. Unit test

Extend `fxmatrix_v2_ref_tests.mq5` with `Test_RefOpenDepthSurvivesCompaction`, mirroring production’s `Test_TelemetryScalpClosedOpenDepthAndBars` pattern (`fxmatrix_v2_tests.mq5` ~518–525): compaction preserves `open_depth`; after L0 and add1 close, add2 exits at `layer_idx=0` with `layer_depth=1` and `open_depth=2`.

---

## `open_depth` vs `layer_depth` (do not conflate)

| Field | Semantics | When set | Stable across compaction? |
|-------|-----------|----------|----------------------------|
| `open_depth` | 0-based index at **append** (`ArraySize` before resize) | Once at append | **Yes** — travels with struct copy |
| `layer_depth` | 1-based current array position (`layer_idx + 1`) | Recomputed at every exit-fill | **No** — shrinks when lower layers close |

**Concrete compaction example (confirmed this session):**

1. Stack `[L0, add1, add2]` — add2 has `open_depth=2`.
2. L0 exits → LIFO shift → `[add1, add2]`; add2 still has `open_depth=2`.
3. add1 exits → `[add2]`; add2 still has `open_depth=2`.
4. add2 exits at `layer_idx=0` → telemetry emits `layer_depth=1`, `open_depth=2`.

`layer_depth` and `stack_depth` computation are **unchanged** by this ADR.
