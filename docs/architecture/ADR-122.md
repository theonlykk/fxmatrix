# ADR-122: Straddle Churn Fix (ref_mid Goalpost Gate) + Feed Staleness Guard

## Status

Accepted -- 2026-08-28. Gemini ruling (execution-layer regression; no DeepSeek
audit required). Implements straddle L0 churn fix and feed staleness guard at
baseline 316d763. Not committed until independent verification passes.

## Context

ADR-121 fixed one-legged straddle persistence: per-leg retry and goalpost advance
only when BOTH legs are live. On a **frozen terminal feed**, however, a new
regression appeared:

1. **Churn:** The buy leg never placed (marketability skip on stale quotes), so
   `g_straddle_ref_mid` stayed at 0. `V2_DumbShouldRePlace` returns `true`
   whenever `ref_mid <= 0`, so `mid_drifted` was always true. ADR-121's
   `V2_StraddleLegShouldAttempt(live, mid_drifted)` re-quoted the LIVE sell
   every tick — cancel-then-replace churn on a one-legged book.

2. **Root trigger:** The terminal feed was stale (mid frozen identical across
   11+ seconds and across two calendar days). Stale quotes priced the buy
   marketable against the live broker market at receipt, compounding placement
   failure.

## Decision

Per Gemini ruling:

1. **Option A — churn fix (ref_established gate):** A LIVE leg re-quotes ONLY
   when `g_straddle_ref_mid > 0` (straddle completed at least once) AND mid has
   drifted past band. If `ref_mid == 0`, a placed leg RESTs patiently while its
   missing partner retries each tick. Missing legs still retry regardless of
   drift or ref state.

   ```cpp
   bool V2_StraddleLegShouldAttempt(bool leg_live, bool mid_drifted, bool ref_established)
   { if(!leg_live) return true; return (ref_established && mid_drifted); }
   ```

2. **Feed staleness guard:** Refuse to place or update ANY straddle L0 order when
   the feed is stale. `V2_IsFeedStale(symbol, max_age_ms)` is called at the
   very top of `V2_StraddleL0OnTick` (after the `ENTRY_STRADDLE` guard); return
   immediately if stale. Do NOT cancel existing orders on staleness — just stop
   acting.

3. **Staleness clock:** Compare broker tick timestamp
   (`SymbolInfoTick().time_msc`) against a **local monotonic clock**
   (`GetTickCount64()`). Do NOT compare against `TimeCurrent()` / server time —
   it freezes with the feed and the guard would never fire.

   Default threshold: `InpFeedStaleMaxMs = 10000` (10 s).

Entry-side only. ADR-120 exit topology, recognizer, SRE, Trigger A, BCC,
Adr013 clamp, `V2_DumbShouldRePlace`, and `ENTRY_SIGNAL` arm untouched.

## Rejected alternatives

**Option B — per-leg drift tracking:** Separate ref anchors per leg would
complicate anti-thrash semantics and diverge from the shared straddle mid.
Rejected in favor of Option A's single `ref_established` gate on live legs.

**Server-clock staleness (`TimeCurrent()` vs tick time):** Server time freezes
when the terminal feed stalls, so elapsed age would read zero forever. Rejected.

**Cancel resting L0 on staleness:** Would create churn on recovery and is out
of scope; guard only suppresses new placement/update actions.

## Verification

- MetaEditor compile: unified shells + tests — 0 errors / 0 warnings.
- Unit suite: baseline (922/922 post-ADR-121) + T-SL-7..11:
  - **T-SL-7:** Live leg + `ref_mid == 0` does NOT re-quote (churn regression).
  - **T-SL-8:** Live leg re-quotes only when ref established AND drifted.
  - **T-SL-9:** Missing leg retries regardless of drift/ref state.
  - **T-SL-10:** `V2_FeedStaleElapsed` boundary behavior.
  - **T-SL-11:** Harness — new `time_msc` clears staleness; unchanged
    `time_msc` past max_age reports stale.

## Consequences

Positive:
- One-legged churn from `ref_mid <= 0` + always-drift eliminated; live leg rests
  until partner completes the straddle.
- Stale-feed quoting suppressed; no new L0 actions off a dead tick stream.
- Existing resting orders preserved through feed gaps.

Negative / bounded:
- While feed is stale, missing-leg retry is also paused (entire straddle path
  gated). Recovery is automatic on next fresh tick.
- First straddle completion still required before live-leg re-quote on drift
  (by design — Option A).
