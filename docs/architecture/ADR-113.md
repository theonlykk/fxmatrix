# ADR-113: First-Position Genesis Anchor — Deferred by Design

## Status

Accepted (Deferred-by-Design) — 2026-08-12, at HEAD `155324f`. Supersedes nothing; relates to ADR-112 (which shipped the rejection-filter readiness guard and observability but deliberately did not enable first-position reconstruction).

## Context

### Gate 2 first-position case

On a live restart the SHORT side halted with `HALT_09_ANCHOR_NOT_FOUND` because the orphan was the **first-ever managed deal** on its side. `V2_SRE_FindAnchor` (Site 2, `state_reconstruction.mqh`) found no prior flat bucket — no earlier closed cycle whose entry and exit volumes both returned to zero within the lookback window.

Ticket 517307012 (GBPUSD SHORT) is the canonical case: a single open entry position whose own entry deal is the earliest deal in-window, present, and in-horizon. ADR-112 readiness passes this case; the subsequent anchor halt is what ADR-113 evaluated.

### What ADR-112 shipped vs what ADR-113 scoped

ADR-112 (shipped at `155324f`) delivered:

- Rejection-filter readiness guard (`V2_SRE_EvaluateReadiness`, R1–R3)
- Local-first OnInit observability (`V2_SRE_EmitOnInitObservability`)
- HALT_31 / HALT_32 halt codes

ADR-112 **did not** relax `V2_SRE_FindAnchor`. First-position genesis anchor enablement was scoped to ADR-113.

### Phase 1 teardown

DeepSeek R1 performed an adversarial teardown of the candidate genesis-anchor predicate (operator seed + gather-reach + ADR-112 filters). Gemini reviewed the teardown and issued a Defer-by-Design ruling.

## Decision

**DO NOT build the genesis anchor.** No code changes authorized under ADR-113.

- `V2_SRE_FindAnchor` remains as shipped at `155324f`.
- The first-position case stays **fail-closed `HALT_09`** (Site 2: no dual-flat bucket).
- The operator **manually reconciles** the rare genuinely-first-position orphan.
- ADR-112 observability makes this a well-lit path (`halt_site=SITE2_NO_DUAL_FLAT`, structured `DIAG V2_* | event=sre_oninit` line) rather than a forensic exercise.

## Rationale

### Recorded conclusions

1. **Seed-only `(S + F)` is explicitly REJECTED.** It is a deterministic FALSE-COMPLETE bypass — strictly worse than today's fail-closed HALT because it replaces a self-announcing halt with a confident but wrong reconstruction whenever the gather is partial in the right way.

2. **The only feasible automated path re-scopes the operator seed** from a boundary axiom ("managed history begins at T") to a **completeness attestation** ("terminal-visible managed history is complete from T to now"). That attestation:
   - Still depends on operator correctness (not provable in-terminal).
   - Retains a FALSE-COMPLETE residual that fails **silently** when the attestation is wrong.
   - Is strictly worse than the current deterministic, self-announcing `HALT_09`.

3. **In-terminal gather-reach proof (`G`) is unprovable** under ADR-112's premise. If `G` must be an in-terminal proof, ADR-113 as scoped is **infeasible**.

```
AUDIT RESULT / BOTTOM LINE

ADR-113 as scoped is **infeasible** if `G` (“gather provably reaches T”) is required to be an in-terminal proof.

The operator seed `S` is a lower-bound axiom: it asserts where managed history *begins*. No terminal-visible signal can upgrade that axiom into a proof that the loaded deal set is gap-free from `T` to `now`. Every predicate that authorizes genesis without an external completeness witness has a **FALSE-COMPLETE** residual. That is the exact failure class ADR-112 exists to prevent.

If the seed is re-scoped from “managed history begins at T” to “managed history begins at T **and the terminal has complete visible managed history from T to now**,” then a safe predicate exists, but that is a materially stronger operator attestation. It should be named and logged as an attestation, not as a proof.

## Definitions used below

- `T` = operator seed epoch: “no managed history exists on this side/account before T.”
- `W0` = default lookback start = `lookback_from - lookback_sec` (shipped default 90 days).
- `D` = the deal set visible through `HistorySelect`.
- “Managed deal” = deal matching the relevant side/stratum (`symbol`, `direction`, `magic`).

---

## C-A. Seed-only relaxation (S + F, no G)

**VERDICT: UNSOUND. Failure class: FALSE-COMPLETE / catastrophic.**

**Failure mode:** `S` is present and `R1/R2/R3` pass, but `D` is not complete back to `T`. A partial-sync terminal cache can satisfy every ADR-112 filter while omitting deals that are inside the interval `[T, now]`.

A concrete triggering sequence:

1. Operator sets `T` for a side.
2. The terminal has never downloaded a block of managed deals between `T` and the first visible managed deal on that side.
3. `HistorySelect(T, now)` returns `true`; `R1` passes.
4. The currently open position has its `DEAL_ENTRY_IN` visible in `D`; `R2` passes.
5. The open position is younger than the 90-day lookback; `R3` passes.
6. `FindAnchor` sees zero managed entry/exit volume from the window start through the first visible managed deal. The first-position branch would normally `HALT_09`; ADR-113’s seed gate instead treats the window start as a valid genesis.
7. The reconstruction proceeds from a baseline that is “flat” only because the pre-gap deals are missing.

The result is not a false halt; it is a confident but wrong reconstruction. If the missing interval contains a closed cycle, the side is not actually first-position. If it contains an exit that is missing while its entry is visible, the reconstruction may generate a phantom open position. Both are **FALSE-COMPLETE** outcomes.

**Why this is worse than the current HALT:** the current behavior is fail-closed. Seed-only makes the fail-closed path bypassable by a single deterministic configuration flag. The bypass does not depend on an unlikely partial-sync race; it is the designed behavior whenever the seed is set and `D` is incomplete in the right way. A wrong or stale seed is not a probabilistic hazard, it is a permanent disable switch for the safety filter.

---

## C-B. Is “gather provably reaches T” provable in-terminal?

**VERDICT: UNSOUND. No in-terminal signal can prove `G`.**

### Candidate (i): “earliest gathered deal_time <= T”

**UNSOUND.**

A visible deal at or before `T` proves only that the terminal has at least one old deal. It does not prove that the interval between that deal and the next visible deal is gap-free.

Example: `T = Feb 1`; the terminal has a visible managed deal on Feb 1 and another on Mar 1, but the server had a managed deal on Feb 5 that was never downloaded. The condition “earliest visible deal <= T” passes; the gap still exists. A lower bound on observed times cannot prove complement absence.

### Candidate (ii): “HistorySelect(T, now) returned true”

**UNSOUND.**

`HistorySelect` returning `true` means the call succeeded and a selection was performed; it does not certify server-side completeness. ADR-112 already scoped `history_select_ok` as a call-status signal, not a completeness certificate. Using it as `G` is the same category error as using “HTTP 200” to prove a downstream data set is complete.

### Candidate (iii): “gathered_deals count is stable across a re-poll”

**UNSOUND.**

Stability across polls proves only that the visible set did not change between those polls. If the missing interval was never downloaded, it will remain missing; the count will be perfectly stable. Bounding the interval below by `T` does not help, because the missing deals are inside `[T, now]`. Re-poll stability is a liveness property, not a completeness proof.

### Ruling on `G`

`G` is **not provable from any in-terminal signal** under ADR-112’s premise. Every candidate is derived from `D`, and `D` is known to be potentially incomplete. Proving no missing server-side deals requires an authenticated server-side or broker-side completeness view — exactly the class of witness Gemini has rejected as over-engineering.

Therefore, if `G` is kept in ADR-113 as an in-terminal proof obligation, **ADR-113 is infeasible as scoped**.

---

## C-E. Is “genesis is flat” provable, even with S + G + F?

**VERDICT: UNSOUND if `Z` is treated as an independently provable filter term. It is not. `Z` is an axiom consequence of `S`.**

`R2` covers only **currently open positions**. It checks that each open position’s entry is in `D`. It cannot see positions that are already closed.

The dangerous cases:

- A position opened before `T` and closed after `T` is not in the current open list; its entry is outside `[T, now]`; `R2` never looks at it. At time `T`, the account is not flat, but no filter sees it.
- A position opened before the gather’s earliest reach but after `T`, and closed before scan time, is also invisible to `R2`. This is the ADR-112 invisible-closed-cycle problem, recurring here.
- A fully closed cycle entirely before `T`, caused by a wrong seed, leaves nonzero cumulative managed entry/exit before `T`. It is invisible unless some pre-`T` scan has access to those deals.

`R2/R3` can **falsify** `Z` when a current open position has a missing entry or is older than the effective window. They cannot **verify** `Z`. The only source of “no position straddles T” is the operator seed axiom `S`.

So `Z` should not be listed as a separate in-terminal proof. In a safe predicate, `Z` is entailed by `S` plus `G`. If `G` is unavailable, the closed-cycle hole is fatal.

---

## Minimal safe predicate / infeasibility proof

### Infeasibility proof (if `G` must be in-terminal)

Any predicate `P` over `(T, D, current open positions, effective window)` is sound only if it cannot be fooled by a missing server-side deal. But `D` is a terminal-local sample. For any non-trivial gap in `[T, now]`, the missing deals are not in `D`; no computation over `D` can prove they do not exist. Every in-terminal completeness candidate — earliest-visible time, `HistorySelect` success, re-poll stability, ticket contiguity, monotonic timestamp checks — is a property of `D`, and is satisfied by an incomplete `D` as well as by a complete `D`.

Therefore, no in-terminal-plus-seed predicate can both:

1. authorize the genesis anchor for at least one real complete-history case, and
2. guarantee no FALSE-COMPLETE case.

Any predicate permissive enough to accept a complete case will also accept the corresponding incomplete case with a missing deal. The only sound predicate is the status quo: always `HALT_09` for first-position.

That is the infeasibility result.

---

## Final recommendation to Gemini

Report ADR-113 as **infeasible as scoped** if `G` must be an in-terminal proof. The only sound way to enable first-position genesis is either:

1. accept a stronger operator-completeness attestation as an axiom (renamed and logged accordingly), or
2. keep `HALT_09` for first-position cases.

Do not ship seed-only `(S + F)` as a genesis gate. That is a deterministic FALSE-COMPLETE bypass and is strictly worse than the current fail-closed behavior.
```

## Consequences

**Positive:**

- Fail-closed safety preserved; no FALSE-COMPLETE bypass introduced.
- Decision recorded formally; genesis anchor will not be re-litigated without meeting the reopen trigger.
- Operator path for rare first-position orphans is documented and observable (ADR-112 diagnostics).

**Explicit non-goals (this ADR):**

- No genesis anchor implementation.
- No operator seed / completeness attestation machinery.
- No change to `V2_SRE_FindAnchor`.
- The 90-day lookback ceiling is logged separately in ARCHITECT.md (Known Limitation), not here.
