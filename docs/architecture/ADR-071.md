# ADR-071 — ADR-014 Direction Consistency Timer (Detection Only)

**Status:** Committed (pending)

## Context

ADR-014 introduced quote substitution and runtime inventory management, but no periodic verification that `Layer.direction` (set at fill time from `deal_type`) still matches the broker's live `POSITION_TYPE` for each tracked `position_ticket`. A direction belief error corrupts exit limit placement (`PlaceExitLimit` derives exit side from `Layer.direction`) and can produce same-direction hedge legs instead of offsetting pairs.

Investigation (session forensic trace) confirmed that the downstream CloseBy unwind path does **not** reliably contain such failures — see Hard-Kill Rationale below.

## Decision

**Two files changed:**

- `StateEngine.mqh` — new `CheckDirectionConsistency()` immediately after `CheckForOrphans()`
- `FXMatrix.mq5` — `EventSetTimer(5)` in `OnInit()`, `OnTimer()` handler, `EventKillTimer()` in `OnDeinit()`

**First timer on this EA.** MT5 allows one active timer interval per instance; ADR-046 cooldown decay runs on M5 bar close inside `OnTick()`, not on a timer.

### `CheckDirectionConsistency()` behavior

Every 5 seconds, for each layer in `g_inventory_0/1/2` with `position_ticket > 0`:

1. `PositionSelectByTicket(pos_tkt)` — if false, **skip** (closed/stale ticket, not a mismatch)
2. Boolean normalization (never direct integer compare):
   - `is_layer_buy = (layer_dir == DIRECTION_BUY)`
   - `is_broker_buy = (PositionGetInteger(POSITION_TYPE) == POSITION_TYPE_BUY)`
3. If `is_layer_buy != is_broker_buy`:
   - Format critical alert string
   - `Print(alert_msg)`
   - Push to `g_critical_alerts[]` **before** halt/remove
   - `g_halted = true`
   - `ExpertRemove()`
   - `return` (stop scanning)

### Enum-collision finding (critical catch)

| Domain | Buy constant | Integer value |
|--------|--------------|---------------|
| `DirectionType` (`LayerStruct.mqh`) | `DIRECTION_BUY` | **1** |
| MT5 `ENUM_POSITION_TYPE` | `POSITION_TYPE_BUY` | **0** |

A naive `layer_dir == PositionGetInteger(POSITION_TYPE)` would **always fail for long positions** (1 vs 0) without ever firing on genuine mismatches, or would require accidental alignment that never holds for sells (`DIRECTION_SELL = -1`). The entire implementation is built on explicit boolean normalization for this reason.

## Scope boundaries (confirmed)

- **One `position_ticket` per layer** — partial entry fills accumulate volume under the ticket set on first fill; no multi-ticket layer model exists
- **`position_ticket == 0`** — always skip (nothing to verify)
- **`PositionSelectByTicket` failure** — skip, not mismatch (ticket closed or stale)
- **`CheckForOrphans()`** — remains **OnInit-only** per architectural constraint; must not be made timer-callable (transient `EA_MAGIC+2` hedge positions during the CloseBy window would cause spurious orphan halts mid-session)
- **No ordering dependency** between this check and `CheckForOrphans()` — they answer different questions (direction vs existence)

## Hard-kill severity ruling

On confirmed mismatch: **`g_critical_alerts` push → `g_halted = true` → `ExpertRemove()`**, in that order (alert before remove, since `ExpertRemove()` ends event processing).

### Rationale — actual confirmed mechanism (not theoretical)

1. **`HandleExitFill()` removes a layer from `g_inventory` based purely on exit-volume accounting**, with **no dependency** on whether the subsequent CloseBy attempt succeeds (`ExecutionEngine.mqh` ~1074–1103: `remaining_exit_volume` decrement and `ArrayRemove` on volume epsilon; CloseBy is only queued, not awaited).

2. **If the layer's direction was wrong** (e.g. an ADR-014 race or fill-time corruption), the exit fill's hedge leg can open the **same** broker direction as the original entry, not the opposite. `TRADE_ACTION_CLOSE_BY` is then an invalid same-direction pairing and is **rejected by the broker** (`FXMatrix.mq5` `ProcessCloseByQueue()` ~1189–1208).

3. **`ProcessCloseByQueue()` retries the failed CloseBy up to 10 times**, then **silently discards** the task with a WARNING and **no halt, no alert** (~1138–1150, ~1203–1208). Confirmed via code trace: no direction-specific handling; the inline comment assuming "delta-neutral" offsetting legs is **factually incorrect** for the same-direction scenario.

4. **Net result:** two live, unmanaged, **same-direction** positions can remain open on the broker indefinitely, **invisible to the EA's inventory** (the layer was already removed in step 1), and **undetected until `CheckForOrphans()` runs at a future `OnInit`** — which, per session forensic history, is **not guaranteed to happen promptly**.

Hard-kill is justified **more strongly** than a simple "doubled position" theory: the actual failure mode is **silent, unbounded-duration, fully unmanaged exposure** — not a doubled position the EA still tracks in `g_inventory`.

## Detection-only — gating out of scope

This ADR implements **detection and hard-stop only**. It does **not** gate, suppress, or alter entry/add_next/exit placement decisions. A separate future task ("Task C") requires its own **synchronous** direction check at placement time per defense-in-depth architecture ruled in this session.

## Related finding — ProcessCloseByQueue exhaustion gap

**Separate, not implemented here.**

`ProcessCloseByQueue()` discards failed CloseBy tasks after 10 retries without halt or critical alert. This applies to **any** persistent CloseBy failure (ADR-014 direction mismatch, ledger timing, margin constraint, requote) — not only direction errors. Scoped for its own future ADR. **`ProcessCloseByQueue()` is untouched by ADR-071.**

## Negative space

- `CheckForOrphans()` — unchanged, OnInit-only
- `OnTick()` — untouched; check runs exclusively on timer
- Trade placement, sizing, gating logic — untouched
- `ProcessCloseByQueue()`, `HandleExitFill()` — untouched
- ADR-063 alert buffer mechanism — unchanged (new write site only)

## Consequences

- Direction belief errors are detected within ~5 seconds while layers remain in inventory
- Mismatch triggers immediate EA detach with telemetry-visible critical alert
- Does not prevent the race at fill time — that remains Task C scope

## Tests

No new unit tests — logic depends on live `PositionSelectByTicket()` / `PositionGetInteger()` broker state; boolean normalization is specified inline.
