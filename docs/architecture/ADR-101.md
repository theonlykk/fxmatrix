# ADR-101 — Bounded Same-Day Retry for Rollover Exit-Modify Failures (Design A)

**Status:** Accepted (code complete; commit OK tonight; VPS deploy waits for flat account)

**Date:** 2026-07-30

---

## Context

ADR-045 (V2 carry) shifts resting **exit limit** prices once per broker midnight when swap is negative, via `V2_ModifyExitLimitPrice` → `TRADE_ACTION_MODIFY`. DeepSeek trace (2026-07-30) confirmed failure modes with **no same-day retry**:

| Failure mode | Effect before ADR-101 |
|--------------|---------------------|
| Stops level / freeze distance | Modify skipped; stale broker exit until next midnight |
| Transient broker reject | Single attempt; stale until next midnight |
| EA offline at `hour==0` | Rollover skipped for that day (unchanged — Design B deferred) |

Gemini approved **Design A only**: bounded same-day retry using a **datetime timer** (`next_retry_due`), not tick-counting. `V2_ModifyExitLimitPrice` already performs passivity/stops checks — retry reuses that path; no new market-risk logic.

### Critical risk: double-shift

If a layer **succeeds** on the initial daily pass, it must **never** enter the retry pending set. Re-running `V2_RolloverAdjustOneLayer` on an already-shifted `exit_target` would apply swap shift **again** (double-shift). ADR-101 tracks **specific failed `position_ticket`s** only; successful layers are never retried.

## Decision

### 1. Session-local retry state (per side, per EA)

In each production EA (`fxmatrix_v2.mq5`, `fxmatrix_v2_eurusd.mq5`, `fxmatrix_v2_eurgbp.mq5`):

```cpp
V2RolloverSideRetryState g_long_rollover_retry;
V2RolloverSideRetryState g_short_rollover_retry;
```

Struct (in `fxmatrix_v2_carry.mqh`):

```cpp
struct V2RolloverSideRetryState {
   ulong    pending_position_tickets[];  // failed layers only
   int      retry_attempt_count;         // shared across pending set
   datetime next_retry_due;              // timer, not tick counter
};
```

Reset to empty/zero at **start of each daily gate fire** (`V2_RolloverRetryResetState`). Not serialized to GVs; lost on EA restart (acceptable — same as pre-ADR-101 single-shot behavior on restart).

### 2. Initial daily pass records failures

`V2_RunDailyRolloverSidePass` (shared) wraps the per-layer adjust loop:

- **Success** → do nothing (never added to pending)
- **Failure** → `V2_RolloverRetryRecordFailure(state, position_ticket, now, InpRolloverRetryMinutes)` sets `next_retry_due = now + minutes`

### 3. Retry pass (every tick, separate from daily gate)

`V2_RunRolloverRetryPass` in `fxmatrix_v2_carry.mqh`, called from `V2_RunRolloverRetryPasses()` **after** `V2_RunDailyRolloverReconciliation()` in `OnTick`:

| Condition | Action |
|-----------|--------|
| Pending empty | Return |
| `TimeCurrent() < next_retry_due` | Return (timer guard) |
| `retry_attempt_count >= InpRolloverMaxRetries` | Return |
| Else | For **each pending ticket only**, lookup layer by `position_ticket`, call adjust; remove on success |
| After pass | Increment counter **once**; set `next_retry_due = now + minutes` |
| Counter reaches max with pending left | Unconditional `ERROR [V2-ADR-101]` log listing tickets; no further attempts until tomorrow's gate reset |

### 4. New inputs (all three production EAs)

| Input | Default | Range (review) |
|-------|---------|----------------|
| `InpRolloverRetryMinutes` | 10 | 5–15 min |
| `InpRolloverMaxRetries` | 15 | 10–20 |

### 5. Observability fix (bundled)

`V2_ModifyExitLimitPrice`: modify-failure `WARNING [V2-ADR-045]` now prints **unconditionally** (not gated on `InpVerboseLog`). Passivity/stops skip messages remain verbose-gated.

## Double-shift guard — design + tests

**Design:** Only tickets returned `false` from the initial daily adjust are appended to `pending_position_tickets`. Retry pass iterates **only** that array.

**Test 6a (`Test_RolloverRetryDoubleShiftGuard`):** Two layers on daily pass — ticket 100 succeeds, 200 fails. Asserts:

1. Ticket 100 **not** in pending after daily pass
2. Ticket 200 **in** pending
3. After retry pass (due elapsed): adjust **never** called for ticket 100
4. Ticket 100 `exit_target` **unchanged** after retry pass
5. Ticket 200 cleared from pending after successful retry

Uses test hook `g_v2_rollover_use_test_adjust` — no broker orders required.
