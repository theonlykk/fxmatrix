# ADR-078 — TEMPORARY: ExitResetDelaySeconds (LIFO Exit Cancel-Replace Gate Bypass)

**Status:** TEMPORARY / TEST INFRASTRUCTURE — not a permanent architectural decision

## Problem

After a LIFO partial exit, the Phase 3 cancel-replace path (`ExecutionEngine.mqh`, partial-unwind branch) cancels the stale `add_next` limit and **immediately** resubmits a replacement in the same call stack. That inline resubmit bypasses:

- `MinLayerIntervalSeconds` (deepening pace gate)
- `KineticGateOpen()` (sigma / velocity gate)

Option B in `OnTick` (`FXMatrix.mq5`) already re-arms `add_next` when it is zero, but it could not distinguish *why* `add_next` was zero. A LIFO scratch that resubmitted inline never left a deferrable empty state — Option B's gates were blind to exit-triggered resets.

## Symptom: Elastic Snapback

With hybrid grid spacing (`GridMode=2`), outer layers are intentionally wide. Every LIFO scratch followed by an **instant** tight re-quote at the new shallowest anchor erased the elastic spacing the grid had built. The book snapped back to near-minimum interval after every exit fill, as if the wide hybrid geometry had never been earned.

## Decision

Introduce a **dedicated** re-engagement delay, separate from deepening pace:

| Mechanism | Governs | Timer |
|-----------|---------|-------|
| `MinLayerIntervalSeconds` | Pace of **new layer adds** (post-fill deepening) | `g_last_layer_time` (add-only, unchanged) |
| `ExitResetDelaySeconds` | Pace of **re-arming add_next after LIFO exit scratch** | `g_last_exit_reset_time` (new, exit-only) |

Staff Architect ruling: deepening pace and re-engagement pace are **different questions** and must not share one timer.

## Inputs (test infrastructure)

```mql5
input bool DebugEnableExitResetDelay = false;
input int  ExitResetDelaySeconds     = 30;
```

| Toggle | `false` (default) | `true` |
|--------|-------------------|--------|
| `DebugEnableExitResetDelay` | **Today's exact behavior** — LIFO cancel then immediate inline `PlaceNextEntryLimit` | Arm `g_last_exit_reset_time[inst]`; defer placement to OnTick Option B |

## Global

```mql5
datetime g_last_exit_reset_time[3] = {0, 0, 0};
```

- Non-zero → exit-triggered reset pending; Option B gates on `ExitResetDelaySeconds`.
- Zero → normal deepen-cycle empty state; Option B gates on `MinLayerIntervalSeconds` (unchanged).

## Code paths

### LIFO branch (`ExecutionEngine.mqh`)

Cancel logic (stale ticket removal, `g_add_next[inst] = 0`) **unchanged**.

Resubmit block:

- `DebugEnableExitResetDelay=false` → existing immediate `ComputeNextLayerPrice` + `PlaceNextEntryLimit` on **new shallowest** (index 0). Byte-for-byte equivalent to pre-ADR-078 production.
- `DebugEnableExitResetDelay=true` → set `g_last_exit_reset_time[inst] = TimeCurrent()` only; no placement.

### OnTick Option B (`FXMatrix.mq5`)

Inside `if (inst_inv_size > 0 && inst_add_next == 0)`:

1. If `g_last_exit_reset_time[inst] > 0` → `timing_ok = elapsed >= ExitResetDelaySeconds`
2. Else → `timing_ok = elapsed >= MinLayerIntervalSeconds` (existing)
3. Both paths still require `KineticGateOpen(inst, inst_inv_size)`
4. On successful placement when exit-reset pending → clear `g_last_exit_reset_time[inst] = 0`

## Neutral-default correctness

When `DebugEnableExitResetDelay=false`:

- LIFO resubmit runs inline exactly as before; `g_last_exit_reset_time` is never set.
- Option B sees `exit_reset_pending=false` and uses `MinLayerIntervalSeconds` only — identical to pre-ADR-078 Option B.
- No new timers participate in production behavior.

## Negative space (untouched)

- LIFO cancel logic
- Full-pod-close branch (`remaining==0`)
- `HandleEntryFill` post-fill deepening gate
- `g_last_layer_time` semantics (add-only)
- `ComputeNextLayerPrice` / `PlaceNextEntryLimit` internals

## Deployment warning

**DO NOT** enable `DebugEnableExitResetDelay=true` on live or demo deployments without explicit backtest validation. This ADR is temporary test infrastructure to measure whether deferred re-engagement preserves hybrid spacing through LIFO exit cycles.

**Test 54** in `temp/run_tests_0_41.py` — pure Python mirror of LIFO defer vs immediate resubmit and Option B timing fork (exit-reset vs normal deepen-cycle), confirming independent timers and shared `KineticGateOpen` requirement.
