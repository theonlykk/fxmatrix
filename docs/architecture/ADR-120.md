# ADR-120: Market-Close Execution Topology (Opposing Hedge & CloseBy)

## Status

Accepted -- 2026-08-28. Gemini ruling (Option B only). Implements the
market-harvest mechanism change at baseline f74a180; supersedes the plain-
position-close fallback introduced in commit 22fec42. Unit suite extended with
T-B-1..7 (Option B regression gate). Not committed until independent
verification passes.

## Context

At f74a180 the exit-fallback harvest path (22fec42) closes the underlying
layer position with a position-scoped `TRADE_ACTION_DEAL`, producing a plain
`DEAL_ENTRY_OUT` stamped `exit_magic`. Two independent failures follow:

**D1 (live, Trigger A):** The exit recognizer (`V2_IsManagedExitDeal`) requires
`DEAL_ENTRY_IN`. A plain OUT deal is invisible to the exit branch, so the
managed layer is never removed while the broker position is flat. Trigger A
observes `managed=1, broker=0` and halts after the 2-tick debounce
(`CRITICAL TA | signal=DIVERGENCE`, 20260828 ~04:10 server time on EURUSD long).

**D2 (latent, SRE HALT_23):** The same plain-OUT footprint is a non-standard
entry-position close in SRE history. On the next non-flat reattach,
`V2_SRE_CheckNonStandardClosures` returns `HALT_23_NON_STANDARD_ENTRY_CLOSE`.
DeepSeek T-1 confirmed the mechanism; live deal 508190031 (position_id
530008594, entry=OUT, magic=21260913) demonstrates the footprint is real.

The resting-limit exit path already uses the correct topology: open an opposing
leg at `exit_magic` (`DEAL_ENTRY_IN`), then resolve via CloseBy to terminal
`DEAL_ENTRY_OUT_BY`. Recognizer, SRE, Trigger A, and BCC all handle that shape
natively.

## Decision

**Option B (binding):** Make the market harvest use the same open-opposing-leg
+ CloseBy topology as the resting-limit exit. When the harvest trigger fires
(`V2_ExitShouldHarvestAtMarketPure`: long `bid >= target`, short `ask <= target`):

1. Send `V2_OpenExitHedgeAtMarket` — a market order **opening** an opposing
   position (`TRADE_ACTION_DEAL`, `req.position` unset, opposite type, magic =
   `exit_magic`, comment `"V2_Exit"`, IOC filling).
2. On full fill: store the hedge **order** ticket as `exit_ticket`, set in-memory
   `exit_is_market_hedge = true`, and let the existing deal handler + CloseBy
   queue produce terminal `OUT_BY`.
3. On confirmed exit fill in the deal handler: route harvest telemetry to
   `V2_HarvestRecordMarket` when `exit_is_market_hedge`, else
   `V2_HarvestRecordLimit` (unchanged limit path).

The harvest **trigger** predicate is unchanged; only the **mechanism** changes.

### Execution policies

| Outcome | Policy |
|---------|--------|
| **Full fill** | Store hedge order ticket + flag; deal handler removes layer, queues CloseBy, records MARKET harvest. |
| **Partial fill** | Halt the side (`g_*_halted = true`), push alert `V2_EXIT_HEDGE_PARTIAL`, do **not** store `exit_ticket`, do **not** CloseBy. |
| **Rejected** | Do **not** halt. Fall through to STEP 2/3 (stretch + passive limit). Retry hedge on subsequent ticks while still through-target. |

No code path may emit a plain `DEAL_ENTRY_OUT` stamped `exit_magic`.

### Inviolates-nothing constraint

Zero change to: `V2_IsManagedExitDeal` (recognizer), SRE modules
(`state_reconstruction.mqh`, `sre_oninit.mqh`), Trigger A
(`fxmatrix_v2_trigger_a.mqh`), or BCC. The exit-magic hedge is invisible to
Trigger A's entry-magic broker count; terminal `OUT_BY` is SRE-native.

## Rejected alternatives

**Option A — broaden the recognizer to accept plain OUT:** Would remove the
layer on D1 but leaves the anomalous OUT footprint in history, arming HALT_23
on reattach (DeepSeek T-1). Rejected.

**Options C+D — dedicated recognizer branch + SRE exemption + replay
synthesis:** Would patch around the footprint rather than eliminating it.
Violates Gemini's SRE-inviolability rationale and adds replay complexity
(DeepSeek comparative). Rejected.

**Retain plain-close as fallback:** Pollutes history; rejected explicitly in the
Gemini ruling.

| Change | Location | Summary |

## Verification

- MetaEditor compile: unified test shells — 0 errors / 0 warnings (authoritative).
- Unit suite: baseline + T-B-1..7:
  - **T-B-1:** Hedge open (not position close), ticket stored, flag set.
  - **T-B-2:** Exit IN recognized, CloseBy queued, OUT_BY terminal, layer nets flat.
  - **T-B-3:** Multi-layer reattach after Option B harvest — no HALT_23 (plain OUT contrast halts).
  - **T-B-4:** Entry-magic broker count matches managed through harvest window; no TA halt (old D1 path would halt).
  - **T-B-5:** Partial fill halts side, no CloseBy, alert pushed.
  - **T-B-6:** Full rejection — no exit_ticket, no halt, falls through to limit.
  - **T-B-7:** Harvest telemetry records MARKET not LIMIT for Option B fill.
- Grep gate: zero references to `V2_CloseExitAtMarket` or
  `V2_BuildExitMarketCloseRequest` under `ea/`.

## Consequences

Positive:
- Market harvest produces the same terminal deal shape as limit harvest; D1 and
  D2 eliminated without touching recognizer, SRE, Trigger A, or BCC.
- Partial-fill and rejection policies are explicit and test-covered.
- `V2_ExitShouldHarvestAtMarketPure` remains the single harvest-trigger source
  of truth.

Negative / bounded:
- Partial hedge fill halts the side and requires manual reconciliation (by
  design — no algorithmic residual management).
- Rejected hedge orders retry/fall back to limit placement; transient spread
  conditions may delay harvest by one or more ticks.
- `exit_is_market_hedge` is in-memory only; mid-window reattach remains governed
  by the accepted HALT_01 crash-in-window policy (DeepSeek T-2).
