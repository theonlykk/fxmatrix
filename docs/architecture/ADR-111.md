# ADR-111: SRE -> Unified V2 Engine Merge (OnInit Reconstruction Transplant)

## Status

Accepted - Gate 1 parity 10/10 EXACT; Gemini authorized commit (2026-08-11). Compiles 0/0 on all three unified shells. Step 4 (Tier 1 real-data fixture on the integrated stack, target 607/615) is the immediate post-commit validation; live Gate 2 (orphan-reattach on the unified binary) is future and gated behind Step 4.

## Context

The Unified V2 Engine (ADR-105) was built before the State Reconstruction Engine and was execution-blocked pending the SRE merge - it carried the pre-SRE orphan path (`V2_ScanInstanceOrphanPositions` / `V2_ProcessOrphanStartupCheck` / `V2_OnInitResultFromOrphanFlags`), which halts on any orphan rather than reconstructing. ADR-106 built SRE; ADR-109/110 completed its entry-pending sweep surface. This ADR transplants the SRE OnInit path into the unified engine so the unified binary reconstructs orphaned books on restart like production.

The merge scope was re-derived from source at `d9771ff` (see `sre_unified_merge_scoping_map_v2.md`), correcting the stale `7ecfe96` map. Two findings shaped it: the `*Engine.mqh` files (`StateEngine`, `ExecutionEngine`, etc.) are stale V3-triad orphans NOT in the unified V2 compile closure and were left untouched; and the SRE surface had grown (ADR-109/110), so the flat-side sweep wiring ports too.

## Decision

Three edits to `fxmatrix_v2_engine.mqh` only (all other files unchanged):

1. Port `V2_ApplyLongSRECommit` / `V2_ApplyShortSRECommit` verbatim (the `LongV2Layer` / `ShortV2Layer` structs are byte-identical between production and the unified engine, and all commit-written globals exist), plus a 3-line `V2_SRE_CapBridgeFromProfile` helper.
2. Replace the old orphan path with the SRE build/run/commit/sweep block: config-build from `g_preset` + shell inputs, `V2_SRE_RunOnInitSidePair`, commit/halt handling, and the two ADR-110 flat-side sweep calls.
3. Change the OnInit return to `agg.init_result`.

### The four wiring points and their resolution

- **Config-build (#1):** magics / symbol / instance tags from `g_preset`; numeric params (`InpLotSize`, `InpExitPips`, `InpAddPipsFloor`, `InpWidenRatio`, `InpAddPipsCeiling`) from shell inputs; `layer_count` from `ArraySize(g_*_layers)`.
- **Cap routing (#2):** a trivial 1:1 map `cap_profile -> cap_bridge` kind (`GBP_ONLY->GBPUSD`, `EUR_ONLY->EURUSD`, `DUAL_GBP_EUR->EURGBP_DUAL`). SRE's kind-dispatched cap-publish (`V2_GbpCapSyncInstance` / `V2_EurCapSyncInstance`) writes byte-identical cap-GVs to the unified `V2_Cap_Sync` bridge - verified they funnel to the same functions with the same symbol - so no rerouting was needed.
- **Layer commit (#3):** the ported commit functions write into `g_long_layers` / `g_short_layers`; struct parity confirmed field-by-field.
- **Flat-side sweep (#4):** two `V2_SweepFlatSideEntryPendings` calls sourced from `g_preset` (the ADR-109 orphaned-side sweep needs no wiring - it is inside `V2_SRE_RunSideOnInit`).

The reconstruction logic (`state_reconstruction.mqh`, `sre_oninit.mqh`) is unchanged by the merge - only its input sourcing (production Inp/magic constants -> `g_preset` + shell inputs) differs.

## Gate 1 Parity

Production vs the merge-wired unified candidate, EXACT match on all 10 suites (calm: `gbpusd_5day`, three `full_quarter`; stress: three `truss_crisis` (2022), three `vaccine_rally` (2020-21)), on the ARCHITECT.md dual-tolerance criteria: identical `V2_STATS` counts, identical combined P&L, identical cap-block sequences.

Integrity-guarded to avoid a vacuous pass: an earlier run showed "EXACT MATCH" on all-zero trades, caused by a stale pre-merge binary in the desktop parity terminal AND a close-only account in the `.ini`. Both were corrected (current source recompiled 0/0 into the parity terminal; account set to 1514123579). The accepted run confirmed, per suite, real non-zero activity (counts L12 to S353) and the correct authorized login, across 693K-8.9M ticks per window.

## Consequences

**Positive:**
- The unified binary now reconstructs orphaned books on restart (SRE), unblocking ADR-105.
- Gate 1 proves the baseline trading loop is byte-identical to production across calm and crisis-era windows.
- Reuses the proven, drill-validated SRE reconstruction + sweep logic unchanged; only input sourcing was rewired.

**Scope / trade-offs:**
- Gate 1 does NOT exercise the SRE reconstruction path (Tester inits flat). That path has unit coverage (Tier 1 607/615) and its live proof is the future Gate 2.
- Step 4 (Tier 1 on the integrated stack) is required before Gate 2 per Gemini's ruling.
