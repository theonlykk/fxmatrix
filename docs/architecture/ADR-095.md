# ADR-095 — Port L0 Requote Deadband into Phase-1 `*_ref` EAs

**Status:** Pending

**Date:** 2026-07-24

---

## Context

Phase-1 `_ref` EAs (`fxmatrix_v2_ref.mq5`, `fxmatrix_v2_eurusd_ref.mq5`, `fxmatrix_v2_eurgbp_ref.mq5`) had **zero L0 deadband protection**. Every flat-L0 bar unconditionally cancelled and replaced the resting L0 limit order.

Confirmed impact this week on the GBPUSD 5-day parity window (`2026.03.09`–`2026.03.14`):

- `_ref` (no deadband): **1,391** `order canceled` journal lines
- Production (deadband active, `InpL0DeadbandMult=1.0`): **1,099** cancels — **292 fewer** (~21% L0 churn reduction)
- Trade counts (l0/add/reload/exits) were **identical** — deadband affects requote volume, not which orders eventually fill

This recreates the mechanism behind a real FTMO hyperactivity incident: **2,928 actions/day vs. a 2,000/day limit**. Gemini classified deadband restoration as **critical / survival priority** for `_ref` deployment.

Production implements ADR-017 deadband in `fxmatrix_v2_logic.mqh` (lines 298–329):

- `V2_L0RequoteDeadband` — band width: `multiplier * (quote_spread * 0.25 - 0.5 * _Point)`, optionally scaled by `pair_spread_pips_ref / V2_L0_DEADBAND_VOL_REF_PIPS`
- `V2_L0RestingWithinDeadband` — skip cancel+replace when `|new_price - current| < deadband`
- `V2_L0_DEADBAND_VOL_REF_PIPS = 0.64` — GBPUSD anchor (denominator only)

`_ref` used `fxmatrix_v2_logic_r1.mqh`, which had **none** of the above (grep: zero `DEADBAND` matches pre-ADR-095).

Prior `_ref` defects coupled to the same code path:

1. `Long_/Short_ReplacePendingBuy/Sell` were **`void`**, always cancel+replace
2. `event=l0_quote` DIAG logged **unconditionally** every flat-L0 bar — not gated on successful requote (production gates on `bool` return)
3. No `g_*_stat_l0_requote` / `g_*_stat_l0_deadband_skip` counters in `V2_STATS_*` output

---

## Decision

### 1. Port deadband helpers into `logic_r1.mqh`

Copy verbatim from production `fxmatrix_v2_logic.mqh`:

- `#define V2_L0_DEADBAND_VOL_REF_PIPS 0.64`
- `V2_L0RequoteDeadband`
- `V2_GetPendingOrderPrice` (dependency — was not in `logic_r1.mqh`)
- `V2_L0RestingWithinDeadband`

Production `logic.mqh` unchanged.

### 2. Inputs (all three `_ref` files)

```mq5
input double InpL0DeadbandMult = 1.0;   // ADR-017: 1.0=V1 parity; 2.0/3.0=wider L0 skip band
```

EURUSD `_ref` additionally:

```mq5
input bool InpL0DeadbandVolScale = true;  // scale band by V2_PAIR_SPREAD_PIPS_REF vs GBPUSD (0.64)
```

Default `InpL0DeadbandMult=1.0` matches production → `_ref` should match **deadband-active** production churn figures, not the no-deadband control run.

### 3. Vol-scale wiring — EURUSD only

Production uses 5-argument deadband + helper **only** on EURUSD:

```mq5
double EurUsd_L0DeadbandSpreadRef() {
   return InpL0DeadbandVolScale ? V2_PAIR_SPREAD_PIPS_REF : 0.0;
}
```

`V2_PAIR_SPREAD_PIPS_REF` for EURUSD is **0.18** in both production and `_ref`'s `pair_config.mqh` — confirmed match, no value correction.

GBPUSD and EURGBP production use **3-argument** deadband only (no vol-scale). `_ref` mirrors this — no `InpL0DeadbandVolScale` on those files.

### 4. `void` → `bool` on ReplacePending functions

Change `Long_ReplacePendingBuy` / `Short_ReplacePendingSell` to `bool` in all three `_ref` files:

1. If within deadband → increment `g_*_stat_l0_deadband_skip`, return `false`
2. Else cancel+replace → if new ticket > 0, increment `g_*_stat_l0_requote`, return `true`; else `false`

### 5. Gate L0 DIAG logging on return value

Replace unconditional:

```mq5
Long_ReplacePendingBuy(...);
if (InpVerboseLog) Print("DIAG ... event=l0_quote ...");
```

with production pattern:

```mq5
if(Long_ReplacePendingBuy(...) && InpVerboseLog)
   Print("DIAG ... event=l0_quote ...");
```

This fixes the logging discrepancy that made `event=l0_quote` line counts invalid parity signals.

### 6. Stats counters

Add to each `_ref` file (long and short):

```mq5
int g_long_stat_l0_requote;
int g_long_stat_l0_deadband_skip;
```

Include in `V2_STATS_LONG |` / `V2_STATS_SHORT |` OnDeinit lines, matching production field order.

### 7. Unit test

Extend `fxmatrix_v2_ref_tests.mq5` with `Test_L0DeadbandCoreMath` — tests `V2_L0RequoteDeadband` width formula (base, multiplier, EUR vol-scale) and strict less-than threshold comparison. No broker dependency for core math (unlike ADR-094 compaction, which requires EA-local functions).

## Negative space

- Do **not** add vol-scale to GBPUSD or EURGBP `_ref` — production does not have it
- Do **not** modify production files
- Do **not** touch ADR-093/094 artifacts (carry, API counter, `open_depth`/`entry_time`)
- Do **not** touch GBP cap (`cross_exposure_cap.mqh`, init wiring) — ADR-096, separate
