# ADR-062 — DirectionalBias Perimeter Seal (SNIPER + Phase-3 + Execution Backstop)

**Status:** Committed

## Context

ADR-058 introduced `DirectionalBias` gating for MM Layer 0 quoting only (`FXMatrix.mq5` ~478–514). Its negative-space clause explicitly left the SNIPER live-signal path and Phase-3 pod-flat resume quoting untouched. Deployment topology assigns `BIAS_LONG_ONLY` / `BIAS_SHORT_ONLY` to SNIPER instances (ADR-058 deployment table), creating a structural mismatch: configured bias applied to MM but not to the execution paths SNIPER and Phase-3 actually use.

### Live evidence (2026-06-30 / 2026-07-01)

Log forensics confirmed **7 bias-violating fills** before this ADR:

## Decision

Three-part perimeter seal (Gemini ruling):

### Ruling 1 — SNIPER live-signal path (`FXMatrix.mq5`)

Immediately before `PlaceEntryLimit(active_price, active_dir, …)` inside the “Place single-sided limit” block: if `active_dir` contradicts `DirectionalBias`, log at INFO and skip placement. Cancel-stale, expiry, deadband, and rollover logic above remain unconditional. SNIPER signal math (`inst_spread`, `active_dir` derivation) untouched.

```
INFO: Valid signal suppressed by DirectionalBias. instrument=… direction=… bias=…
```

### Ruling 2 — Phase-3 pod-flat resume (`ExecutionEngine.mqh` ~1189–1207)

Wrap existing ADR-043 `SameDirectionInventoryExists` checks inside the same bias conditions as MM Layer 0:

- Bid branch: `bid_price > 0 && DirectionalBias != BIAS_SHORT_ONLY`
- Offer branch: `offer_price > 0 && DirectionalBias != BIAS_LONG_ONLY`

ADR-043 log lines preserved exactly, nested one level deeper.

### Ruling 3 — Execution-layer backstop (`ExecutionEngine.mqh`)

At the **top** of `PlaceEntryLimit()` and `PlaceNextEntryLimit()` (before any pricing or passivity logic):

```mql5
if ((direction == DIRECTION_BUY && DirectionalBias == BIAS_SHORT_ONLY) ||
    (direction == DIRECTION_SELL && DirectionalBias == BIAS_LONG_ONLY)) {
    Print("CRITICAL: Orthogonal exposure leak blocked at execution layer. ",
          "direction=", direction, " bias=", DirectionalBias,
          " instrument=", symbol);
    return 0;
}
```

`PlaceNextEntryLimit` uses `prev_layer.direction` at function entry (before gap-aware pricing).

SNIPER suppression = INFO (expected routine). Backstop = CRITICAL (defense in depth; should never fire if perimeter gates work).

## Reversal of ADR-058 negative space

ADR-058 stated: “SNIPER mode quoting block untouched.” ADR-062 **reverses** that clause. SNIPER now receives perimeter gating at placement (Ruling 1) plus execution backstop (Ruling 3). Phase-3 resume quoting is also newly gated (Ruling 2).

MM Layer 0 gate (~478–514) unchanged. Exit placement unchanged.

## Consequences

- SNIPER and Phase-3 resume can no longer open orthogonal Layer 0 / add-next entries against configured bias
- Execution backstop catches any future call-site regression before `OrderSend`
- Test 48 locks suppression and backstop logic in pure Python
- Test 45 subtests 45i/45j (add_next always permitted) reflect pre-ADR-062 ADR-058 intent; Ruling 3 now blocks contradictory add-next at execution layer

## Negative Space

- **`PlaceExitLimit()` untouched** — exits always permitted regardless of bias (Tests 45g/45h)
- SNIPER signal-generation math untouched
- MM Layer 0 gate untouched
- ADR-061 (`ComputeLDAKLotSize` split gate, partial-unwind logging) untouched
- ADR-056 restitution untouched
- `ComputeNextLayerPrice()` untouched
