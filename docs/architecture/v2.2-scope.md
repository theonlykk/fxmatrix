## 1. WHY A BATCH, WHEN, WHERE

- One EA (`main`) for every IC box; a batch means one compile and one
  restart per box instead of one per fix.
- **When:** after the C63 roll-watch (a few days; cycle-4 note s8.12
  step 4), so any lattice fix it finds rides along, and after Friday's
  export confirms C86 on a larger Wednesday sample.
- **Where:** wine-c, then wine-test, by compile in session (the C63
  pattern: stage 1 only, no input change unless an item needs one);
  wine-d gets it at its attach (C85). **The VPS stays on `5685e4f`**
  until cycle 3 ends (geometry-cycle3 A4).

## 2. IN (proposed core)

**V1-V4: the carry multiplier (C86) and same-price modifies (C60).**
- The pass prices the rollover it is about to cross: multiplier of the
  pass's own server day (Mon 1, Tue 1, Wed 3, Thu 1, Fri 1 per the
  ledger; the weekend passes are incomplete anyway). VERIFIED in
  source: `Grind_CarrySwapMultiplier` returns 0 for Saturday and Sunday,
  3 for the broker's `SYMBOL_SWAP_ROLLOVER3DAYS` (Wednesday on both) and
  1 otherwise, so passing `day_of_week` instead of `day_of_week + 1`
  gives exactly Mon 1, Tue 1, Wed 3, Thu 1, Fri 1: a one-argument change
  at 1114 (and 1330).
- The snapshot's `mult_tomorrow` follows the same rule (V2), or is
  renamed to say what it is.
- A modify whose normalised price equals the order's price is not sent:
  commit the accrual and count it apart (`unchanged`), not as `failed`.
- An ADR-135b amendment records the ledger evidence (study s12.7) and
  withdraws "settled empirically". Tests whose expectations change:
  CS4 (if the function changes), CS8 (`mult_tomorrow`), CX3 (pending).
- Effect today: each exit mis-shifted by up to two nights' swap for a
  day (Tue, Wed) or the weekend (Fri); never accumulates (V3). Economic.

**V5: C79.** A full reset of the snapshot flag when the gate day
