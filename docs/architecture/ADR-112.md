# ADR-112: SRE OnInit Rejection-Filter Readiness Guard + Local-First Observability

## Status

Accepted — implementation at HEAD `bc4fdd4` + this ADR. Gate 2 first-position anchor remains deferred to ADR-113.

## Context

### Root cause recap (Gate 2)

On a live restart the SHORT side halted with `HALT_09_ANCHOR_NOT_FOUND` because the orphan was the **first-ever managed deal** on its side. `V2_SRE_FindAnchor` (Site 2, `state_reconstruction.mqh` line 823) found no prior flat bucket — there was no earlier closed cycle whose entry and exit volumes both returned to zero within the lookback window.

Ticket 517307012 (GBPUSD SHORT, magic 20260902/20260904) is the canonical Gate 2 case: a single open entry position whose own entry deal is the earliest deal in-window, present, and in-horizon. Readiness passes this case; the anchor halt is ADR-113 territory.

### DeepSeek two-worlds proof

DeepSeek proved (and Gemini ruled) that **no in-terminal signal can prove history completeness**. Two worlds are indistinguishable to the EA:

1. A truly complete gather.
2. A partial gather missing a closed cycle whose entry precedes lookback-start and whose exit lands inside the window.

Therefore any positive "history is complete" verdict from terminal APIs alone is unsound. The first-position anchor requires an external, deterministic completeness witness — deferred to ADR-113.

### Silent-failure surface (pre-ADR-112)

Two collapse points were verified at HEAD `bc4fdd4`:

- `fxmatrix_v2_sre_oninit.mqh:286` — `if(!HistorySelect(...)) return;` made a HistorySelect **failure** and a genuinely **empty gather** indistinguishable (both yield `deals[]` empty).
- `fxmatrix_v2_sre_oninit.mqh:733` — `result.history_read = true` was set unconditionally on the live path after gather, even when the gather was rejected or empty due to sync failure.

## Gemini ruling (verbatim)

> "I am officially overturning my previous ruling mandating a single, atomic ADR. [...] 1. Approval of the Split: ADR-112 will proceed immediately, scoped strictly to the rejection-filter readiness guard and SRE observability. The first-position anchor is formally deferred to ADR-113 and will remain execution-blocked until an external, deterministic completeness witness [...] is designed. 2. Readiness Guard as a Rejection Filter: APPROVED. Converting HistorySelect failures from a silent collapse into a hard, explicit HALT is mandatory. Bounding the check against the terminal's native POSITION_TIME gives us an immutable internal anchor to reject against. Absence of rejection must not be misconstrued as a positive proof of completeness. 3. Local-First Observability: APPROVED. Primary: the structured, greppable Experts log line is the definitive source of truth. Secondary: the pipshed HTTP push must be strictly non-blocking (fire-and-forget) and its success/failure state must be entirely decoupled from the reconstruction halt decision. 4. ADR-113 Deferral Scope: CONFIRMED. Ensure the pure-logic tests are updated to assert the rejection filter's behavior."

## Decision

ADR-112 ships **only**:

1. A **rejection-filter readiness guard** (hard signals R1–R3; no positive completeness verdict).
2. **Local-first observability** via a structured Experts `Print()` line on every live OnInit reconstruction exit path.

The first-position anchor and any relaxation of `V2_SRE_FindAnchor` flat-bucket logic are **explicitly out of scope** (ADR-113). `V2_SRE_FindAnchor` (`state_reconstruction.mqh` 775–830) is **unchanged**.

### Split: ADR-112 vs ADR-113

| ADR | Scope |
|-----|-------|
| **112** (this ADR) | Rejection-filter readiness guard + SRE OnInit observability |
| **113** (deferred) | First-position anchor; external completeness witness; Gate 2 anchor halt resolution |

Gate 2's first-position case (`HALT_09` Site 2) **remains a halt** until ADR-113. ADR-112 readiness returns `V2_SRE_OK` for that case by design — the subsequent anchor halt is expected and correct under current anchor rules.

### New halt reason codes

Appended to `V2SREHaltReason` (after `V2_SRE_HALT_30_CLOSEBY_PRICE_INCONSISTENT`, before `V2_SRE_HALT_VALIDATION_MISMATCH`; existing values not renumbered):

- `V2_SRE_HALT_31_HISTORY_UNAVAILABLE` — HistorySelect returned false
- `V2_SRE_HALT_32_HISTORY_INCOMPLETE` — rejection-filter tripped (R2 or R3)

Labels: `HALT_31_HISTORY_UNAVAILABLE`, `HALT_32_HISTORY_INCOMPLETE`.

### Rejection-filter rules (R1–R3)

Pure predicate `V2_SRE_EvaluateReadiness()` over fixture inputs — **no IO** (no HistorySelect, PositionSelect, Print):

| Rule | Condition | Result |
|------|-----------|--------|
| **R1** | `!history_select_ok` | `V2_SRE_HALT_31_HISTORY_UNAVAILABLE` |
| **R2** | Open entry position P has no deal in `deals[]` with `position_id == P.position_id`, `entry_type == DEAL_ENTRY_IN`, `deal_magic == entry_magic` | `V2_SRE_HALT_32_HISTORY_INCOMPLETE` |
| **R3** | Open entry position P has `P.open_time < (lookback_from - lookback_sec)` (POSITION_TIME older than lookback horizon) | `V2_SRE_HALT_32_HISTORY_INCOMPLETE` |
| **OK** | None of R1–R3 fire | `V2_SRE_OK` — means **not rejected**, never "proven complete" |

No count-stability re-poll, Sleep(), or timing/deadline loop. Hard signals only.

### Live path wiring

In `V2_SRE_RunSideOnInit` live path, after gather and before `RunOnInitSteps3To10`:

1. `V2_SRE_GatherDealHistory` now exposes `bool &history_select_ok` (false on HistorySelect failure; true otherwise). Filtering logic unchanged.
2. Call `V2_SRE_EvaluateReadiness(...)`.
3. On non-OK: set `result.halt_reason`, `result.side_halted = true`, **`result.history_read = false`**, emit observability, return `V2_SRE_ProcessSideHalt`.
4. On OK: set `result.history_read = true`, emit observability, proceed to Steps 3–10.

`result.history_read` is false on every readiness rejection; true only on the OK path.

### Local-first observability

**Primary (mandated):** one structured, pipe-delimited Experts log line per exit invocation via `V2_SRE_EmitOnInitObservability()`:

- Prefix: `DIAG V2_LONG` / `DIAG V2_SHORT` per `cfg.is_long`
- Event tag: `event=sre_oninit`
- Fields: `instance`, `is_long`, `readiness` (OK | HALT_31 | HALT_32), `halt_site` (NONE | SYNC_UNAVAILABLE | HISTORY_INCOMPLETE | SITE1_EMPTY_WINDOW | SITE2_NO_DUAL_FLAT | OTHER_STEP3_10), `history_select_ok`, `gathered_deals`, `lookback_sec`, `lookback_from`, `open_managed_pos`, `open_pos_entry_found`, `earliest_deal_time`, `latest_deal_time`, `anchor_index`, `halt_reason_label`

Invoked on every **live** OnInit reconstruction exit path: precheck halt, empty-entry halt, readiness reject, OK-before-Steps3To10, Step3–10 halt, clean commit.

**Secondary (pipshed HTTP push):** **not added in this ADR.** `TelemetryEngine.mqh:388` uses synchronous `WebRequest`, which would block the OnInit readiness path. Per Gemini ruling and negative space, observability is Print-only here; any fire-and-forget push is a follow-up and must remain decoupled from halt decisions.

### Unit tests

Five pure-predicate tests in `fxmatrix_v2_tests.mq5` drive `V2_SRE_EvaluateReadiness` directly:

| Test | Case |
|------|------|
| T1 | `history_select_ok=false` → HALT_31 |
| T2 | Open position, entry deal present, in-window → OK |
| T3 | Open position, entry deal absent → HALT_32 (R2) |
| T4 | Open position older than `lookback_from - lookback_sec` → HALT_32 (R3) |
| T5 | Gate 2 first-position fixture → OK (readiness passes; anchor halt is ADR-113) |

## Consequences

**Positive:**

- HistorySelect failure is a hard, explicit HALT_31 instead of silent empty-gather collapse.
- Provably partial gathers (missing entry deal for open position; position older than horizon) halt with HALT_32.
- Every live OnInit reconstruction exit emits a greppable diagnostic line for SRE triage.
- Pure predicate is fixture-testable without broker IO.

**Explicit non-goals (ADR-113):**

- No first-position anchor relaxation.
- No positive completeness verdict anywhere in code or comments.
- Gate 2 SHORT orphan (517307012) still halts at `HALT_09` Site 2 after readiness passes.

**Compile:** CLI pre-check (non-authoritative) reports 0 errors / 0 warnings on all four targets including `fxmatrix_v2_tests.mq5`. MetaEditor GUI 0/0 remains the authoritative gate per ARCHITECT.md.
