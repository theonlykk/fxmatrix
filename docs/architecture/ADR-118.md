# ADR-118: V2 Circuit Breaker Trigger B -- Equity Floor (Pause-and-Hold)

## Status

Accepted -- 2026-08-17. Gemini ruling ("V2 Operational Circuit Breaker",
Q1-Q6 + persistence mandate). Shipped at commit 8160758; unit suite 699/699 at
ship. Dormant on origin -- not deployed to the VPS (which remains on 1c6797e);
going live is a separate deliberate act via deploy.ps1.

## Context

The unified V2 engine, after the ExecutionEngine strip (ADR-104/105), carries
no account-preservation control: a grep of the full live include set finds no
daily-drawdown / equity-failsafe / circuit-breaker logic (the equity value is
read only by telemetry). The ratified controls ADR-012 (FTMO equity failsafe)
and ADR-055 (two-tier vault + daily kill) were dropped with that strip. On the
FTMO 2-Step Swing account, Max Daily Loss is 5% of the day's opening balance
(equity-based, resets 00:00 CE(S)T) and Max Loss is 10% of the initial balance
(static); breaching either ends the account.

Operator posture (Khalid, binding on design intent): fixed 0.01 lots on the 10k
account, scaling horizontally (more pairs) not vertically (lot size), so a
MARKET-driven equity breach is barely reachable -- the dominant risk is an
OPERATIONAL fault causing runaway loss. NEVER flatten/close-all: that locks in a
temporary dislocation and destroys the recovery path. Acceptable response is
PAUSE, fix non-market problems, resume on the intact book.

Two source facts made this cheap and safe. First, the existing per-side halt
(g_long_halted / g_short_halted) is ALREADY pause-and-hold: when set it gates
every entry/quote site and leaves positions and resting orders untouched --
there is no close/sweep/ExpertRemove on the halt path. So a circuit breaker
needs a new TRIGGER, not a liquidation subsystem. Second, cross-instance
coordination already exists via terminal GlobalVariables (the exposure caps,
ADR-100). Anything touching the live trade path is a Gemini ruling; this does.

## Decision

Add an account-wide equity-floor circuit breaker as a new shared-engine module
(fxmatrix_v2_circuit_breaker.mqh), wired to the existing halt. Per Gemini's
rulings:

- Threshold (Q2): 4.5% daily / 9% absolute -- set just inside the FTMO 5%/10%
  floors so it acts as a last-resort disaster-catch, not an early stop that
  would strangle normal harvestable drawdown at 0.01 sizing.
- Scope (Q3): account-wide. On breach, publish V2CB_ACCT_HALT via terminal GV;
  every instance reads it and halts both sides (peer-honor).
- Response: pause-and-hold only -- no flatten, sweep, cancel, or ExpertRemove.
- Resume (Q5): manual only. No code path clears the halt GV; the operator
  clears it by hand after restart + state cleanup, then SRE reconstructs.
- Persistence mandate (Gemini): the daily 4.5% floor uses an immutable opening-
  balance anchor. The trading-day key is derived from the CE(S)T calendar day
  (TimeGMT() + EU DST, broker-server-time-independent), and the date-stamped
  anchor GV is read-not-overwritten on restart -- so a mid-day reboot cannot
  re-anchor at a drawn-down intra-day balance and silently widen the real FTMO
  floor.

Trigger A (operational-anomaly signals) is phased to follow (see ADR-119).
Pure-logic cores (V2_CbDailyFloorBreached / V2_CbAbsoluteFloorBreached /
V2_CbResolveDailyAnchor) are separated from broker calls for hermetic unit
tests, including a re-anchor-trap test asserting the restart case cannot widen
the floor.

## Consequences

Positive:
- The account has an equity-floor backstop again -- pause-and-hold sized inside
  the FTMO limits, catching runaway operational loss without ever flattening
  the book, consistent with the going-concern recovery model.
- Reuse over rebuild: the halt, GV coordination, and SRE restart path already
  existed; the change is a trigger plus wiring, not a subsystem.
- Hermetic tests (mock GV/balance hooks) make the persistence guarantee
  regression-proof.

Negative / bounded:
- At 0.01 sizing a market-driven trip is essentially unreachable; the floor
  chiefly backstops the anomaly detector (ADR-119). This is intentional.
- Dormant until deployed. Origin leads the VPS; the breaker provides no
  protection until deploy.ps1 ships it live.
- First-attach mid-day anchors at the attach-time balance, not the true 00:00
  open -- a known limitation on attach-day only, acceptable at current sizing.
