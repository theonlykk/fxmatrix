# ADR-084 — Midpoint Exit-Reset Recomputation (Finding 1)

**Status:** Accepted

## Problem: Kinetic Distance Over-Widens Deferred Exit-Reset add_next

When `DebugEnableExitResetDelay=true`, a LIFO layer close arms `g_last_exit_reset_time[inst]` in `HandleExitFill()` and defers add_next resubmission to **OnTick Option B** (`FXMatrix.mq5`). After `ExitResetDelaySeconds`, Option B recomputed price via `ComputeNextLayerPrice()` (kinetic-distance-based).

Finding 1's June 2026 backtest evidence (28 `EXIT_RESET_ARMED` events) showed kinetic distance was **100% WINNER=KINETIC** in every matched deferred recomputation — always wider than the midpoint of each layer's own stored `add_next` values. Two worst-case instances priced materially worse than the layer's own proven fill level.

**Critical scope distinction:** Finding 1's evidence is entirely from the **deferred OnTick Option B path**, not the immediate `LIFO_RESUBMIT` branch in `HandleExitFill` (which fires only when `DebugEnableExitResetDelay=false`).

## Decision: Full Replacement with Midpoint Formula (Deferred Path Only)

When `exit_reset_pending == true` inside OnTick Option B, replace `ComputeNextLayerPrice()` entirely:

```
midpoint = 0.5 * (deepest.add_next + g_last_exit_reset_closing_add_next[inst])
computed = NormalizeDouble(midpoint, SymbolInfoInteger(inst_symbol, SYMBOL_DIGITS))
```

**No kinetic floor or ceiling** — Staff Architect ruling: full replacement, not a blend or cap.

### Deepest vs Shallowest Surviving Layer

Option B already uses `deepest` at index `inv_size - 1` (not shallowest at index 0). The midpoint formula uses **`deepest.add_next`**, matching the branch actually in use for `PlaceNextEntryLimit()`.

### Why New Tracking Is Required

At arm time (`HandleExitFill`, `DebugEnableExitResetDelay=true`), the closing layer is removed from inventory via `ArrayRemove` before Option B runs. Only `g_last_exit_reset_time[inst]` was previously cached — not the closing layer's `add_next`.

**New global:** `g_last_exit_reset_closing_add_next[3]` in `Globals.mqh`, declared alongside `g_last_exit_reset_time[3]`.

**Lifecycle (mirrors timestamp array exactly):**

| Event | Action |
|-------|--------|
| Arm (`HandleExitFill`) | `g_last_exit_reset_closing_add_next[inst] = CurL.add_next` alongside `g_last_exit_reset_time[inst] = TimeCurrent()` |
| Successful deferred placement (Option B) | `g_last_exit_reset_closing_add_next[inst] = 0.0` alongside `g_last_exit_reset_time[inst] = 0` |
| Failed placement (`PlaceNextEntryLimit` returns 0) | **Not cleared** — remains set for retry on a future tick (same as timestamp) |

`CurL` at arm time holds the **closing** layer's data (local copy not refreshed after `ArrayRemove`).

### Normalization Requirement

Midpoint arithmetic can produce values at finer precision than the broker accepts. Normalization uses instrument-specific digits:

```mql5
int digits = (int)SymbolInfoInteger(inst_symbol, SYMBOL_DIGITS);
computed = NormalizeDouble(midpoint, digits);
```

Same pattern as `PlaceEntryLimit()` — **not** chart-global `_Digits`.

**Worked example (findings doc):**

```
0.5 * (1.16176 + 1.16355) = 1.162655
NormalizeDouble(..., 5) = 1.16266
```

Six decimal places in the raw midpoint; five-digit instrument rounds to `1.16266`.

## Explicit Non-Scope

| Path | Behavior |
|------|----------|
| `exit_reset_pending == false` (Option B) | Unchanged — `ComputeNextLayerPrice()` kinetic distance governs normal deepen-cycle re-arm |
| Immediate `LIFO_RESUBMIT` (`HandleExitFill`, delay off) | Untouched |
| `HandleEntryFill` (fresh layer creation) | Untouched |
| `KineticGateOpen()` / `timing_ok` gating | Unchanged for both sub-paths |
| `PlaceNextEntryLimit()` passivity clamp | Unchanged — `computed` flows in as before |
