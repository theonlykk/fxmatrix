# ADR-076 — TEMPORARY: DebugAddNextBarCloseOnly (ADR-028 Cadence Isolation)

**Status:** TEMPORARY / TEST INFRASTRUCTURE — not a permanent architectural decision

## Purpose

Controlled backtest comparison to isolate **ADR-028's cadence change** (commit `b4c89c2`, 2026-06-22): Option B add_next re-arm moved from **new M5 bar close only** to **every tick**.

All other Option B logic (F3 stale-ticket check, `MinLayerIntervalSeconds`, `KineticGateOpen`, `ComputeNextLayerPrice`, `PlaceNextEntryLimit`) remains unchanged. Only **when** the block is evaluated differs.

## Input

```mql5
input bool DebugAddNextBarCloseOnly = false;
```

| Value | Behavior |
|-------|----------|
| `false` (default) | **Current live behavior** — Option B runs every tick (`!false \|\| new_bar` → always true) |
| `true` | **Pre-ADR-028 cadence** — Option B runs only when `new_bar` is true |

## Implementation

`FXMatrix.mq5` — single wrapper around the existing Option B block:

```mql5
if (!DebugAddNextBarCloseOnly || new_bar) {
    // ... existing Option B block unchanged ...
}
```

`new_bar` is reused from the existing computation earlier in `OnTick()`.

## Constraints

- **DO NOT** set `DebugAddNextBarCloseOnly = true` on live or demo deployments
- Backtest isolation only
- Remove this input and wrapper, or hard-disable it, once the ADR-028 comparison test is complete

## Negative space

- No changes inside the Option B block
- No other `OnTick()` logic touched
- Default `false` is a compile-time no-op equivalent to current HEAD behavior

## Lifecycle

This ADR and input are **test scaffolding**. Delete or permanently gate off after the backtest A/B run concludes.
