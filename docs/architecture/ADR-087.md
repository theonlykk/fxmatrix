# ADR-087 — Flatten ADR-052 Sigmoid Lot Multiplier (Default `SigmoidMaxScale = 1.0`)

**Status:** Accepted

## Background: ADR-052 Sigmoid Mechanism

ADR-052 Step C introduced `ComputeSigmoidLotMultiplier()`, mapping term-structure dispersion (`g_sigma_fv_pts`) to an upside lot-size multiplier via a mirrored logistic function:

```
multiplier = 1.0 + (SigmoidMaxScale - 1.0) / (1.0 + exp(SigmoidSteepness * (sigma_pts - SigmoidMidpoint)))
```

With defaults `SigmoidMaxScale = 3.0`, `SigmoidMidpoint = 50.0`, `SigmoidSteepness = 0.15`, low dispersion (high timeframe agreement, σ ≈ 0) scaled entry-limit volume up to **3×** `BaseLotSize` (after LDAK penalties). High dispersion drove the multiplier back toward **1.0** (baseline). The formula never went below 1.0.

Rationale at introduction: reward high term-structure agreement with larger quotes when conditions appeared "calm."

## Problem: Upside Scaling During Calm Is Backwards

Volatility clustering implies that low-dispersion / calm periods statistically **precede** elevated volatility more often than they precede continued calm. Sizing **up** when dispersion is low therefore increases exposure precisely when the regime is most likely to transition into stress — the opposite of prudent volatility-aware sizing.

A confirmed backtest account blowup was traced to this mechanism. When `SigmoidMaxScale` was set to **1.0** alongside an exit-reset-delay fix, the blowup resolved. Isolation analysis identified the sigmoid upside scaling as the **dominant** of the two factors (not merely correlated).

## Decision: Change Default Only

Change `SigmoidMaxScale` default from `3.000` to `1.000` in `Globals.mqh`. **No code logic changes.**

### Mathematical Flattening at `SigmoidMaxScale = 1.0`

When `SigmoidMaxScale = 1.0`:

```
(SigmoidMaxScale - 1.0) = 0
multiplier = 1.0 + 0 / (1.0 + exp(...)) = 1.0
```

This holds for **all** `sigma_pts`, `SigmoidMidpoint`, and `SigmoidSteepness` values — the variable term is identically zero, not merely clamped by `MathMax(1.0, ...)`.

`ComputeSigmoidLotMultiplier()` function body is unchanged; the existing formula and clamp already produce the desired behavior at the new default.

`SigmoidMidpoint` and `SigmoidSteepness` remain as adjustable inputs but are **inert** at `SigmoidMaxScale = 1.0` (kept for future research, not removed).

## Scope and What Is Unaffected

**Flattened:** Only the sigmoid/dispersion upside component applied inside `ComputeLDAKLotSize()` before entry-limit placement (`PlaceEntryLimit`, `PlaceNextEntryLimit`).

**Unchanged and separate:**

- LDAK drawdown scaling (`size_mult`) — downside risk reduction
- LDAK correlation penalty (`w`) — downside risk reduction
- `ComputeSigmoidLotMultiplier()` function body
- `PlaceExitLimit()` and all exit volumes
- All other ADR logic

These LDAK mechanisms are downstream/upstream of the sigmoid step but operate independently; ADR-087 does not modify them.
