# ADR-045 — Spatial Carry/Rollover Adjustment

**Status:** Committed

## Context

Parked limit orders across rollover accumulate swap costs; grid spatial structure must absorb financing to remain financially equivalent.

## Decision

`RunDailyRolloverReconciliation()` fires at 00:01 broker time; unified drift math — long side drifts up, short side drifts down; only negative carry adjusted; Wednesday 3× multiplier.

## Consequences

Grid self-adjusts daily; `exit_price_fixed` remains source of truth by syncing after each modify; positive carry untouched.

## Negative Space

No PnL cash calculations; no new input parameters; no changes to fill logic.

## History / Notes

### Origin-story correction (Jul 2026 empirical review)

The live EURGBP trade (−$0.33 swap on 0.01 lot, account 1513973831) that
motivated porting ADR-045 rollover reconciliation to V2 **does not appear
to have been a genuine Tue→Wed triple-swap crossing**. Deal history shows
position 501698069 opened **Wed Jul 22 12:26** server time — **after** the
Tue→Wed 00:00 rollover window — and closed Thu Jul 23 02:48 after crossing
**one** ordinary Wed→Thu midnight rollover. The −$0.33 charge is real
observed swap, but it is not isolated proof that the platform applied a
Wednesday triple on that hold.

This corrects the feature's origin narrative only. It does **not** resolve
whether `V2_RolloverWednesdayMultiplier()` ×3 is correct for FTMO: that
remains **undetermined** pending a natural Tue→Wed crossing with rollover
verbose logs (see below).

### Wednesday multiplier verification (open)

`V2_RolloverWednesdayMultiplier()` remains **frozen** pending empirical
confirmation. Rollover verbose logs now print raw `swap_long`, `swap_short`,
`swap_used`, `day_of_week`, and `server_time` on each exit adjust so the
next genuine Tue→Wed broker-midnight crossing can settle the question without
a dedicated re-check.
