# ADR-056 — Event-Driven Grid Restitution in HandleExitFill()

**Status:** Committed

## Context

When a LIFO layer is scalped out, the outermost exit limit can remain at stale price geometry — the live order was placed for the previous shallowest layer's exit target, not the new index-0 layer after `ArrayRemove()`. This ties up margin at the wrong price until some other mechanism corrects it.

There was no event-driven path to recompute and drag the outermost exit limit immediately after partial unwind.

## Decision

Add a Grid Restitution block at the bottom of `HandleExitFill()` in `ExecutionEngine.mqh`, strictly after LIFO `ArrayRemove()` and the Phase 3 partial-unwind add-next logic, immediately before `SaveAllInventoryState()`.

**Trigger conditions:**
- Layer fully closed (`remaining_exit_volume <= VOLUME_EPSILON`)
- Inventory remains after removal (`post_inv_size > 0`)

**Restitution logic:**
1. Read new shallowest layer at index 0 (`RestLayer`)
2. Compute `rest_half_spread = (ask - bid) / 2.0` from live market — mirrors `HandleEntryFill()` exactly
3. Recompute exit target via `ComputeExitPriceDeterministic()`
4. For each live exit ticket on `RestLayer`: skip if within 1 point of target; check freeze level; `OrderModify` to new price
5. On success, sync `g_inventory_X[0].exit_price_fixed` to mirror the live order

**Not triggered when:**
- Pod is flat after removal (`post_inv_size == 0`) — full unwind path unchanged

## Consequences

- Grid perimeter contracts immediately on each LIFO scalp — no per-bar API sweep required
- Capital efficiency maintained: outermost exit limit reflects correct geometry for the new shallowest layer
- `exit_price_fixed` stays in sync with broker order after restitution
- Freeze-level and 1-point skip guards prevent unnecessary or rejected modifies

## Negative Space

- Full unwind path (`remaining == 0`) untouched
- Phase 3 add-next cancel/resubmit logic untouched
- `ComputeExitPriceDeterministic()`, `HandleEntryFill()`, `OnTradeTransaction()` untouched
- No other files modified in this ADR
