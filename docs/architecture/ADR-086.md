# ADR-086 — Decouple Exit-Sizing from Add-Spacing (Isolated Kinetic Exit Toggle)

**Status:** Accepted

## Problem: Exit and Add Toggles Were Coupled

ADR-082 introduced kinetic-derived exit sizing inside the 8-parameter `ComputeExitPriceDeterministic()` overload, gated solely on `DebugUseUnifiedAddNextSpacing`. That single flag simultaneously controls:

1. **Add side (ADR-080):** whether `HandleEntryFill` uses `ComputeNextLayerPrice()` for stored `add_next` at layer creation.
2. **Exit side (ADR-082):** whether the same toggle activates kinetic-derived exit distance at layer creation.

ADR-082's original justification was **architectural consistency** — exit geometry should derive from the same kinetic signal trusted for add spacing — not an empirically validated PnL comparison showing kinetic exits outperform the legacy 0.618-decay + 3-pip floor formula in isolation. With both behaviors behind one flag, any backtest comparing kinetic vs. legacy exits necessarily also changes add-side spacing, confounding the measurement.

## Decision: Independent Exit Toggle

Add a second input, `DebugEnableKineticExits` (default `false`), placed alongside `DebugUseUnifiedAddNextSpacing` in `Globals.mqh`.

Change the 8-parameter overload gate in `MathEngine.mqh` from:

```
if (DebugUseUnifiedAddNextSpacing) {
```

to:

```
if (DebugUseUnifiedAddNextSpacing && DebugEnableKineticExits) {
```

**Nothing else in the overload changes.** The kinetic branch body, the delegating `return` to the legacy 7-parameter function, and all other logic remain byte-for-byte as in ADR-082.

## Behavior Matrix

| `DebugUseUnifiedAddNextSpacing` | `DebugEnableKineticExits` | Exit sizing at HandleEntryFill | Add spacing at HandleEntryFill |
|--------------------------------|---------------------------|-------------------------------|-------------------------------|
| `false` | `false` | Legacy 7-param (delegation) | Legacy A_golden formula |
| `false` | `true` | Legacy 7-param (delegation) | Legacy A_golden formula |
| `true` | `false` | Legacy 7-param (delegation) | Unified `ComputeNextLayerPrice()` |
| `true` | `true` | Kinetic exit (ADR-082) | Unified `ComputeNextLayerPrice()` |

## Backward Compatibility

- **`DebugUseUnifiedAddNextSpacing=false` (production default):** Short-circuit AND guarantees the kinetic branch never runs regardless of `DebugEnableKineticExits`. Byte-identical to pre-ADR-086 behavior.
- **`DebugUseUnifiedAddNextSpacing=true`, `DebugEnableKineticExits=false`:** Falls through to the existing delegating `return` calling the untouched 7-parameter function — byte-identical to ADR-082 with unified add but legacy exit.
- **`DebugUseUnifiedAddNextSpacing=true`, `DebugEnableKineticExits=true`:** Unchanged ADR-082 kinetic exit behavior.

## Scope and Negative Space

**Changed:**

- `Globals.mqh` — new `DebugEnableKineticExits` input
- `MathEngine.mqh` — single gate condition in 8-parameter overload

**Untouched:**

- Kinetic branch internal logic (formula, normalization, `half_spread` handling)
- Delegating else branch in the 8-parameter overload
- Legacy 7-parameter `ComputeExitPriceDeterministic()`
- `ComputeNextLayerPrice()` and all add-spacing paths — zero effect from this flag
- OnInit, CarryEngine, ADR-056 restitution call sites (7-param only)
- ADR-077 through ADR-085 logic
