# ADR-063 — Telemetry State Capture (LDAK Snapshot, Backstop Counter & Alert Ring Buffer)

**Status:** Committed (pending)

## Context

Prior to this ADR:

- `ComputeLDAKLotSize()` (ADR-061) computed `size_mult`, `S_eff`, `w`, `raw_vol`, and a three-way gate outcome (pass / clamp / refuse) entirely in function-local variables — discarded on return.
- ADR-062's execution-layer backstop logged `"CRITICAL: Orthogonal exposure leak blocked at execution layer."` via `Print()` only — no persisted state for telemetry.

`TelemetryEngine.mqh` could not expose any of this to Pipshed without new global state. This ADR adds **purely additive** global writes alongside existing logic. No trading, gating, or execution behavior is changed.

## Decision

### Part A — LDAK gate snapshot per slot (`Globals.mqh` + `ExecutionEngine.mqh`)

New enum and per-slot arrays immediately after `g_cooldown_LDAK[3]`:

```mql5
enum ENUM_LDAK_GATE_OUTCOME {
    LDAK_GATE_PASS   = 0,
    LDAK_GATE_CLAMP  = 1,
    LDAK_GATE_REFUSE = 2
};

double g_ldak_last_size_mult[3] = {0.0, 0.0, 0.0};
double g_ldak_last_S_eff[3]     = {0.0, 0.0, 0.0};
double g_ldak_last_w[3]         = {0.0, 0.0, 0.0};
double g_ldak_last_raw_vol[3]   = {0.0, 0.0, 0.0};
int    g_ldak_last_gate[3]      = {LDAK_GATE_PASS, LDAK_GATE_PASS, LDAK_GATE_PASS};
```

**Design note — enum vs string:** Gate outcome is stored as `int` using `ENUM_LDAK_GATE_OUTCOME` rather than a string label. Prompt 1b can map `0/1/2` to `"pass"/"clamp"/"refuse"` at serialization time — avoids string allocation on every `ComputeLDAKLotSize()` call in the hot path.

**Design note — diagnostic depth:** Gemini's minimum spec called for gate outcome per slot. The implementation also captures `S_eff`, `w`, and pre-gate `raw_vol` alongside `size_mult` as intentional additional diagnostic depth — telemetry can reconstruct the full gate decision without parsing verbose logs.

In `ComputeLDAKLotSize(int instrument)`:

- After `raw_vol` is computed, the four double snapshots are written to `[instrument]` on **every** call (pre-gate values).
- `g_ldak_last_gate[instrument]` is set on the existing ADR-061 branches:
  - `LDAK_GATE_REFUSE` before `return 0.0` (drawdown brake)
  - `LDAK_GATE_CLAMP` in the correlation-only floor-clamp branch
  - `LDAK_GATE_PASS` when `raw_vol >= min_vol * 0.70`

### Part B — Backstop event counter (`Globals.mqh` + `ExecutionEngine.mqh`)

```mql5
int g_bias_backstop_count = 0;
```

In `PlaceEntryLimit()` and `PlaceNextEntryLimit()`, inside the existing ADR-062 backstop block, `g_bias_backstop_count++` executes immediately before `return 0`. The existing `Print("CRITICAL: ...")` text is unchanged.

### Part C — Circular alert message buffer (Gemini Ruling 5)

```mql5
#define CRITICAL_ALERT_BUFFER_SIZE 10
string g_critical_alerts[CRITICAL_ALERT_BUFFER_SIZE];
int    g_critical_alert_write_idx = 0;
```

**Never clear on read.** The buffer is never cleared when telemetry reads it. Clear-on-read would race with a failed HTTP push to Pipshed — a real alert could be lost if the push fails after the buffer slot is zeroed. Instead, oldest entries are silently overwritten once the ring is full; telemetry reads the full array and interprets write index for ordering.

At both backstop sites, immediately after `g_bias_backstop_count++` and before `return 0`:

1. Format a UTC timestamped message identifying the function (`PlaceEntryLimit` or `PlaceNextEntryLimit`), `direction`, `DirectionalBias`, and `symbol`.
2. Write to `g_critical_alerts[g_critical_alert_write_idx]`.
3. Advance `g_critical_alert_write_idx = (g_critical_alert_write_idx + 1) % CRITICAL_ALERT_BUFFER_SIZE`.

Example message shape:

```
2026-07-01 06:45:12 UTC | Orthogonal exposure leak blocked (PlaceEntryLimit). direction=1 bias=2 instrument=EURUSD
```

## Rationale

- **Part A:** Last-known LDAK internals per slot enable Pipshed to show gate state without log scraping.
- **Part B:** Monotonic counter gives a single scalar health signal for backstop fires.
- **Part C:** Formatted message history survives beyond the MT5 journal and supports dashboard alert replay; ring buffer bounds memory without losing recent events under burst conditions.

## Consequences

- Prompt 1b can serialize `g_ldak_last_*`, `g_bias_backstop_count`, and `g_critical_alerts[]` in `BuildTelemetryPayload()`.
- Backstop fires produce both a count increment and a durable formatted message.
- F7 compile not run on this machine (static review only).

## Negative Space

- `TelemetryEngine.mqh` — not modified (Prompt 1b)
- ADR-061 gate logic and return values — unchanged
- ADR-062 backstop conditions and `Print()` text — unchanged
- `PlaceExitLimit()` — untouched
- LDAK snapshot capture sites — unchanged after Part A
