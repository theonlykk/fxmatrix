# ADR-080 — TEMPORARY: DebugUseUnifiedAddNextSpacing (HandleEntryFill Unification)

**Status:** TEMPORARY / TEST INFRASTRUCTURE — not a permanent architectural decision

## Problem: Dual-Math Race at Fill Time

Two code paths computed fill-time `add_next` storage with **different formulas** on the same inputs:

| Path | Formula |
|------|---------|
| **HandleEntryFill** (legacy) | `A_golden = E_n × 1.618`; `A_n = max(base_add, A_golden)` — 2-way, no kinetic |
| **ComputeNextLayerPrice** (Option B / LIFO) | `A_n = max(base_add, max(E_n + 10×pt, kinetic_dist))` — 3-way, kinetic-aware |

Centralizing without a toggle would silently change stored `add_next` at layer creation — not pure structural consolidation.

## Index Resolution (anchor finding)

`ComputeNextLayerPrice()` interprets `next_layer_idx` as the **layer about to be created**:

```
prev_idx = next_layer_idx - 1
```

HandleEntryFill must pass **`layer_idx + 1`**, not `L.layer_index` alone. Passing `L.layer_index` would anchor to the **prior** layer via internal array lookup.

The legacy branch does **not** perform this lookup — it uses `L.layer_index` directly in the formula, which is correct for that path. Only the unified branch needs `layer_idx + 1`.

## Staff Architect Ruling: Option B (Toggle)

| Option | Disposition |
|--------|-------------|
| **A — Direct unification, no toggle** | Rejected — unverified kinetic injection at fill time |
| **C — Leave dual math unresolved** | Rejected — race condition persists |
| **B — Toggle (this ADR)** | Accepted — validate before changing stored fill-time values |

## Input

```mql5
input bool DebugUseUnifiedAddNextSpacing = false;
```

| Toggle | `false` (default) | `true` |
|--------|-------------------|--------|
| `DebugUseUnifiedAddNextSpacing` | Legacy `A_golden` formula — **today's production** | `ComputeNextLayerPrice(layer_idx + 1, instrument, …)` — full kinetic + `E_n+10pt` |

## Scope

- **Modified:** HandleEntryFill add_next block only (lines ~916–953 region)
- **Unchanged:** Downstream sentinel / 5% deviation / storage guards; `ComputeNextLayerPrice()` body; Option B; LIFO resubmit; ADR-077/078/079

## Deployment warning

**DO NOT** enable `DebugUseUnifiedAddNextSpacing=true` on live or demo without explicit backtest validation. This changes **stored** `add_next` at layer creation, not just downstream placement timing.

## Test

**Test 56** in `temp/run_tests_0_41.py` — legacy formula mirror, unified path via shared `compute_next_layer_price()` helper (reuses Test 44 kinetic + Test 53 grid interval), and counterexample proving legacy must use `L.layer_index` not `layer_idx + 1` in the formula.
