# ADR-054 — Harden Unmatched Fill Handling and Orphan Detection

**Status:** Committed

## Context

A CloseBy deal (ticket=483585634, magic=0, broker-assigned) was broadcast via `OnTradeTransaction` to the SNIPER instance. ADR-049 did not intercept it — CloseBy deals can arrive as `magic=0` or with unexpected entry types. `HandleUnmatchedFill()` correctly could not match it to SNIPER inventory, but then set `g_halted=true`, killing SNIPER for 18 hours.

Additionally, `CheckForOrphans()` fired on the transient CloseBy position on both instances before it settled, triggering spurious halts.

## Decision

### `ExecutionEngine.mqh` — `HandleUnmatchedFill()`

- Downgrade the no-fallback-match path from fatal halt to `WARNING [ADR-054]` + `return`.
- Unmatched fills are treated as foreign noise (CloseBy broadcasts, manual interventions, broker-assigned transient deals) — not evidence of internal inventory corruption.
- Gemini ruling 2026-06-29: Warning & Skip, not Fatal Halt.

### `ExecutionEngine.mqh` — `DetectInventoryCorruption()` (new helper, ADR-054b wiring deferred)

- Add a new function defining hard halt conditions for genuine internal corruption:
  - **Hard halt 1:** Volume mismatch on a fill the EA owns (`deal_volume` vs `expected_volume`).
  - **Hard halt 2:** Inventory array overflow safety (`inv_size > 100`).
- Function is inserted after `HandleUnmatchedFill()` but not yet wired into `HandleExitFill()` — wiring deferred to ADR-054b to keep this diff minimal.

### `StateEngine.mqh` — `CheckForOrphans()`

- Before halting on an untracked position, re-select the position ticket via `PositionSelectByTicket(ticket)`.
- If the position is already closed/settled, log `INFO [ADR-054]` and `continue` — transient CloseBy positions that appear briefly then settle do not trigger a halt.
- If the position is still open and untracked, retain the existing fatal orphan halt unchanged.

## Halt Matrix

| Condition | Severity | Action |
|-----------|----------|--------|
| Unmatched fill (no ticket or fallback match) | WARNING | Log and skip — no halt |
| Volume mismatch on owned fill | ERROR | `g_halted = true` |
| Inventory array size > 100 | ERROR | `g_halted = true` |
| Untracked position already closed (transient) | INFO | Skip — no halt |
| Untracked position still open (genuine orphan) | ERROR | `g_halted = true` |

## Consequences

- SNIPER (and all instances) are resilient to foreign broadcast noise from CloseBy deals, manual trades, and magic=0 broker-assigned events.
- Genuine internal corruption (volume mismatch, inventory overflow) still halts via `DetectInventoryCorruption()` once wired in ADR-054b.
- Orphan scanner false positives from transient CloseBy settlement lag are eliminated; genuine open orphans still halt.
- Fallback match logic in `HandleUnmatchedFill()`, magic number filter in `CheckForOrphans()`, `HandleExitFill()` body, and `OnTradeTransaction()` are unchanged in this ADR.
