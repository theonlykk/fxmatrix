# ADR-067 — Full Resting Order Book in Telemetry `working_orders`

**Status:** Committed (pending)

## Context

ADR-064 added a `working_orders` top-level field to the telemetry heartbeat, populated from `g_pending_bid[]` and `g_pending_offer[]` with guarded `GetPendingOrderPrice()` lookups. In live operation with open inventory, those globals are **deliberately zero**: they track Layer 0 flat-pod entry limits only (MM two-sided quoting, SNIPER single-sided placement, Phase 3 full-flat resume). The Option A gate in `FXMatrix.mq5` skips flat quoting whenever `inst_inv_size > 0`, and pending bid/offer tickets are cleared on Layer 0 fill.

This is **working as designed since inception** — not a regression from ADR-063/064 or any other recent ADR. The telemetry field simply never covered the other two resting order types:

| Order type | Magic | Tracker |
|------------|-------|---------|
| Layer 0 entry | `EA_MAGIC` | `g_pending_bid[slot]` / `g_pending_offer[slot]` |
| Add-next | `EA_MAGIC + 1` | `g_add_next[slot]` |
| Exit limit | `EA_MAGIC + 2` | `Layer.exit_tickets[]` per layer |

Resting add_next and exit orders were already serialized in `active_pods.layer_detail[]` as **targets** (`add_next`, `exit_price_fixed`) but not as **live broker tickets/prices**. Dashboard consumers saw empty `working_orders` while pods held multiple open layers with active add_next and exit limits on the book.

## Decision

**One file changed:** `TelemetryEngine.mqh` (read/serialize only — no new capture state).

Replace the per-slot `working_orders` object shape. Old keys (`bid_ticket`, `bid_price`, `offer_ticket`, `offer_price`) are renamed and extended:

```json
"EURUSD": {
  "layer0_bid_ticket": 0,
  "layer0_bid_price": null,
  "layer0_offer_ticket": 0,
  "layer0_offer_price": null,
  "add_next_ticket": 480391138,
  "add_next_price": 1.13060,
  "exit_orders": [
    {"ticket": 480325889, "price": 1.13850},
    {"ticket": 480391125, "price": 1.13690}
  ]
}
```

### Helper additions

- **`BuildExitOrdersJSON(int slot)`** — iterates all layers in `g_inventory_0/1/2[slot]` × all elements of each layer's `exit_tickets[]`. Emits a JSON array of `{ticket, price}` objects. Empty array when no exits.
- **`SerializeWorkingOrdersJSON(int slot)`** — assembles the full per-slot object: Layer 0 bid/offer from `g_pending_bid/offer`, add_next from `g_add_next`, exit array from `BuildExitOrdersJSON`.

### Ticket lookup discipline

Every price field uses the ADR-064 guard pattern:

```mql5
TelPriceOrNull(ticket > 0 ? GetPendingOrderPrice(ticket) : -1.0)
```

Applied to layer0 bid, layer0 offer, add_next, and each exit ticket. No unconditional calls on zero or stale tickets.

### Live price vs fixed target

`exit_orders[].price` is the **current resting limit price** on the broker (`ORDER_PRICE_OPEN` via `GetPendingOrderPrice()`). This may differ from `layer_detail[].exit_price_fixed` after ADR-056 carry restitution / drag. The two fields serve different purposes and must not be conflated.

### Exit multiplicity (anchor D)

A slot may have **zero to many** exit orders:

- Multiple open layers → typically one exit per layer (up to `MaxLayers`)
- Partial entry fills → multiple `exit_tickets[]` entries on a single layer

`exit_orders` is always an array, never a scalar.

## Follow-up Required — Pipshed breakage

This change **breaks** Pipshed's existing `best_quotes` aggregation (ADR-066) until updated in a separate follow-up prompt. Pipshed `telemetry_aggregate()` currently reads `working_orders[*].bid_price` and `working_orders[*].offer_price`. Those keys no longer exist; they are replaced by `layer0_bid_price`, `layer0_offer_price`, `add_next_*`, and `exit_orders[]`.

**End-to-end dashboard quoting is not complete until Pipshed is updated** to consume the new field names and optionally incorporate add_next / exit resting prices into aggregate best-quote logic.

## Negative Space

- `g_pending_bid/offer` assignment logic (`FXMatrix.mq5`, `ExecutionEngine.mqh`) — untouched
- `g_add_next[]` population (`PlaceNextEntryLimit`) — untouched
- `exit_tickets[]` population (`HandleEntryFill`, `AuditExitLimits`) — untouched
- `SerializePodJSON()` / `layer_detail[]` — untouched
- ADR-063 globals, `EmitPodClose()`, `EmitTelemetry()` dispatch — untouched
- Pipshed repo — **not modified in this ADR** (explicit follow-up)

## Consequences

- Telemetry heartbeat now exposes the full resting order book per slot when pods hold inventory
- Layer 0 bid/offer fields remain present (often zero/null with open inventory — expected)
- Pipshed `best_quotes` will return empty or error until field names are migrated

## Tests

No new unit tests — JSON serialization only; exit iteration logic mirrors existing inventory reads in `SerializePodJSON()` and `GetPodMetrics()`.
