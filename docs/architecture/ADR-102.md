# ADR-102 — OnTradeTransaction Halt Gate for Halted V2 Instances

**Status:** Accepted (code complete; VPS deploy waits for flat account)

**Date:** 2026-08-02

---

## Context

V2 production EAs set `g_long_halted` / `g_short_halted` when the orphan startup guard detects open broker positions while the in-memory layer array is empty (`V2_ProcessOrphanStartupCheck`). `Long_OnTick` / `Short_OnTick` already return immediately when halted.

**Defect:** `OnTradeTransaction` unconditionally called `Long_HandleDealFill` / `Short_HandleDealFill`. A halted side could still append layers, place exits, sync cap GVs, queue CloseBy, and call `EnsureAddNext` if a fill arrived (e.g. from resting pending orders left on the book before reattach).

DeepSeek Phase 1 audit (2026-08-02) confirmed the fix direction and required:
- Per-side gate **after** deal-ownership validation (symbol + magic), not before.
- Unconditional `ERROR`-level print plus `system_alerts[]` append (not telemetry-only).
- Mark deal processed on the halted path (dedup).
- **No** CloseBy queuing on exit-magic fills while halted (queue would never run; layer array is untrustworthy).

### Inspection note: orphan halt does not cancel pending orders

`V2_ProcessOrphanStartupCheck` (in `fxmatrix_v2_exits.mqh`) only prints, pushes an alert, and returns `true`. It does **not** call `OrdersTotal()` or cancel pending orders.

**Accepted limitation:** Fix 1 stops the EA from **reacting** to fills on a halted side. It does **not** prevent broker-side fills from resting exit/add/reload limits. A fill on a halted instance still changes broker state; the EA ignores it and alerts for manual reconciliation. Full broker-level halt (pending-order cancellation) is **out of scope** for Part A.

Unrelated: the parked State Reconstruction Engine proposal remains blocked separately.

---

## Decision

In all three production files (`fxmatrix_v2.mq5`, `fxmatrix_v2_eurusd.mq5`, `fxmatrix_v2_eurgbp.mq5`), both `Long_HandleDealFill` and `Short_HandleDealFill`:

1. After existing dedup, `HistoryDealSelect`, and `_Symbol` filter — unchanged.
2. After `MarkDealProcessed` — unchanged.
3. Compute `is_*_entry` / `is_*_exit` via shared helpers in `fxmatrix_v2_logic.mqh`.
4. If the deal is managed (entry or exit magic) **and** the side is halted:
   - Emit `V2_EmitHaltedFillAlert` (unconditional `Print` + `V2_PushSystemAlert`).
   - Return without `AppendLayer`, `RemoveLayerAt`, cap sync, or CloseBy.

Shared helpers: `V2_IsManagedLongEntryDeal`, `V2_IsManagedShortEntryDeal`, `V2_IsManagedExitDeal`, `V2_FormatHaltedFillAlert`, `V2_EmitHaltedFillAlert`.

---

## Consequences

- Halted instances no longer mutate in-memory layer state or issue orders on fill events.
- Exit-magic fills on halted sides leave hedge positions for manual CloseBy/reconciliation (safer than acting on an untrusted layer array).
- Resting pending orders can still fill at the broker; operators must reconcile manually after alerts.
- Cap thresholds remain at **0** (unchanged).
