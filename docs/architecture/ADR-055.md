# ADR-055 — Two-Tier Vault + Serialization Shield (Phase 3.A)

**Status:** Committed

## Context

The EA had no hard daily drawdown kill switch tied to `g_daily_start_balance`. The previous Tier 2 "Global Nuclear Failsafe" used unrealised P&L against `GlobalDrawdown` and immediately closed all positions — too aggressive for manual triage. Tier 3 used FTMO static floors but did not enforce a configurable daily percentage kill.

Additionally, `g_daily_start_balance` and related daily state lived only in memory. A VPS reboot or EA reattach reset drawdown tracking, allowing the daily floor to be re-established at the current (already-drawn-down) balance.

## Decision

### Two-Tier Vault (`CheckCircuitBreakers()` in `FXMatrix.mq5`)

**Tier 2 — Soft Warning (default 3%):**
- Compares `ACCOUNT_EQUITY` against `g_daily_start_balance * (1 - InpSoftDrawdownLimit/100)`.
- Sends `Print` + `SendNotification` push alert on first breach per day.
- `g_warning_sent` gate prevents notification spam.
- Takes **no** market action and does **not** set `g_halted`.

**Tier 3 — Hard Kill Switch (default 4%):**
- Compares equity against `g_daily_start_balance * (1 - InpHardDrawdownLimit/100)`.
- Full institutional sweep: `CloseAllPositions()`, `CancelAllPendingEntries()`, explicit cancel loop for `EA_MAGIC` / `+1` / `+2`, clear all inventory arrays, `SaveAllInventoryState()`, `g_halted = true`, `ExpertRemove()`.
- Legacy FTMO absolute floor (`FTMO_Initial_Balance * (1 - FTMO_Max_Loss_Pct)`) retained as account-level backstop with same sweep + detach behaviour.

**Midnight rollover:**
- Uses `YYYYMMDD` string (`g_daily_start_date`) instead of `dt.day` int — handles month/year boundaries correctly.
- Resets `g_daily_start_balance`, `g_warning_sent`, API counters; persists via `SaveGlobalState()`.

### Serialization Shield (`StateEngine.mqh`)

Extended `SaveGlobalState()` / `LoadGlobalState()` JSON schema with:
- `daily_start_balance` (double, 8 decimal places)
- `daily_start_date` (string, YYYYMMDD)
- `warning_sent` (boolean)

Loaded on `OnInit()` via existing ADR-045 ordering (`LoadGlobalState()` before inventory hydration).

### New inputs and globals (`Globals.mqh`)

- `InpSoftDrawdownLimit` (default 3.0%)
- `InpHardDrawdownLimit` (default 4.0%)
- `g_warning_sent`, `g_daily_start_date`

`GlobalDrawdown` input retained but no longer used in circuit breaker logic.

## Consequences

- Khalid receives a push alert at 3% daily drawdown for manual triage without the EA taking market action.
- At 4% daily drawdown the EA self-destructs: full sweep, halt, and detach via `ExpertRemove()` — requires manual reattach.
- Daily drawdown state survives VPS reboot via serialized global state file.
- Tier 1 per-pod circuit breaker unchanged.

## Negative Space

- Tier 1 (per-pod isolation) untouched.
- `CloseAllPositions()` and `CancelAllPendingEntries()` implementations untouched.
- `OnInit()` line-30 `g_daily_start_balance` initialisation untouched.
- No other files modified in this ADR.
