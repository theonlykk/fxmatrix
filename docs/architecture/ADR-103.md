# ADR-103 — OnInit Cap GV Publish Ordering and Trigger-Reset Removal

**Status:** Accepted (code complete; VPS deploy waits for flat account)

**Date:** 2026-08-02

---

## Context

**Defect:** All three production `OnInit` paths called cap layer-count sync (`V2_GbpCapSyncInstance` / `V2_EurCapSyncInstance` / `V2_SyncAllCaps`) and reset shared trigger GVs (`V2GBP_CAP_TRIGGERS`, `V2EUR_CAP_TRIGGERS`) **before** the orphan scan. An instance about to halt still published zero layer counts and erased trigger history in the same `OnInit` where it discovered non-flat broker state.

### Functions inspected (pre-implementation)

| Function | Behavior relevant to this ADR |
|----------|-------------------------------|
| `V2_ScanInstanceOrphanPositions` | Counts open positions by entry + exit magic; returns combined ticket list. Does not touch GVs. |
| `V2_ProcessOrphanStartupCheck` | Halts when `layer_count==0 && position_count>0`; alerts only; **no** pending-order cancellation. |
| `V2_OnInitResultFromOrphanFlags` | `INIT_FAILED` only if **both** sides orphan; partial halt returns `INIT_SUCCEEDED`. |
| `V2_SyncAllCaps` (EURGBP) | Thin wrapper calling `V2_GbpCapSyncInstance` + `V2_EurCapSyncInstance` for the pair. |

Orphan scan has no dependency on cap GV writes; safe to run immediately after `Long_OnInit()` / `Short_OnInit()`.

### Trigger recording without prior GV

`V2_GbpCapRecordBlock` / `V2_EurCapRecordBlock` use `GlobalVariableCheck ? Get : 0` then increment — safe when the key never existed.

---

## Decision

### 1. Reorder `OnInit` (all three production files)

After `Long_OnInit()` / `Short_OnInit()`:

1. Run orphan scan for long and short (unchanged logic; sets `long_orphan` / `short_orphan` and halt flags).
2. **Per-side** cap publish via `V2_ShouldPublishCapSyncOnInit(side_orphan)`:
   - Flat side (`side_orphan == false`): publish `ArraySize(g_*_layers)` (zero on fresh attach).
   - Halted side: **skip** cap-sync call entirely; leave existing GV value untouched.

Partial halt: clean side still publishes; halted side skips (not a blanket skip for both).

### 2. Remove trigger GV reset from `OnInit` entirely

Delete all `GlobalVariableSet("V2GBP_CAP_TRIGGERS", 0.0)` and `GlobalVariableSet("V2EUR_CAP_TRIGGERS", 0.0)` from production `OnInit`. Not conditional on flat/halt — flat restart is the common case and resetting still destroys cross-instance trigger history (documented cap-enablement gate in ARCHITECT.md).

---

## Known deferred limitations (explicit)

This fix does **not** make the cap system safe to enable at nonzero thresholds by itself. Two problems remain open for a follow-up:

1. **Stale-direction GV:** Skipping publish on halt leaves a prior layer count that may be wrong if positions changed while detached (manual closes/opens). Stale is not always conservative (can under-block opposite-direction adds).
2. **Missing GV reads as zero/permissive:** If no prior GV exists and publish is skipped, cap readers treat absence as zero — unsafe when real orphan positions exist.

Cap thresholds must remain at **0** until a follow-up adds e.g. a stale/unconfirmed marker that cap readers treat conservatively. **Out of scope for Part A.**

Unrelated: State Reconstruction Engine remains parked separately.

---

## Consequences

- Orphan-halt startup no longer broadcasts confirmed-flat zero exposure to peer instances.
- Shared trigger history survives EA restarts (no silent erase on EURGBP attach).
- Per-side publish on partial halt preserves correct GV for the clean side.
