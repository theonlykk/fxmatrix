# ADR-074 — Tier 3 Emergency System Sweep (ExecuteEmergencySystemSweep)

**Status:** Accepted

## Context

On 2026-07-02, Tier 3 (4% daily drawdown) fired on all three FXMatrix instances. MM's `SaveInventoryState` went from **5/7/3 layers to 0/0/0** in under 2 seconds while **11 broker positions remained open** (e.g. GBPUSD tickets 486140829, 486044662, 486044637, 486016661 — MM grid layers with `EA_MAGIC+1`).

**Incident figures:** equity ≈ 9712.27 vs `daily_start` 10117.59, `tier3_floor` ≈ 9712.89 (4% hard kill).

### Root causes (independently confirmed)

1. **Magic filter scope:** `CloseAllPositions()` only closed `POSITION_MAGIC == EA_MAGIC`. Layer 0 entries use `EA_MAGIC`; add_next layers use `EA_MAGIC+1`; exit hedges use `EA_MAGIC+2`. Grid layers 1+ were never selected for closure.

2. **Unconditional inventory clear:** After close attempts, Tier 3 ran `ArrayResize(g_inventory_*, 0)` with **no** `PositionSelectByTicket` verification. Internal state was wiped regardless of broker reality.

3. **No failure telemetry:** Successful closes were silent; stranded positions produced no `g_critical_alerts` entry.

## Decision

Consolidate both Tier 3 trigger paths (4% daily drawdown and legacy absolute equity floor) into a single function:

**`ExecuteEmergencySystemSweep()`** in `StateEngine.mqh`.

### Sweep sequence

1. **Broker scan (Step A):** Iterate `PositionsTotal()` with the **same symbol + magic filter as `CheckForOrphans()`** — all three triad symbols, all three magics (`EA_MAGIC`, `+1`, `+2`). Send `TRADE_ACTION_DEAL` market close per position. Track every attempted ticket in `close_attempted[]`.

2. **Cancel orders:** `CancelAllPendingEntries()` unchanged, plus explicit loop for `EA_MAGIC` / `+1` / `+2` pending orders (preserved from prior Tier 3 logic).

3. **Batched verification poll (Step B):** Up to **5 rounds × 50 ms**, checking **all** outstanding tickets each round (not serial per-ticket). Break early when every ticket confirms closed via `!PositionSelectByTicket()`. Worst-case delay ~250 ms regardless of position count — serial per-ticket polling would scale linearly with layer depth and violate the "time is blood" principle at Tier 3.

4. **Stranded alerts (Step C):** Any ticket still open after poll → `CRITICAL: Tier 3 Sweep Failure. Stranded position ticket=...` pushed to `g_critical_alerts[]`.

5. **Selective inventory purge (Step D):** `PurgeClosedLayers()` removes only layers whose `position_ticket` is confirmed closed. Stranded layers **remain in inventory** so existing **ADR-040 OnInit reconciliation** (`g_reconciliation_pending` exit re-arm) resumes management on next reattach — no new resumption logic.

6. **`SaveAllInventoryState()` → `g_halted = true` → `ExpertRemove()`**

### Trigger simplification (`FXMatrix.mq5`)

Both blocks retain **verbatim** CRITICAL `Print()` lines for log-search continuity. Body replaced with:

```mql5
ExecuteEmergencySystemSweep();
return;
```

### Array reference pattern

`PurgeClosedLayers(Layer &inv[], ...)` uses MQL5 dynamic-array reference semantics — `ArrayRemove()` mutates the caller's global `g_inventory_*` in place (same pattern as direct `ArrayRemove(g_inventory_0, i, 1)` used throughout `ExecutionEngine.mqh`).

## Negative space

- **`ClosePodPositions()` (Tier 1)** — explicitly **out of scope**; deferred to full codebase audit (same magic-filter class of bug may exist there via inventory-ticket close, but Tier 1 uses ticket-based selection not magic scan — separate review).
- **`CloseAllPositions()`** — retained in `FXMatrix.mq5` but **no longer called** (dead code; safe removal deferred).
- **`CancelAllPendingEntries()`** — unchanged
- **`CheckForOrphans()`** — OnInit-only, untouched
- **`CheckDirectionConsistency()` (ADR-071)** — untouched
- **ADR-072 CloseBy exhaustion** — separate mechanism, untouched

## Tests

**Test 51** added to `temp/run_tests_0_41.py` — pure Python mirror of batched poll early-break logic (5 subtests: all close round 1, none stranded, one stranded after 5-round exhaust, empty input no-op).

## Consequences

- Tier 3 now closes all instance magic variants, not Layer 0 only
- Inventory state cannot diverge to empty while broker positions remain open without critical alert
- Stranded layers preserved for ADR-040 reattach path instead of silent orphaning
- Both Tier 3 triggers share one audited code path — no duplicated sweep logic
