# ADR-042 — LDAK Intent Gate + 70% Volume Binary Gate

**Status:** Committed

## Context

During fast unilateral USD moves on 2026-06-25, EURUSD and GBPUSD both breached the signal threshold simultaneously while `g_corr` was stale. The rolling correlation math in `ComputeLDAKLotSize()` did not reflect live same-direction intent across the AC/BC pair, allowing double USD exposure when both pods attempted entry at full size.

## Decision

Two mandatory changes to `ComputeLDAKLotSize()` in `ExecutionEngine.mqh`:

1. **Intent Gate** — Before computing `S_eff` from `g_corr` and `g_vratio`, scan the correlated peer slot (AC↔BC only) for same-direction intent in open positions (`EA_MAGIC`, `EA_MAGIC+1`) and pending entry limits (`EA_MAGIC`, `EA_MAGIC+1`). Exit limits (`EA_MAGIC+2`) are explicitly excluded. On overlap, force `S_eff = 10.0` locally and skip the correlation loop entirely. Direction is passed via `signal_direction`; inventory arrays are not polled for direction.

2. **70% Volume Binary Gate** — After computing `w`, calculate `raw_vol = BaseLotSize * size_mult * w`. If `raw_vol < min_vol * 0.70`, return `0.0` and suppress the quote. Otherwise return `MathMax(raw_vol, min_vol)`. Both `PlaceEntryLimit()` and `PlaceNextEntryLimit()` check the returned volume before `OrderSend`.

## Consequences

- Strict binary gate today: sub-70%-of-minimum sizing pulls the quote entirely rather than submitting a clipped order.
- True fractional scaling deferred until `BaseLotSize` scales to 0.05 or higher, at which point the 70% threshold will permit proportional sizing above broker minimum.
- Grid dilation logic in `MathEngine.mqh` is unchanged.
- SLOT_AB (EURGBP) has no peer for intent gate; correlation loop runs as before.

## Negative Space

- Internal memory overrides only (`S_eff` local override); no modification to `g_corr[]`, `g_vratio[]`, or any global state.
- No new input parameters.
- `PlaceExitLimit()` and exit order placement unaffected.
- Magic number semantics unchanged.

## ADR-042 Fix (sequential asymmetry bug)

**Status:** Implemented

### Root cause

The original intent gate lived inside `ComputeLDAKLotSize()`, which is called once per order inside `PlaceEntryLimit()`. In MARKET_MAKER flat quoting, bid and offer are placed sequentially. The first order (e.g. GBPUSD BUY) is evaluated before the peer's order (EURUSD BUY) is on the book — no overlap is found and the order is placed. When the second order on the same slot (GBPUSD SELL) is evaluated, the peer's resting limit is already present — the gate fires and suppresses it. Result: asymmetric quoting (one limit placed, one suppressed).

### Fix

1. **Slot-level pre-placement gate** — `IsSlotSuppressedByLDAK()` in `ExecutionEngine.mqh` evaluates once per slot in the MARKET_MAKER quoting loop in `FXMatrix.mq5`, before either bid or offer is placed. Direction-agnostic: either both limits are placed or neither is (`continue` skips the entire slot).

2. **`ComputeSlotSEff()`** — Helper that computes live `S_eff` from `g_corr[]` and `g_vratio[]` without inventory gating. Used by `IsSlotSuppressedByLDAK()` to apply the 70% volume threshold when the peer slot has an open position or pending entry limit.

3. **Intent gate removed from `ComputeLDAKLotSize()`** — The per-order same-direction overlap scan and `S_eff = 10.0` override are deleted. The correlation loop runs unconditionally. Signature simplified to `double ComputeLDAKLotSize(int instrument)` (no `signal_direction`).

### Consequences of fix

- Symmetric slot-level suppression replaces asymmetric per-order suppression.
- SNIPER mode unchanged — single-sided by design; no slot-level gate added there.
- 70% binary volume gate in `ComputeLDAKLotSize()` unchanged.
- ADR-043 Phase 3 resume gate unchanged.
