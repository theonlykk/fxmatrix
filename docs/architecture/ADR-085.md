# ADR-085: Removal of half_spread Compensation from Exit and Entry Pricing

## Status
Approved (Gemini Staff Architect ruling) — Implemented

## Context
`half_spread` was being subtracted from exit-price targets in
`ComputeExitPriceDeterministic()` (both the legacy 7-parameter and the
ADR-082 8-parameter overload) and applied to entry quoting in
`InvertSpreadToPrice()`. This "compensate for crossing the spread" term
contradicts this project's confirmed identity as a strict passive
liquidity provider (ADR-031: never crossing the spread). Backtest
analysis traced two real violations to this logic: an exit landing
below the stated 3-pip floor, and an exit landing on the wrong side of
entry entirely.

## Decision
Remove `half_spread` entirely from:
- `InvertSpreadToPrice()` — no longer adjusts the routed price by
  plus-or-minus half_spread; the AB-pair liquidity guard (checks
  `ab_bid`/`ab_ask` validity) is preserved, since it serves a different
  purpose (refusing to quote when liquidity data is unavailable) and
  does not depend on the half_spread computation.
- `ComputeExitPriceDeterministic()` — the `half_spread` parameter is
  removed from both overloads' signatures; exit targets are computed
  without any spread compensation term.
- All call sites (`HandleEntryFill()`, `RunCarryRecalculation()`,
  `HandleExitFill()` ADR-056 restitution block, `OnInit()`
  reconciliation) updated to stop computing/passing `half_spread`.

Dead code removed alongside: the `ac_bid`/`ac_ask`/`bc_bid`/`bc_ask`
fetches and `ac_half_spread`/`bc_half_spread` computations in
`InvertSpreadToPrice()`, which existed solely to feed the removed
half-spread adjustment and had no other use.

## Consequences
- Exit and entry prices are now computed purely from the strategy's own
  passive-liquidity-provider logic, with no spread-crossing
  compensation term.
- Explicitly out of scope for this ADR: extending the liquidity guard
  in `InvertSpreadToPrice()` to also check AC/BC pair bid/ask validity
  (currently AB-only). Noted as a possible follow-on but not pursued
  here, to avoid scope creep beyond what was gathered and approved.
- Test suite (`temp/run_tests_0_41.py`) required updates to remove
  half_spread-dependent expected values in tests 0b/0c/0d, 12, 16-19,
  43, 58, and 60. Subtest 58d, which specifically validated
  half_spread sign-convention behavior, was removed, as it tests a
  mechanism that no longer exists.
