# ADR-082 — Kinetic-Derived Exit Sizing (Unified Geometric Engine)

**Status:** Accepted

## Problem: Arbitrary Fixed Exit Floor

The hard minimum exit distance (`MinLayerExitPoints = 30` broker points = 3.0 pips on 5-digit symbols) exists solely to avoid round-trip commission losses. It is independent of the kinetic signal already trusted for add-side spacing (`GridBase`, `ComputeKineticDistance()`). This introduces a third arbitrary constant rather than tying exit geometry to the same real-time volatility signal validated for the add side.

## Decision: Kinetic-Derived Exit Formula (HandleEntryFill Only)

When `DebugUseUnifiedAddNextSpacing=true`, `HandleEntryFill` routes exit locking through a new **8-parameter overload** of `ComputeExitPriceDeterministic()` that derives exit distance from the same kinetic signal as the unified add path:

```
kinetic_dist_pips = kinetic_dist_raw / (point_value * 10.0)
exit_pips = max(min_layer_exit_points / 10.0,
                min(kinetic_dist_pips / ExitKineticDivisor,
                    ExitKineticCapPips))
exit_dist_price = exit_pips * point_value * 10.0
```

**Permanent inputs (Globals.mqh):**

| Input | Default | Role |
|-------|---------|------|
| `ExitKineticDivisor` | 3.0 | Scales kinetic distance down so exit < add by construction |
| `ExitKineticCapPips` | 8.0 | Upper cap on kinetic-derived exit distance (pips) |

**3-pip floor:** `min_layer_exit_points / 10.0` preserves the original commission-cost justification.

**8-pip cap:** Calibrated against this session's real dataset — `24.6 pips / 3 ≈ 8.2`, sitting near the 75th percentile of observed `kinetic_dist` values. Engages in the upper quartile of real conditions, not only rare extremes.

**Division by 3:** Ensures exit distance stays smaller than add distance using the same underlying signal (verified across observed range 3–79.9 pips).

### Empirical Calibration (137 Kinetic-Win Observations)

| Percentile | kinetic_dist (pips) |
|------------|---------------------|
| 50th (median) | 14.8 |
| 75th | 24.6 |
| 90th | 39.4 |
| 95th | 57.1 |
| Max | 79.9 |

Applying the formula to all 137 observations:

- Hits 3-pip floor: 1.5%
- Hits 8-pip cap: 26.3%
- Scales smoothly between: 72.3%
- **Mean proposed exit: 5.58 pips** vs. today's flat **3.0 pips**

Ordering guarantee: exit < add in every case except the single boundary where `kinetic_dist` equals exactly the 3-pip floor (exit == add, not strictly ordered).

## Hard Dependency on ADR-080

The kinetic exit formula applies **only when `DebugUseUnifiedAddNextSpacing=true`**. With the toggle off (production default), the 8-parameter overload delegates directly to the untouched legacy 7-parameter function. The add side in that mode uses the legacy `E_n * 1.618` path without `ComputeKineticDistance()` — a kinetic-derived exit measured against a different add formula would break the ratio guarantee verified in Finding 9.

## Single-Threaded Execution Invariant (Ruling 1)

The 8-parameter overload calls `ComputeKineticDistance(instrument)` independently from `ComputeNextLayerPrice()`'s internal call. Per Staff Architect Ruling 1, this is acceptable because MT5 EA execution is single-threaded: `g_sigma_fv_pts` cannot update mid-`HandleEntryFill()`. Both calls return identical values within one execution. This is a **documented tradeoff**, not an enforced architectural guarantee — ADR-082 explicitly notes this invariant dependency.

## half_spread Compensation (Staff Architect Ruling)

The kinetic branch applies `half_spread` identically to the legacy function's interval-to-price step:

- BUY: `entry_price + exit_dist_price - half_spread`
- SELL: `entry_price - exit_dist_price + half_spread`

`half_spread` is a live-tick correction independent of which formula computed the interval.

## Scope: Function Overloading, HandleEntryFill Only

Kinetic-derived exit sizing applies **only at initial layer creation** (`HandleEntryFill`). Implemented via MQL5 function overloading — a new 8-parameter overload alongside the untouched 7-parameter legacy function — **not** a signature change to the existing function.

**Untouched call sites (zero edits):**

1. OnInit reconciliation pass (`FXMatrix.mq5`) — `half_spread=0.0`
2. CarryEngine carry-adjustment recompute
3. ADR-056 grid restitution (`ExecutionEngine.mqh`)

MQL5 resolves by argument count: 7-arg calls route to legacy; only `HandleEntryFill` passes the 8th `instrument` argument.

### Argument 1 — OnInit Cold-Start Hazard

`g_sigma_fv_pts` is written only by `ComputeTermStructure()` on bar close and defaults to `{0.0, 0.0}` on declaration. OnInit's reconciliation pass (per ADR-040 design) lacks reliable live bid/ask and cannot be assumed to have live volatility data. A kinetic-mode exit computed there could silently produce the mathematical floor regardless of actual market conditions.

### Argument 2 — Lifecycle Calibration vs. Drift

Finding 9's formula was calibrated and backtested strictly against initial layer creation. Allowing CarryEngine or ADR-056 restitution to dynamically recompute a kinetic-derived exit later in a layer's life would let a live-tick volatility change alter an already-open position's risk-reward ratio in ways never modeled or tested — independent of the OnInit reliability concern.

## Pip Conversion Discipline

Two non-interchangeable conversions exist in the codebase (confirmed Part 1):

| Pattern | Formula | Used by |
|---------|---------|---------|
| Broker points | `min_layer_exit_points * point_value` | Legacy 7-parameter exit floor |
| NudgePips / pip-labeled | `pips * point_value * 10.0` | ADR-082 kinetic branch |

The kinetic overload converts `kinetic_dist_raw` and `min_layer_exit_points` to a common pip basis before applying floor/scale/cap, then converts back via the NudgePips pattern.

## Unchanged

- Existing 7-parameter `ComputeExitPriceDeterministic()` body and signature
- `ComputeNextLayerPrice()` — no signature change (Ruling 1)
- OnInit, CarryEngine, ADR-056 call sites
- ADR-077/078/079/080/081 toggles and logic
