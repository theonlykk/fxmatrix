# ADR-081 — Orphaned Exit Retry Throttle + Serialization Safety

**Status:** Accepted

## Problem: Tick-Rate Retry Storm

When `PlaceExitLimit()` fails passivity at fill time (exit price within broker freeze band), the layer is orphaned: `exit_tickets` empty, `remaining_exit_volume` armed.

`AuditExitLimits()` runs **every tick** and calls `PlaceExitLimit()` with **no interval gate**. Each failure prints an **unconditional** `DIAG [ADR-040] PlaceExitLimit passivity fail` (not gated on `EnableVerboseLog`). At backtest tick rates this produces multiple lines per second until the market moves and placement succeeds ("successfully recovered orphaned exit").

**Option A rejected:** Gate or remove the DIAG print inside `PlaceExitLimit()` — treats symptom, not cause; retries would still fire every tick.

## Decision: Per-Layer Retry Throttle + One-Shot Escalation

Three new `Layer` fields (persisted in memory; legacy state files omit them — see serialization section):

| Field | Purpose |
|-------|---------|
| `last_exit_retry_time` | Minimum interval between attempts (`ExitRetryIntervalSeconds`, default 15s) |
| `first_exit_retry_time` | Wall-clock anchor for orphan episode |
| `exit_escalated` | One-shot latch — critical alert fires once per episode |

**Inputs (permanent, not debug toggles):**

```mql5
input int ExitRetryIntervalSeconds = 15;
input int ExitRetryMaxSeconds        = 300;
```

`AuditExitLimits()` reads/writes all three fields via `g_inventory_X[i]` directly (never the local `L` value copy), matching the existing `exit_tickets` pattern.

On successful placement: all three fields cleared to `0 / 0 / false`.

On failure past `ExitRetryMaxSeconds`: one-shot `CRITICAL [ADR-081]` alert to `g_critical_alerts` buffer; `exit_escalated = true` prevents repeat alerts.

**Unchanged:** `PlaceExitLimit()` body, stale-ticket clearing block, `HandleEntryFill` fill-time placement, ADR-077–080 toggles.

## Serialization Safety (DeepSeek Adversarial Review)

Adding struct fields without updating `InitLayer()` creates **uninitialized memory** in MQL5 local struct copies — not zero. **Mandatory same-commit fix:**

```mql5
L.last_exit_retry_time  = 0;
L.first_exit_retry_time = 0;
L.exit_escalated        = false;
```

**Symmetric load-time bounds** in `LoadInventoryState()` (on local `L` before append):

```mql5
if (L.first_exit_retry_time > TimeCurrent() || L.first_exit_retry_time < L.entry_time)
    L.first_exit_retry_time = 0;
if (L.last_exit_retry_time > TimeCurrent() || L.last_exit_retry_time < L.entry_time)
    L.last_exit_retry_time = 0;
```

Both datetime fields get identical two-sided checks. `exit_escalated` intentionally omitted (bool — no temporal range).

**Schema versioning foundation:** `SaveGlobalState()` writes `"schema_version": 1`. `LoadGlobalState()` parses it into `g_loaded_schema_version`. No enforcement/halt on missing or old version — foundation only.

Source: DeepSeek adversarial review (InitLayer single-point-of-failure, symmetric bounds rationale, schema_version foundation).
