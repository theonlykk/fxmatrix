## Background

### Why this work happened

Production V2 consists of three ~1,600-line EAs (`fxmatrix_v2.mq5`, `fxmatrix_v2_eurusd.mq5`, `fxmatrix_v2_eurgbp.mq5`) that are structurally identical except for pair-specific constants, signal path (BC native vs AB triad), cap wiring, and EURUSD-only deadband vol-scale. Every ADR since 2026-07-18 was applied three times (or inlined three times), creating a maintenance burden and drift risk.

The Phase 1 **`_ref` branch was abandoned.** It added macro/dispatch scaffolding but retained three full logic duplicates and fell behind live production. Per Gemini's **2026-08-02 parameterization scope ruling** (integrated into `UNIFIED_V2_ENGINE_DESIGN_SPEC_DRAFT.md`): rebuild from **current live production only** — no behavioral changes, no parameter recalibration — using a typed preset for structural constants and shell `input` declarations for all behavioral parameters. Phase 1 `_ref` artifacts were archived at `ea/archive/phase1_ref_deprecated/`.

The Mandatory Refactoring Parity Gate (`ARCHITECT.md`) was applied before any cutover decision: unified shells (`fxmatrix_v2_unified_*.mq5`) vs production, all three pairs, five canonical windows, real-tick tester config, dual-tolerance comparison.

## Architecture (Summary)

Full detail: `docs/architecture/UNIFIED_V2_ENGINE_DESIGN_SPEC_DRAFT.md`. Briefly:

| Layer | Artifact | Role |
|-------|----------|------|
| **Preset** | `V2PairPreset` + `fxmatrix_v2_preset_{gbpusd,eurusd,eurgbp}.mqh` | Structural constants only: magic numbers, telemetry labels, signal slot (BC native vs AB triad), cap profile, deadband enable flag, leg symbol defaults |
| **Dispatch** | `fxmatrix_v2_l0_signal.mqh` | Pure L0 core (`V2_L0CoreComputeBc/Ab`) + wrapper (`V2_L0ComputeBid/Offer`) routing by `g_preset.signal_slot` |
| **Cap bridge** | `fxmatrix_v2_cap_bridge.mqh` + per-shell bridge implementations | Engine calls `V2_Cap_CheckBlocks` / `V2_Cap_RecordBlock` / `V2_Cap_Sync` exclusively — never direct cap-module APIs |
| **Engine** | `fxmatrix_v2_engine.mqh` (~1,533 lines) | Pair-agnostic shared body: Long_/Short_ lifecycle, rollover (ADR-101), ADR-102 halt gate, ADR-103 OnInit sequencing, telemetry |
| **Shells** | `fxmatrix_v2_unified_{gbpusd,eurusd,eurgbp}.mq5` | Thin deployment artifacts: preset fragment + cap headers + bridge impl + production-default inputs + `#include engine` last |

Behavioral parameters live in shell `input` declarations only — the preset does not shadow them.

## Bugs Found and Fixed During Parity Testing

Both bugs were found during Mandatory Refactoring Parity Gate runs. Neither was present in production (production files were not modified). Fixes landed in `ea/fxmatrix_v2_l0_signal.mqh` and are included in commit `e76fbba`.

### Bug 1 — BC `bc_now` guard divergence

**Symptom:** GBPUSD unified theoretical prices diverged from production by ~0.9 pips from the first affected bar (`2022.08.01 00:10:09`, truss_crisis), despite identical bid/ask at order placement.

**Root cause:** Phase A aligned unified BC `bc_now` with guarded `V2_MidNowFromSymbol()` semantics (skip half-spread when bid/ask invalid). Production BC path uses **unguarded inline** `closes[0] + (ask - bid) / 2.0` with no validity check — verified verbatim in `fxmatrix_v2.mq5` and `fxmatrix_v2_eurusd.mq5` (grep: zero `V2_MidNowFromSymbol` calls on BC path).

**Fix:** Reverted `V2_L0CoreComputeBc` to production's unguarded half-spread formula. Additional hardening: pass `closes[]` by reference into core (eliminate struct `ArrayCopy`); resolve `V2_L0ResolveLiveSpreadPrice` after `CopyClose` + bid/ask read (match production call order).

**Confirmation:** GBPUSD parity gate — 5/5 windows exact match after fix, including `vaccine_rally` (manual GUI verification, Gate 1); truss_crisis deal sequences and prices identical.

### Bug 2 — AB path `ArrayCopy` series-index scramble (EURGBP)

**Symptom:** EURGBP unified `bid_theo` diverged by ~16 pips from bar zero (`2022.08.01 00:05:06`, truss_crisis): production **0.83812** vs unified **0.83646**, despite identical EURGBP market and matching FV/sigma/ratio.

**Root cause:** `V2_L0ComputeImpl` AB branch copied `ac_closes[]` and `bc_closes[]` into `V2L0AbInputs` struct members via `ArrayCopy` before calling `V2_L0CoreComputeAb`. This scrambled the as-series `[0]` index used for `ac_now`/`bc_now` while FV indices `[6,12,48]` remained coincidentally correct — same bug class as Bug 1's BC struct copy, never carried over to the AB path when BC was fixed. Wrapper logged pre-copy `ac_close0=1.02261`; core computed with post-copy `[0]≈1.02046`, corrupting `inst_spread`.

**Fix:** Added `V2_L0CoreComputeAb` overload taking `ac_closes[]`/`bc_closes[]` by reference (mirrors BC fix); removed `ArrayCopy` calls; moved `V2_L0ResolveLiveSpreadPrice` to after `CopyClose` + bid/ask read on AB branch.

**Confirmation:** First-bar re-run — `ac_now=1.02299`, `bid_theo=0.83812` (production match). Full EURGBP gate — 5/5 windows exact match, including `vaccine_rally` (manual GUI verification, Gate 1, $176.91 / 1,740 trades exact match); truss_crisis ($140.65 / 1,740 trades) deal sequences identical throughout.

## Consequences (If and When Accepted)

- Single engine body (`fxmatrix_v2_engine.mqh`) becomes the maintenance target for shared Long_/Short_ logic across all three pairs.
- Cap-specific verbose logging removed from engine (pair-specific net-exposure prints); blocking semantics unchanged via shell bridges.
- EURGBP unified shell uses empty-string leg defaults with runtime sanitization (`V2_L0LegInputUsable`) — stale tester `.set` profiles may still inject corrupted leg descriptors; deployment hygiene required.
- Cutover without Gate 2 drill would leave ADR-102/103 live-behavior unverified under the only conditions that exercise them.
