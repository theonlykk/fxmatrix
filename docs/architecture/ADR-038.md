# ADR-038: Remove ADR-036 Exit Clamp; Align ADR-037 Gate with Exit Floor

**Status:** Accepted

## Context

Two defects were identified in the exit and entry gating pipeline:

### ADR-036 misapplication

ADR-036 ("Dynamic Exit Clamp — overrun protection") was designed as overrun protection for directional exits. In FXMatrix V3's passive market-making model, it misapplies that logic:

- When a SELL limit exit is in-the-money (ask has risen above `exit_price`), ADR-036 moves the exit price **up** away from execution — the opposite of correct passive behaviour.
- In a passive market-making model, an in-the-money limit resting on the book is the ideal condition; it should remain untouched until lifted.
- ADR-036 therefore corrupts prices computed upstream by `ComputeExitSpreadTarget` and `InvertSpreadToPrice`.

### ADR-037 gate / exit floor desynchronisation

The ADR-037 entry gate checked `MathAbs(inst_spread) <= SkewFloor0` (0.0002 = 2 pips). The exit floor in `ComputeExitSpreadTarget` used `MinLayerExitPoints=30` → 30 × 0.00001 = 0.0003 (3 pips).

Signals between 2–3 pips passed the gate, entered, then produced wash trades because `floor_skew > 1` → clamped to 0.99 → `exit_spread ≈ entry_spread`.

## Decision

### 1. Remove ADR-036 from `PlaceExitLimit`

Remove the entire ADR-036 scoped block from `PlaceExitLimit` in `ExecutionEngine.mqh`. Freeze level check, `IsPassive` check, and order submission logic remain unchanged.

### 2. Align ADR-037 gate with exit floor formula

In `FXMatrix.mq5`, replace the gate condition:

```mql5
if (MathAbs(inst_spread) <= SkewFloor0)
```

With the same `floor_n` computation used at layer 0 in `ComputeExitSpreadTarget`:

```mql5
double phi     = 0.6180339887;
double point   = SymbolInfoDouble(inst_symbol, SYMBOL_POINT);
double floor_n = MathMax(SkewFloor0 * MathPow(phi, 0), MinLayerExitPoints * point);
if (MathAbs(inst_spread) <= floor_n)
```

Baseline bracket fallback logic inside the gate block is unchanged.

### 3. Lower `MinLayerExitPoints`

Change `MinLayerExitPoints` from `30` to `2` in `Globals.mqh` so that `SkewFloor0` governs at layer 0 rather than the hard broker-point floor dominating.

## Consequences

- In-the-money exit limits are no longer re-priced away from execution at placement time.
- Entry gate and exit floor use identical `floor_n` arithmetic — no 2–3 pip gap where entries pass but exits collapse to wash trades.
- `MinLayerExitPoints=2` ensures the hard floor (0.00002) stays below `SkewFloor0` (0.0002) at layer 0.
- Test 10 (ADR-036 dynamic exit clamp) is superseded; Test 13 validates the synchronisation fix.
- `HandleEntryFill`, `AuditExitLimits`, `IsClearOfFreezeLevel`, `IsPassive`, and `ComputeExitSpreadTarget` are unchanged.
