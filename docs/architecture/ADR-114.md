# ADR-114: V2.5 Layer-Anchor Ratchet -- Carry-Corrected Reload Origin

## Status

Accepted -- 2026-08-13. Shipped in the V2.5 ratchet commit (parent HEAD
`6f5d92f`). Relates to: ADR-017 (flat-L0 deadband requote -- preserved as
INV-1), ADR-045 (carry exit-drift, uncapped by design -- the exposure INV-3
neutralizes), ADR-106..113 (State Reconstruction Engine -- INV-2/INV-3
operate strictly within the ADR-112/113 closed-history boundary). Supersedes
nothing.

## Context

### The flaw

The grid was framed as anchor-relative: L0 a fixed price, layers fixed
offsets from it. An arbitrary, possibly-outlier starting point acquires
false gravitational significance -- the system implicitly "wants" price to
return to L0.

### Source reframe (verified at 6f5d92f)

Inspection of the shipped engine showed the system is already more dynamic
than the flaw statement implied:

- L0 is a computed signal (fair value), not a static anchor: the first entry
  of a fresh stack anchors to `V2_L0ComputeBid` (`engine.mqh` 122-126).
- Within an open stack the reload ALREADY re-anchors to the last exit:
  `Long_ComputeAddTarget` (`engine.mqh` 267-283) places the next add relative
  to `g_long_last_exit_price` when `last_exit_valid`.
- The exit handler sets that anchor to the exited layer's ENTRY price
  (`Long_RemoveLayerAt` `engine.mqh` 479), and `V2_OnOwnStackFlat` CLEARS
  `last_exit_valid` the instant the side goes flat (`engine.mqh` 494-496),
  after which the next stack re-anchors to the signal.

Therefore V2.5's real delta is one change of intent: anchor the reload to the
carry-corrected HARVEST level (entry +/- InpExitPips) instead of the exited
ENTRY price. It is a ~3-pip refinement of an existing mechanism, not a new
subsystem. Spacing (floor 9.0, widen 1.304), exit distance (3.0) and per-pair
values are identical across GBPUSD/EURUSD/EURGBP.

### Pipeline

Phase 1 DeepSeek adversarial teardown (threats T-A'/T-1/T-2/T-3 + a critique

## Decision

Anchor the CLEAN-HARVEST reload origin to the carry-corrected harvest level
`entry_price +/- InpExitPips`, computed via the shared
`V2_SRE_ExpectedExitPrice` formula in BOTH the live engine and SRE
reconstruction, so live and reconstruction share one stateless formula. Ship
GUARD-1 (rollover-ghost suppression). Verification path is unit tests plus a
forward shadow deploy; the MT5 Strategy Tester A/B is dropped.

Three binding invariants:

- INV-1: the origin does NOT persist across a flat side. Going flat clears
  `last_exit_valid` and re-anchors to the L0 signal (existing behavior,
  preserved). Cross-flat persistence is forbidden.
- INV-2: exit targets remain PER-POSITION and ENTRY-RELATIVE
  (`entry +/- ExitPips`). The shared side origin governs ONLY next-add
  placement and never re-derives an existing position's exit.
- INV-3: live and SRE compute the origin from ONE formula
  (`V2_SRE_ExpectedExitPrice`). Carry-immune (the entry-relative theoretical
  target does not drift with carry), no cross-restart fuzz.

GUARD-1: before honoring a re-base, suppress it within `InpRebaseBlackoutSec`
of broker midnight (symmetric window) OR when the fill spread exceeds
`InpRebaseMaxSpreadPips`; on suppression fall back to the entry anchor and let
the harvest complete normally.

Files: `fxmatrix_v2_engine.mqh`, `fxmatrix_v2_state_reconstruction.mqh`,
`fxmatrix_v2_logic.mqh`, `fxmatrix_v2_sre_oninit.mqh` (replay call-site),
`fxmatrix_v2_tests.mq5`, and the three unified shells.

## Rationale

### Teardown outcome, source-verified at 6f5d92f

- T-1 (re-base chain drift) -- REFUTED. DeepSeek's unbounded-walk repro
  threads the origin through flat states; the code clears `last_exit_valid`
  on flat and re-anchors the next stack to the signal (`engine.mqh` 494-496,
  122-126), so the walk is bounded to a single open stack. DeepSeek also
  inverted the long-side geometry (entries above origin rather than fade-the-
  low below) and flagged its own contradiction in its reasoning trace.

- T-A' (mid-flight-crash localization) -- premise correct, EXPLOIT REFUTED.
  DeepSeek was right that the origin is side-level shared, but wrong that a
  crash injects a false propagating origin. Exit targets are per-position and
  entry-relative (`engine.mqh` 436/1139; SRE `V2_SRE_ExpectedExitPrice`
  203-209 used at 614), so the origin cannot cascade into existing exits. On
  incomplete reconstruction the SRE defaults `last_exit_valid=false`
  (`state_reconstruction.mqh` 1169) and writes back to the live globals
  (`engine.mqh` 1473-1474 / 1494-1495); the next add falls back to the last
  surviving entry and self-heals on the next harvest -- DeepSeek's own
  recommended fix, already implemented.

- T-2 (carry-shift invariant) -- VALID, and it is V2.5's own change that
  opened it, now fixed by INV-3. The base invariant min-spacing(9) >
  add-to-exit(3) holds uniformly across all three pairs. But `carry.mqh`
  (`V2_RolloverShiftedExitPrice`) drifts the exit target away from entry every
  negative-carry night, uncapped by design (ADR-045; only a 15-pip warning
  log). The drifted exit keeps its magic, so neither the clean-harvest filter
  nor the spread-check screens it. A raw-fill anchor would therefore re-base
  to a carry-drifted price beyond the next layer. The CURRENT entry-price
  anchor is carry-immune; it was the proposed switch to the fill price that
  introduced the exposure. INV-3 (origin = entry +/- InpExitPips, the
  undrifted theoretical harvest level) neutralizes it and makes the parked
  "carry-exact L0'" unnecessary -- it is a formula, not stored state.

- T-3 (tester path-dependence) and Section 6 (D5 statistical design) --
  CREDITED. The MT5 Strategy Tester cannot faithfully simulate dynamic
  delete-and-replace of the ladder (fresh limits filled against same-tick
  range; broker queue priority lost on re-post), so a naive A/B measures a
  tester artifact. The pre-registered delta (= the fixed-anchor arm's own
  cross-window dispersion) is self-referential and gameable. Both drive the
  move to unit tests + shadow deploy.

### Net

Of DeepSeek's three headline mechanism exploits, two are refuted by existing
architecture it could not see (T-1, T-A'), one is real and traces to V2.5's
own design choice (T-2 carry, fixed by INV-3), and the methodology reds
reshape the verification path. The reframe reduces V2.5 to a bounded ~3-pip,
carry-immune, per-position-safe, flat-bounded anchor shift.

## Consequences

Positive:

- Carry-immune origin: the theoretical harvest level does not drift with
  swap, closing the only surviving mechanism exposure.
- Foundational: lives in the shared engine, so all six instances plus a
  future V3 and new pairs inherit it.
- One stateless formula shared by live and SRE -- no cross-restart fuzz, no
  new state-file dependency.

Non-goals / deferred:

- No crash-atomic origin persistence. The D4 `POSITION_PRICE_OPEN` fallback
  is accepted: in the ~50ms window between an exit fill and ladder placement,
  a hard crash reverts that one recovery to the entry anchor -- non-atomic but
  safe-not-corrupting, manually reconciled if it ever bites.
- Carry-exact L0' via stored level+date is not built: the entry-relative
  formula is carry-immune, so exact storage is unnecessary.
- Rollover-ghost tick-confirmation is deferred in favor of the blackout +
  spread guard.
- `InpRebaseMaxSpreadPips` (default 8.0 pips) is a placeholder pending
  live-tuned calibration against observed rollover-second spreads; it is
  live-editable per shell.

Follow-ups:

- Forward shadow deploy is the gating evidence before V2.5 is treated as
  proven.
- ARCHITECT.md SRE backlog doc-staleness fix and this ADR's ledger entry are
  a separate doc-hygiene commit.
