# ADR-110: Baseline Flat-Side Entry-Pending Sweep (Bifurcated Quote-Lifecycle)

## Status

Accepted - implemented locally, Tier 1 607/615 (+2 new tests, all pass; 8 authorized Cases 3/5 reds unchanged per ADR-108 Problem 3). Compiles 0/0 on all four targets. Gemini rulings: Remedy (A) mandate and Option 1a ordering ruling, 2026-08-11.

## Context

ADR-109 added an entry-pending sweep on the SRE reconstruction success path. Drill A (live, faithful: natural fill at 0.0001, spread persisted across the crash, no mid-flight parameter change) proved that fix necessary but insufficient. On a `taskkill` crash-restart the book went from 6 resting entry-magic limits to 11; exactly one stale entry was swept.

Root cause: the ADR-109 sweep sits behind the orphan gate in `V2_SRE_RunSideOnInit`:

```
const int total_pos = ArraySize(entry_positions) + ArraySize(exit_positions);
if(!V2_IsOrphanedStartupState(cfg.layer_count, total_pos))   // layer_count==0 && pos>0
    return false;                                             // flat side returns here
...
result.entry_pendings_swept = V2_SRE_SweepEntryPendingOrders(...);  // orphaned side only
```

It runs per side and only when that side holds an orphaned position. In a market-making book, sides are flat-but-quoting the majority of the time and hold inventory on at most one side. So the "flat-book stale-L0" case documented as a known limitation in ADR-109 is not an edge - it is the dominant operating state, and it is where essentially all the duplicates occur. In the drill, 5 of 6 stale entries were on flat sides; none were swept. Even GBPUSD, which reconstructed its short side cleanly, duplicated on its flat long side.

## Decision

Add a baseline flat-side sweep in the production EA `OnInit`, per Gemini's ruling of **Option 1a**. The two lifecycles are handled separately:

- **Orphaned side** (holds positions): unchanged. The ADR-109 sweep stays at its post-reconstruction location, strictly after Step 3, so `V2_SRE_CheckPendingEntryConsistency` evaluates the raw pre-crash broker state before any `TRADE_ACTION_REMOVE` side effect. Its fail-closed halts (HALT_05/06/11/13/20) are preserved.
- **Flat side** (zero positions): swept in baseline `OnInit`, after the SRE orchestration block and before the tick loop re-quotes.

### Mechanism

`V2_SweepFlatSideEntryPendings(symbol, entry_magic, exit_magic, side_direction)` gates on **zero open positions** for that side, then delegates to the unchanged `V2_SRE_SweepEntryPendingOrders`. The proven deletion logic is not touched (Gemini mandate). The zero-position gate structurally excludes both reconstructed sides (hold positions, already self-swept) and halted sides (hold positions, must stay frozen for manual reconciliation) - only genuinely flat sides are swept. Wired into all three production EA `OnInit` functions (`fxmatrix_v2`, `_eurusd`, `_eurgbp`), long and short.

### Gemini rulings (verbatim)

On approach and placement:

> "MANDATE REMEDY (A) - UNCONDITIONAL OnInit SWEEP. ... Sweeping stale orders guarantees the tick loop rebuilds the book at current theoretical prices, eliminating the risk of ghost limits catching off-market fills. ... BASELINE QUOTING ENGINE OnInit. As explicitly noted in ADR-109, this is a baseline quoting engine quote-lifecycle defect, not a crash-recovery defect."

On the ordering conflict (why the orphaned-side sweep stays post-reconstruction):

> "MANDATE OPTION 1a; PRESERVE FAIL-CLOSED GATES. ... We do not mask corrupted states; we halt on them. ... Orphaned Sides: Preserving the existing sweep location (post-reconstruction, strictly after Step 3) guarantees that V2_SRE_CheckPendingEntryConsistency evaluates the raw, unmodified pre-crash broker state before any TRADE_ACTION_REMOVE side-effects are authorized."

Options 1b (snapshot-then-sweep) and 1c (retire the consistency halts) were rejected: 1c is incompatible with the anti-tampering mandate (a corrupt pending state must hard-halt, not be quietly swept); 1b adds unnecessary `OnInit` state-management complexity.

## Testing

Two fixture tests added to `fxmatrix_v2_tests.mq5`:

1. Flat side (injected zero positions) with 2 entry-magic limits + 1 exit-magic limit -> `swept == 2` (exit preserved, delegation to the proven filter confirmed).
2. Non-flat side (injected position count 1) -> `swept == 0` (the gate returns before any sweep; protects reconstructed and halted sides).

Suite: **607/615** (+2 pass). Fail count unchanged at 8 = authorized Cases 3/5 reds (ADR-108 Problem 3). Compile 0/0 on `fxmatrix_v2`, `_eurusd`, `_eurgbp`, and the test target.

Note: as with ADR-109, unit tests exercise the gate and filter but not the live `TRADE_ACTION_REMOVE`. Live confirmation is a terminal-kill restart drill on a flat book (expect zero duplicates on all sides).

## Consequences

**Positive:**
- Duplicate resting entry quotes are eliminated on the dominant (flat-but-quoting) sides after a crash-restart, not just the single inventoried side.
- Resting quotes are rebuilt at current theoretical prices; no stale pre-crash ghost limits.
- The fail-closed pending-consistency gate on the orphaned/reconstruction path is fully preserved.
- Reuses the proven, drill-validated deletion helper unchanged.

**Negative / trade-offs:**
- A few API-counted deletes per flat side on every restart (bounded; restarts are rare).
- Brief un-quoted gap on a flat side between the sweep and the tick loop's re-quote (self-correcting on the next tick).
- `ORDER_STATE_PARTIAL` handling is inherited from the underlying helper (see ADR-109 known limitation 2); unchanged here.
