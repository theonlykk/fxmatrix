# ADR-026 — Entry Gate Race Condition Fix — Pending Ticket Guard

**Status:** Accepted

## Context

MT5 OnTradeTransaction fires asynchronously relative to OnTick.
HandleEntryFill zeroes g_pending_bid/offer before ArrayResize appends the
layer to g_inventory_X, creating a window where the slot appears empty to
OnTick, causing a machine-gun fill cascade (20+ orders in 6 seconds on GBPUSD).

## Decision

Extend the Option A entry gate to include pending ticket state:

    inst_inv_size > 0 || inst_bid > 0 || inst_offer > 0

## Consequences

Race window eliminated. No Highlander logic debt introduced.
Zero computational overhead (variables already in scope). Phase 3 resume
path unaffected (g_pending_bid/offer already zeroed before resume fires).
