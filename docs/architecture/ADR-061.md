# ADR-061 — Partial-Unwind Observability & Split LDAK Volume Gate

**Status:** Committed

## Context

Two independent failures on 2026-06-30 caused silent grid deepening loss on EURUSD MM:

1. **False success logging (Part A):** `HandleExitFill`'s partial-unwind block called `PlaceNextEntryLimit()` and unconditionally printed `"Phase 3 add-next resubmitted"` regardless of return value. When LDAK suppressed the order (sub-minimum volume), the grid stopped deepening with no failure indication. Confirmed at 15:02:05 (layer 4→3 partial unwind) and in the 13:11–13:14 cluster (layer=1).

2. **Undifferentiated volume gate (Part B):** `ComputeLDAKLotSize()`'s ADR-042 70% binary gate (`raw_vol < min_vol * 0.70`) returned `0.0` for both drawdown-driven suppression (`size_mult` near zero — a deliberate risk refusal) and correlation-only suppression (`w` low, `size_mult` healthy). The diagnostic line (`S_eff`, `w`, `lot_size`) only printed on the success path after the gate, making failure states unrecoverable from logs.

## Decision

### Part A — Conditional partial-unwind logging (`ExecutionEngine.mqh`)

Capture `PlaceNextEntryLimit()` return value and gate the success message on `tkt > 0`. On failure, emit an explicit `WARNING` instead of a false success message.

```mql5
ulong tkt = PlaceNextEntryLimit(NewShallowest, sym, computed);
if (tkt > 0) {
    Print("INFO: Phase 3 add-next resubmitted for new shallowest layer. ",
          "ticket=", tkt, " instrument=", NewShallowest.instrument,
          " price=", computed);
} else {
    Print("WARNING: add_next resubmission failed (tkt=0). Possible ",
          "sub-minimum lot size or API rejection. Grid deepening is halted. ",
          "instrument=", NewShallowest.instrument, " computed_price=", computed);
}
```

### Part B — Split gate in `ComputeLDAKLotSize()` (`ExecutionEngine.mqh`)

New input parameter in `Globals.mqh`:

```mql5
input double InpLDAKDrawdownHealthyThreshold = 0.80;
// size_mult above this = drawdown brake not engaged
```

When `raw_vol < min_vol * 0.70`:

| Condition | Outcome |
|-----------|---------|
| `size_mult < InpLDAKDrawdownHealthyThreshold` | **Refuse** — return `0.0` (ADR-042 drawdown brake preserved) |
| `size_mult >= InpLDAKDrawdownHealthyThreshold` | **Floor-clamp** — set `raw_vol = min_vol`, continue |

Unconditional diagnostic (before the gate, every call, `EnableVerboseLog` gated):

```mql5
Print("DIAG [ADR-061] ComputeLDAKLotSize: instrument=", symbol,
      " size_mult=", ..., " S_eff=", ..., " w=", ...,
      " raw_vol=", ..., " min_vol=", ...);
```

## Rationale

Continuous grid depth matters more than a fractional margin over-allocation when suppression is purely a correlation artifact. The drawdown brake is a genuine risk control and must not be weakened by the same fix. Silent and false-positive logging is a critical observability failure independent of the underlying volume bug — a functional failure must never be logged as success.

## Consequences

- Grid can no longer silently fail to deepen from either cause
- Every gate outcome (refuse, clamp, or pass) is fully attributable via the unconditional `DIAG [ADR-061]` line
- Drawdown brake behavior unchanged when `size_mult` is below threshold
- Correlation-only suppression now produces a minimum lot instead of killing the layer
- `PlaceEntryLimit` / `PlaceNextEntryLimit` post-call suppress checks remain as redundant safety net

## Negative Space

- `ComputeNextLayerPrice()` formula untouched
- ADR-052 sigmoid multiplier calculation untouched
- ADR-056 exit-limit restitution untouched
- Full-pod-flat branch (`remaining == 0`) untouched
- No other `PlaceNextEntryLimit` call sites touched
- `DetectInventoryCorruption()` remains unwired
- `MathEngine.mqh` untouched
