# ADR-096 — GBP Cap Init Wiring + Gated Synthetic Verification Inputs

**Status:** Pending

**Date:** 2026-07-24

---

## Context

Phase-1 `_ref` EAs for GBP-triad participants (`fxmatrix_v2_ref.mq5`, `fxmatrix_v2_eurgbp_ref.mq5`) include full cross-exposure cap **block logic** at all four `Long_/Short_EnsureAddNext` call sites:

- `V2_CrossCapBlocksNewAdd(g_v2_cross_cap, …)` gate
- `V2_CrossCapRecordBlock()` → increments `V2GBP_CAP_TRIGGERS` GV
- Verbose log: `"INFO V2_LONG | GBP cap blocked new add net="` (or SHORT equivalent), using `V2_CrossCapNetExposure(g_v2_cross_cap)` and `InpGbpCapThreshold`

Confirmed this session: **this block logic is production-equivalent and requires no change.**

The entire defect is upstream: **`V2_CrossCapInitGbpTriadLegacy()` was never called.** `g_v2_cross_cap` stays zero-initialized:

- `cfg.threshold = 0` → `V2_CrossCapBlocksNewAdd` always returns `false` (threshold ≤ 0 disables cap)
- `local_gv_long` / `local_gv_short` empty → sync and delta logic inert

All four cap-block branches are **dead code** despite correct implementation.

Production (`fxmatrix_v2.mq5`, `fxmatrix_v2_eurgbp.mq5`) initializes via `fxmatrix_v2_gbp_cap.mqh` inline helpers; `_ref` uses the generic `fxmatrix_v2_cross_exposure_cap.mqh` wrapper but omitted the init call.

`fxmatrix_v2_eurusd_ref.mq5` is a **non-participant** (delta = 0, never blocked) — no change.

Prior ADR-093/094/095 baselines used `InpGbpCapThreshold=0` (cap off). Even with init fixed, cap remains off at default until threshold is set explicitly in tester inputs.

---

## Decision

### 1. Wire cap init in OnInit (GBPUSD + EURGBP `_ref` only)

In `fxmatrix_v2_ref.mq5`:

```mq5
V2_CrossCapInitGbpTriadLegacy(g_v2_cross_cap, "GBPUSD", InpGbpCapThreshold);
```

In `fxmatrix_v2_eurgbp_ref.mq5`:

```mq5
V2_CrossCapInitGbpTriadLegacy(g_v2_cross_cap, "EURGBP", InpGbpCapThreshold);
```

Placed immediately after `Long_OnInit()` / `Short_OnInit()`, **before** existing `V2_CrossCapSyncInstance` calls (which require initialized GV keys).

### 2. Gated synthetic peer GV debug inputs (tester verification only)

Per Gemini ruling: Strategy Tester GVs are isolated per run and not pre-seedable externally. Synthetic peer state must be injected from within the EA under test.

Add to both GBP-triad `_ref` files:

```mq5
input int InpDebugSeedEurgbpShort = 0;  // TESTER-ONLY: seeds V2GBP_S_EURGBP for cap verification
input int InpDebugSeedEurgbpLong  = 0;  // TESTER-ONLY: seeds V2GBP_L_EURGBP for cap verification
```

In `OnInit()`, **after** the real cap init call:

```mq5
if(InpDebugSeedEurgbpShort != 0 || InpDebugSeedEurgbpLong != 0) {
   if(MQLInfoInteger(MQL_TESTER)) {
      if(InpDebugSeedEurgbpShort != 0) {
         GlobalVariableSet("V2GBP_S_EURGBP", (double)InpDebugSeedEurgbpShort);
         PrintFormat("DEBUG: Synthetic GV V2GBP_S_EURGBP seeded to %d", InpDebugSeedEurgbpShort);
      }
      if(InpDebugSeedEurgbpLong != 0) {
         GlobalVariableSet("V2GBP_L_EURGBP", (double)InpDebugSeedEurgbpLong);
         PrintFormat("DEBUG: Synthetic GV V2GBP_L_EURGBP seeded to %d", InpDebugSeedEurgbpLong);
      }
   } else {
      Print("FATAL: Debug seed inputs cannot be used outside the Strategy Tester. Halting.");
      return(INIT_FAILED);
   }
}
```

**Guardrail rationale:** Debug seeds must never run on a live chart. Accidental non-zero seed values on a real terminal could fabricate peer exposure and block legitimate adds. The `MQL_TESTER` gate plus `INIT_FAILED` on live chart is intentional live-chart accident prevention — not optional simplification.

Default `0` on both inputs: zero behavioral change for production-like runs and ADR-093/094/095 regression baselines (`InpGbpCapThreshold=0`).

### 3. No changes to block bodies, cross_exposure_cap.mqh, or production

The four existing cap-block branches, `V2_CrossCapRecordBlock`, and verbose logging are confirmed correct — untouched.

## Verification

**Compile:** Khalid GUI-compiles (F7) `fxmatrix_v2_ref.mq5` and `fxmatrix_v2_eurgbp_ref.mq5` from terminal Experts folder (sync from repo first).

**Window:** GBPUSD 5-day `2026.03.09`–`2026.03.14`, Model=4, `InpVerboseLog=true`.

Two GBPUSD-side runs required:

### Run 1 — Control (real GBPUSD exposure alone, Example A)

| Input | Value |
|-------|-------|
| `InpGbpCapThreshold` | **3** |
| `InpDebugSeedEurgbpShort` | **0** |
| `InpDebugSeedEurgbpLong` | **0** |

Expected behavior when GBPUSD reaches 3 LONG layers:

```
net = (3 − 0) − (0 − 0) = 3
Next widening LONG add: new_net = 4, |4| > 3 → BLOCK
```

Confirm:

- Journal contains `"INFO V2_LONG | GBP cap blocked new add net="` (at least once)
- `V2GBP_CAP_TRIGGERS` GV > 0 at end of run
- `V2_STATS_*` add count **lower** than unconstrained baseline (ADR-093/094: LONG add=11) — blocked add(s) visible as missing/reduced adds

### Run 2 — Seeded (synthetic peer injection, Example B or C)

**Example B** (threshold=3, peer seed flips marginal add):

| Input | Value |
|-------|-------|
| `InpGbpCapThreshold` | **3** |
| `InpDebugSeedEurgbpShort` | **1** |
| `InpDebugSeedEurgbpLong` | **0** |

With GBPUSD at 2 LONG: `net = 2 − (−1) = 3`; next LONG add → 4, blocked.

**Example C** (threshold=12, production-default scale):

| Input | Value |
|-------|-------|
| `InpGbpCapThreshold` | **12** |
| `InpDebugSeedEurgbpShort` | **9** |
| `InpDebugSeedEurgbpLong` | **0** |

With GBPUSD at 3 LONG: `net = 12`; next LONG add → 13, blocked.

Confirm for seeded run:

- Journal contains `"DEBUG: Synthetic GV V2GBP_S_EURGBP seeded to N"`
- Cap block log fires **deterministically** from peer injection independent of whether GBPUSD alone would have crossed threshold
- `V2GBP_CAP_TRIGGERS` increments

Report `V2_STATS_*` output and DEBUG/INFO log lines for both runs.

### Guardrail smoke test (optional)

Attach EA on live chart with non-zero debug seed → must print FATAL and return `INIT_FAILED`.
