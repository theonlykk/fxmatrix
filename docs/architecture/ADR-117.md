# ADR-117: Tier1 pairB/pairC LONG tests assert HALT_30 (retire the 8 authorized reds)

## Status

Accepted -- 2026-08-14. Test-hygiene change only; no production/SRE logic
change. Aligns the test baseline to behavior already ruled correct by ADR-108.

## Context

Since ADR-108, the unit suite has carried 8 permanently-red assertions -- the
LONG-side checks of Test_SRE_Tier1RealData_PairB_Gbpusd and
Test_SRE_Tier1RealData_PairC_Eurgbp (4 each). They were documented as
"authorized reds" and eyeballed by name on every run to confirm no NEW failure
was hiding among them.

These tests assert clean reconstruction (halt_reason == V2_SRE_OK, committed,
one layer) on Case 3 (GBPUSD long, order 510003492, 5.6pt residual) and Case 5
(EURGBP long, order 509107430, 8.5pt residual) -- overnight CloseBy pairs with
genuine execution-noise residuals spanning a broker midnight. But the SRE
CORRECTLY halts these by design: they return
V2_SRE_HALT_30_CLOSEBY_PRICE_INCONSISTENT (state_reconstruction.mqh:53, set at
:1015). ADR-108 deliberately left the strict 2pt HALT_30 band for
rollover_units>0 pairs, because widening it reopens the grid-cancellation
vector (rollover drift + spread ~= one grid step -- see ARCHITECT.md "Problem 3
-- HALT_30 Overnight Fill-Noise Availability Constraint").

So the CODE is correct and the TESTS were stale: they encoded the pre-ADR-108
expectation. A permanently-red suite degrades signal -- every green run required
manually confirming "the 8 reds are the RIGHT 8," and twice during the BCC
cycle real new failures hid in the count until grepped.

## Decision

Flip the 8 LONG-side assertions in the two tier1 tests to assert the by-design
halt instead of clean reconstruction:
- "long not halted" -> "long halted (HALT_30 by design)"
- "long committed" -> "long not committed (halted)"
- "long halt reason ok (== V2_SRE_OK)" -> "long halt reason HALT_30
  (== V2_SRE_HALT_30_CLOSEBY_PRICE_INCONSISTENT)"
- "long one layer" -> dropped (layer_count_after is not a meaningful invariant
  on a fail-closed halt; replaced with an explanatory comment)

The SHORT sides of both pairs reconstruct cleanly and their assertions already
pass -- untouched. No fixture, swap-override, or config setup changed; the
fixtures (SRE_Tier1FillCase3/5LongBroker) already model the real historical
overnight-noise pairs correctly. Only the expected OUTCOME was wrong.

This is Route A (assert the correct behavior), chosen over Route B (an xfail
registry) because the tests now positively verify the fail-closed HALT_30
behavior rather than merely suppressing a known failure.

## Consequences

Positive:
- The unit suite is now FULLY GREEN. "All tests pass" is once again a
  trustworthy signal; a single new FAIL is immediately visible instead of
  hiding among 8 expected reds.
- The tests now assert the ADR-108 security posture (overnight fill-noise
  fails closed), so a future regression that made these cases reconstruct
  clean -- reopening the vector -- would FAIL the suite loudly.

Neutral / non-goals:
- No change to the HALT_30 band, the SRE, or Problem 3. If Problem 3 is ever
  designed (a safe overnight fill-noise allowance), these assertions will need
  revisiting to match whatever new behavior is ruled.
- The ARCHITECT.md "Problem 3" backlog entry remains open and accurate; this
  ADR only updates the tests to match current (correct) behavior.
