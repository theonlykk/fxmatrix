# ADR-064 — Pipshed Telemetry Payload Enrichment

**Status:** Committed (pending)

## Context

ADR-063 introduced global state (`g_ldak_last_*`, `g_bias_backstop_count`, `g_critical_alerts[]`) for telemetry consumption. `TelemetryEngine.mqh` still emitted a minimal payload: per-pod `{layers, net_pnl, distance_to_target_pips}` plus top-level account/engine fields. Pipshed could not render live positions, working orders, LDAK gate status, or critical alert history without this enrichment.

## Decision

**One file changed:** `TelemetryEngine.mqh` (read-only access to ADR-063 globals and existing inventory/order state).

### `SerializePodJSON()` — layer detail + LDAK status per pod

Each pod now includes:

- **`layer_detail[]`** — per-layer objects with: `layer_index`, `direction`, `entry_price`, `entry_spread_raw`, `exit_price_fixed`, `add_next`, `lot_size`, `position_ticket`, `has_exit_limit`, `is_toxic`, `is_floor_clamped`, `resting_exit_missing`
- **`ldak_status`** — string mapped from `g_ldak_last_gate[slot]` via `LdakGateToString()` (`"pass"` / `"clamp"` / `"refuse"`)
- **`ldak_size_mult`** — from `g_ldak_last_size_mult[slot]`
- **`ldak_raw_vol`** — from `g_ldak_last_raw_vol[slot]`

Existing fields (`layers`, `net_pnl`, `distance_to_target_pips`) preserved.

### `BuildTelemetryPayload()` — top-level enrichment

New top-level JSON fields alongside existing `timestamp`, `account_metrics`, `engine_state`, `active_pods`:

| Field | Source |
|-------|--------|
| `working_orders` | `g_pending_bid/offer[slot]` + guarded `GetPendingOrderPrice()` |
| `market_prices` | live `SYMBOL_BID` / `SYMBOL_ASK` per slot symbol |
| `cooldown_ldak` | `g_cooldown_LDAK[slot]` |
| `bias_backstop_count` | `g_bias_backstop_count` |
| `system_alerts` | non-empty entries from `g_critical_alerts[]` (never cleared on read) |

### Helper additions

- **`TelPriceOrNull(double price)`** — renders `GetPendingOrderPrice()`'s `-1.0` sentinel as JSON `null` instead of a literal number
- **`LdakGateToString(int gate)`** — maps `ENUM_LDAK_GATE_OUTCOME` to string at serialization time (enum stored as int in globals per ADR-063 design note)
- **`GetPendingOrderPrice(ulong ticket)`** — forward declaration required (see below)

### `GetPendingOrderPrice()` forward declaration

`FXMatrix.mq5` `#include`s `TelemetryEngine.mqh` at line 16 but forward-declares `GetPendingOrderPrice()` at line 24. MQL5 compiles one translation unit per `.mq5`; function bodies in the included header are parsed before the host file's forward declare. A single forward declaration was added to `TelemetryEngine.mqh` above `SerializePodJSON()`. Definition remains in `FXMatrix.mq5` line 1212 — unchanged.

### `resting_exit_missing` rename

Field named **`resting_exit_missing`** (not `orphan_detected`). True when `position_ticket > 0` but `ArraySize(exit_tickets) == 0` — a layer holds a live position with no resting exit limit. Distinct from `CheckForOrphans()`'s OnInit broker-mismatch concept; avoids conflating telemetry commentary with startup reconciliation.

### `-1.0` to JSON `null`

`GetPendingOrderPrice()` returns `-1.0` when `OrderSelect` fails. `TelPriceOrNull()` converts this to JSON `null`. Every call site guards with `ticket > 0` before invoking `GetPendingOrderPrice()`, matching existing `FXMatrix.mq5` convention.

### `system_alerts` buffer dump

Iterates `g_critical_alerts[0..CRITICAL_ALERT_BUFFER_SIZE-1]`, omitting slots where `StringLen == 0`. Never clears buffer on read (ADR-063 Ruling 5 race-condition rationale). Pipshed receives only fired alerts, not 10 empty strings.

## Scoped OUT — `bias_status`

Routine SNIPER suppression indicator (`"active"` / `"suppressed"`) is **explicitly deferred**. The per-tick suppression check in `FXMatrix.mq5` is not persisted to any global. No proxy or inference from available state — field omitted entirely pending dedicated state capture in `FXMatrix.mq5`.

## Negative Space

- `EmitPodClose()` — unchanged
- `EmitTelemetry()` dispatch — unchanged
- No new input parameters; URL/auth unchanged
- ADR-063 globals and `ExecutionEngine.mqh` capture sites — read only, never written
- `FXMatrix.mq5`, `Globals.mqh`, `LayerStruct.mqh`, `ExecutionEngine.mqh` — untouched (except existing `GetPendingOrderPrice` definition, not modified)

## Consequences

- Pipshed dashboard can render layer-level positions, working order tickets/prices, market distance, LDAK gate state, and critical alert history from a single heartbeat payload
- F7 compile not run on this machine (static review only)

## Tests

No new unit tests — enrichment is JSON serialization only; ADR-063 Test 49 covers the alert buffer index logic consumed indirectly via `system_alerts`.
