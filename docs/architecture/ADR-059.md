# ADR-059 — EmitPodClose PnL Source Fix

**Status:** Committed

## Context

`HandleExitFill()` computes `real_profit` with an ADR-050 fallback: when `deal_profit == 0.0` (common for CloseBy-settled positions on hedging accounts), it reads `PositionGetDouble(POSITION_PROFIT) + PositionGetDouble(POSITION_SWAP)` before the position is removed. `LogLayerExit()` correctly receives `real_profit`, so local `LAYER_EXIT` logs show accurate `gross_pnl`.

`EmitPodClose()` was still passed raw `deal_profit`, producing `gross_pnl: 0.00` in the Pipshed `/pod_closed` telemetry payload despite correct values in the EA log.

## Decision

Pass `real_profit` (already in scope at the call site) as the seventh argument to `EmitPodClose()` instead of `deal_profit`. No signature change in `TelemetryEngine.mqh` — only the argument at the single call site in `HandleExitFill()`.

## Consequences

- Pipshed closed trades table shows accurate PnL for all exit types, including CloseBy settlements
- Telemetry PnL matches `LAYER_EXIT` log output for the same close event
- No duplicate P&L logic — reuses the existing ADR-050 correction path

## Negative Space

- `real_profit` calculation (lines 1022–1027) untouched
- `LogLayerExit()` call untouched
- `EmitPodClose()` function body in `TelemetryEngine.mqh` untouched
- No other call sites modified
