# ADR-093 — Merged Carry Port (ADR-3) + API Counter Rewire (ADR-4) for Phase-1 `*_ref` EAs

**Status:** Accepted

**Date:** 2026-07-24

---

## Context

Phase-1 parameterized EAs (`fxmatrix_v2_ref.mq5`, `fxmatrix_v2_eurusd_ref.mq5`, `fxmatrix_v2_eurgbp_ref.mq5`) were parity-validated against production V2 on five historical windows but lacked two production mechanisms wired only on the non-ref path:

1. **ADR-045 daily rollover** (`V2_RunDailyRolloverReconciliation` + `fxmatrix_v2_carry.mqh`) — shifts resting exit limits by broker swap on negative-carry nights.
2. **Account-wide daily API counter** (`V2_OrderSendCounted` / `V2_ApiCounterMaybeReset`) — counts every broker `OrderSend` across all six V2 chart instances.

Per Gemini's structural ruling, ADR-3 and ADR-4 were merged into one implementation pass because both touch the same `fxmatrix_v2_exits_r1.mqh` call sites and the same include-guard collision fix.

Read-only investigation confirmed:

- `fxmatrix_v2_exits.mqh` and `fxmatrix_v2_exits_r1.mqh` shared the guard `FXMATRIX_V2_EXITS_MQH`, causing the second `#include` to be silently skipped.
- `exits_r1.mqh` lacked `V2_ModifyExitLimitPrice` and `V2_ResolvePositionTicket` (present only in `exits.mqh`).
- `exits_r1.mqh` routed `V2_SendExitLimit`, `V2_CancelExitOrder`, and `V2_ProcessCloseByQueue` through raw `OrderSend`; production's `exits.mqh` routes through `V2_OrderSendCounted`.
- `carry.mqh`'s internal `#include "fxmatrix_v2_exits.mqh"` was redundant in production (each production `.mq5` already includes `exits.mqh` before `carry.mqh`) and would cause duplicate-definition collisions once `exits_r1.mqh` gained the ported functions.
- `_ref` layer structs/arrays use the same names as production (`LongV2Layer`, `ShortV2Layer`, `g_long_layers[]`, `g_short_layers[]`) but omit `open_depth` and `entry_time` — carry logic does not touch those fields; they were not added in this pass.
- `_ref` `OnTick()` was only `Long_OnTick(); Short_OnTick(); V2EmitTelemetry(false);` with no rollover or API counter reset.
- No `g_v2_last_rollover_day_of_year` existed in `_ref` — newly declared per file.
- `_ref`'s `Long_ResolvePositionTicket` / `Short_ResolvePositionTicket` are separate side-local duplicates and were not modified; carry calls `V2_ResolvePositionTicket` by name.

Production files were **not** modified.

---

## Decision

### 1. Rename `exits_r1.mqh` include guard

`FXMATRIX_V2_EXITS_MQH` → `FXMATRIX_V2_EXITS_R1_MQH` (both `#ifndef`/`#define` and closing `#endif` comment).

**Rationale:** Allows `carry.mqh` and `_ref` EAs to compile against `exits_r1.mqh` without guard collision with production's `exits.mqh` if both headers are ever pulled into the same translation unit during testing.

### 2. Port carry helpers into `exits_r1.mqh`

Copied verbatim (logic unchanged):

- `V2_ResolvePositionTicket`
- `V2_ModifyExitLimitPrice`

Inserted after `V2_CancelExitOrder`; no existing `exits_r1.mqh` functions were modified during the port.

**Rationale:** `carry.mqh` calls `V2_ModifyExitLimitPrice` and rollover reconciliation calls `V2_ResolvePositionTicket`. These must live on the `_ref` exits surface, not production's `exits.mqh`.

### 3. Rewire `OrderSend` → `V2_OrderSendCounted` in `exits_r1.mqh`

Three call sites only (no other logic changed):

| Function | Site |
|----------|------|
| `V2_SendExitLimit` | send path |
| `V2_CancelExitOrder` | cancel path |
| `V2_ProcessCloseByQueue` | CloseBy retry path |

**Rationale:** ADR-4 parity with production exits module; counter increments on every broker send attempt (including failures), matching `V2_OrderSendCounted` semantics.

### 4. Rewire `_ref` `.mq5` direct send sites

Six `OrderSend` → `V2_OrderSendCounted` substitutions per `_ref` file (long cancel, long entry limit, long reload limit × 3 functions; same for short side):

| File | Sites changed |
|------|---------------|
| `fxmatrix_v2_ref.mq5` | 6 |
| `fxmatrix_v2_eurusd_ref.mq5` | 6 |
| `fxmatrix_v2_eurgbp_ref.mq5` | 6 |

**Total rewire count:** 3 (`exits_r1.mqh`) + 18 (`_ref` `.mq5`) = **21 call sites**.

Long_/Short_ `ResolvePositionTicket` local functions were not touched.

### 5. Rollover wiring per `_ref` EA

- Declared `int g_v2_last_rollover_day_of_year = 0;` at file scope near other globals.
- Added `#include "fxmatrix_v2_carry.mqh"` after `fxmatrix_v2_exits_r1.mqh`.
- Ported `V2_RunDailyRolloverReconciliation()` inline into each `_ref` `.mq5` (same as production — not extracted to shared `.mqh`).
- Updated `OnTick()` ordering to match production:

```mq5
void OnTick() {
   V2_ApiCounterMaybeReset();
   V2_RunDailyRolloverReconciliation();
   Long_OnTick();
   Short_OnTick();
   V2EmitTelemetry(false);
}
```

**Rationale:** Production ordering verified; daily gate consumes once per broker-midnight tick via `V2_RolloverTryConsumeDailyGate`.

### 6. Remove redundant include from `carry.mqh`

Deleted `#include "fxmatrix_v2_exits.mqh"` from `fxmatrix_v2_carry.mqh`. Not replaced with `exits_r1.mqh` — parent `.mq5` provides the exits surface before carry functions are invoked.

**Rationale:** Production `.mq5` files already include `exits.mqh` directly before `carry.mqh`. Keeping the internal include would duplicate `V2_ModifyExitLimitPrice` / `V2_ResolvePositionTicket` once ported into `exits_r1.mqh`.

---

## Negative space (explicit non-goals)

- No changes to CloseBy queue logic beyond `OrderSend` substitution.
- No addition of `open_depth` / `entry_time` to `_ref` layer structs.
- No merge/rename of `Long_ResolvePositionTicket` / `Short_ResolvePositionTicket`.
- No modifications to production `.mq5` or production-only modules.
- No full n=500 parity suite in this pass (targeted regression only).

---

## Testing

### Unit tests

`ea/fxmatrix_v2_ref_tests.mq5` (separate compilation unit — cannot co-include `exits.mqh` and `exits_r1.mqh` due to duplicate function bodies):

- `Test_ExitsR1_ResolvePositionTicket` — zero ref returns zero.
- `Test_ExitsR1_ModifyExitLimitEarlyExit` — zero ticket early exit, no API increment.
- `Test_ExitsR1_OrderSendCountedWiring` — early-exit paths do not increment; direct `V2_OrderSendCounted` increments once (same GlobalVariable counter pattern as `Test_ApiCounterIncrementAndRollover` in `fxmatrix_v2_tests.mq5`).

Existing `fxmatrix_v2_tests.mq5` carry/API/rollover math tests remain valid — that file includes `exits.mqh` before `carry.mqh`.

### Targeted regression

Single-window MT5 backtest: **GBPUSD 5-day** (`2026.03.09`–`2026.03.14`, Model=4 real ticks), `fxmatrix_v2_ref.ex5`. Entry/exit/reload integer counts must match pre-change `_ref` baseline (Phase-1 parity methodology — no hash comparison).

Rollover log lines (`INFO [V2-ADR-045] RunDailyRolloverReconciliation firing`) must appear once per broker midnight in-window without error.

---

## Consequences

- `_ref` EAs now carry-adjust resting exit limits and count API sends identically to production wiring shape.
- `carry.mqh` is exits-module-agnostic — safe for both production (`exits.mqh` parent include) and `_ref` (`exits_r1.mqh` parent include).
- Telemetry `account_daily_api_count` fields will now reflect sends from `_ref` instances once deployed (previously read counter but never incremented on `_ref` send paths).
