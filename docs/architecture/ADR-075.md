# ADR-075 — Parameterized ExecuteSystemSweep (Tier 1 + Tier 3 Consolidation)

**Status:** Accepted

## Context

ADR-074 fixed Tier 3's magic-filter scope gap and unconditional inventory clear via `ExecuteEmergencySystemSweep()`. A read-only audit of Tier 1 (`ClosePodPositions()`) confirmed two parallel bugs in the same "drifting copy" class:

### B1 — Missing `req.position` on hedging close

`ClosePodPositions()` built `TRADE_ACTION_DEAL` requests with `req.symbol`, `req.volume`, `req.magic`, etc., but **never set `req.position`**. On FTMO hedging accounts this opens a new opposite-direction deal instead of closing the existing position.

Direct three-way comparison confirmed the correct pattern already existed in:
- `CloseAllPositions()` — `req.position = ticket`
- `ProcessCloseByQueue()` — `req.position` + `req.position_by` (`TRADE_ACTION_CLOSE_BY`)
- `ExecuteEmergencySystemSweep()` — `req.position = ticket`

### B2 — Single-magic order cancel filter

`ClosePodPositions()` order-cancel loop checked **`EA_MAGIC` only**, missing `EA_MAGIC+1` (add_next layers) and `EA_MAGIC+2` (exit hedges) — the same Cause-1 shape as the 2026-07-02 Tier 3 incident.

### B7 — Pending-ticket coma risk (scoped mode)

After amputation, stale `g_pending_bid[]` / `g_pending_offer[]` / `g_add_next[]` for the amputated slot would cause the flat-quote loop (`FXMatrix.mq5` ~366) to `continue` forever on a nonzero stale ticket — silent permanent freeze on that pod.

### Consolidation rationale

Fable 5 git-history finding: safety lessons were "trapped in comments" across three diverging implementations instead of one audited shared path. Tier 3 was consolidated in ADR-074; Tier 1 now uses the same engine.

## Decision

Rename and generalize:

```mql5
void ExecuteSystemSweep(int target_instrument = -1)
```

| Mode | `target_instrument` | Scope | Detach |
|------|---------------------|-------|--------|
| Full (Tier 3) | `-1` (default) | All triad symbols, all magics | `g_halted` + `ExpertRemove()` |
| Scoped (Tier 1) | `0` / `1` / `2` | `GetInstrumentSymbol(target_instrument)` only, all magics | No halt, no detach |

### Implementation-critical details

1. **`int target_instrument = -1` sentinel** — matches existing slot idiom (`SLOT_AC/BC/AB` = 0/1/2); `-1` is new but consistent with "no slot selected" convention.

2. **Scoped cancel avoids friendly fire** — scoped mode does **not** call `CancelAllPendingEntries()` (unscoped; would cancel Layer-0 entries on healthy pods). Inline loop filters **both** symbol match **and** all three magic offsets.

3. **Pending-global clearing (scoped only)** — zeros `g_pending_bid/offer/add_next[target_instrument]` after sweep; full sweep skips this (reattach reload).

4. **Selective purge scope** — full: all three `g_inventory_*`; scoped: matching array only via `PurgeClosedLayers()`.

5. **Self-contained per call** — `close_attempted[]` and `still_open[]` are function-local. Tier 1 can amputate multiple pods sequentially in one tick (no shared state leak).

### Severity split (deliberate, not philosophy change)

- **Tier 3:** full sweep + halt + detach (unchanged intent).
- **Tier 1:** scalpel — one pod amputated, other two continue (Staff Architect ruling).

`ClosePodPositions()` becomes a thin wrapper preserving verbatim log strings for search continuity.

## Separate finding — `GlobalDrawdown` (Preliminary P)

Grep of live `ea/` codebase: **`GlobalDrawdown` appears only in its `Globals.mqh` input declaration** — no consumer in production code. ADR-055 documents it as retained but no longer used in circuit breaker logic. Legacy temp snapshots used it against `g_peak_equity`.

- **Value:** `0.03` (3%)
- **Comment:** claims "4.5% global — front-runs FTMO 5% daily limit"
- **Assessment:** dead input; comment is stale **and** mismatched to value. Not corrected in this ADR — removing or rewiring requires separate decision. Only `MaxPodDrawdown` comment fixed (`2%` → `3%`, matches operative Tier 1 threshold).

## Negative space

- Batched 5×50 ms verification poll — unchanged, shared
- `CancelAllPendingEntries()` function — unchanged; not called from scoped mode
- ADR-071 / ADR-072 — untouched

## Consequences

- Tier 1 closes positions correctly on hedging accounts (`req.position` set)
- Tier 1 cancels all magic variants on the amputated symbol only
- One audited sweep implementation for Tier 1 and Tier 3
- Tier 1 preserves multi-pod operation; Tier 3 retains nuclear detach
