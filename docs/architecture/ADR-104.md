# ADR-104: Unified V2 Engine Phase B Implementation

**Status:** Accepted (implementation complete; parity gate NOT passed)  
**Date:** 2026-08-03  
**Spec:** `docs/architecture/UNIFIED_V2_ENGINE_DESIGN_SPEC_DRAFT.md`  
**Phase:** B (engine body, thin shells, extended tests, compile check)

---

## Context

Phase A delivered pair presets, cap-bridge declarations, and the pure L0 core (`V2_L0CoreComputeBc/Ab`) with bid/ask fallback semantics aligned to production. Phase B consolidates the ~1,500-line duplicated logic from three production EAs into one shared engine and three thin deployment shells.

---

## Decision

Implement the Unified V2 Engine **behind new filenames only**. Production files remain untouched:

| Production (unchanged) | Unified (new) |
|------------------------|---------------|
| `fxmatrix_v2.mq5` | `fxmatrix_v2_unified_gbpusd.mq5` |
| `fxmatrix_v2_eurusd.mq5` | `fxmatrix_v2_unified_eurusd.mq5` |
| `fxmatrix_v2_eurgbp.mq5` | `fxmatrix_v2_unified_eurgbp.mq5` |

Shared body: `ea/fxmatrix_v2_engine.mqh` (~1,533 lines).

---

## What Was Built

### Engine (`fxmatrix_v2_engine.mqh`)

- Single copy of Long_/Short_ layer logic, rollover (ADR-101), telemetry, API counter, chart handlers.
- Pair routing via `g_preset.magic_*`, `g_preset.tel_instance_*`, `V2_L0ComputeBid/Offer`, and `V2_EngineDeadbandSpreadRef()`.
- Cap operations exclusively through `V2_Cap_CheckBlocks`, `V2_Cap_RecordBlock`, `V2_Cap_Sync` (no direct cap-module calls, no cap `#include`s).
- ADR-102 halt gate: symbol filter → deal classification via `g_preset.magic_*` → halt check → return before mutation.
- ADR-103 OnInit: `Long_OnInit`/`Short_OnInit` → orphan scan → conditional cap publish per side → telemetry on orphan → fail/warn paths.

### Thin shells

Each shell: preset fragment + pair-specific cap headers + cap-bridge implementations + production-default inputs + compile-compat inputs (`InpL0DeadbandVolScale`, `InpLegAC`/`InpLegBC`, unused cap thresholds) + `#include "fxmatrix_v2_engine.mqh"` last.

### Tests (`fxmatrix_v2_tests.mq5` v1.10)

- Pure-core L0 tests: cold-start, ease ramp, floor, invalid bid/ask fallback (BC + AB, including bid>0/ask==0 half-spread guard).
- Pair-label linter (§5.1) and magic-literal grep (§5.2) against `fxmatrix_v2_engine.mqh`.

## Authorization Scope

**This ADR authorizes:**

- The unified implementation existing behind `fxmatrix_v2_unified_*.mq5` and `fxmatrix_v2_engine.mqh`.
- Continued development and syntax/unit-test verification on those artifacts.

**This ADR does NOT authorize:**

- Replacing, renaming, or modifying production `fxmatrix_v2*.mq5` files.
- VPS deployment or live/demo attachment of unified shells.
- Any cutover decision.

**Production replacement requires:**

1. Full parity gate per spec §8 and ARCHITECT.md Mandatory Refactoring Parity Gate (all three pairs, all five canonical windows, real-tick tester config).
2. A separate future ADR or explicit cutover decision after parity passes.

---

## Consequences

- Bug fixes to trading logic should land in `fxmatrix_v2_engine.mqh` (or Phase A shared headers) and propagate to all three shells automatically.
- Cap-specific verbose logging from production `EnsureAddNext` was removed from the engine (pair-specific net-exposure prints); blocking semantics unchanged via shell bridges. EURGBP `V2_AnyCapBlocksNewAdd` retains internal eval logging.
- Until parity passes, production EAs remain the authoritative runtime artifacts.
