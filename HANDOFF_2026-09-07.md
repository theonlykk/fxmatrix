## 2. TODAY'S DEFECT AND FIX (context for anyone reading cold)

**The account is HEDGING.** Confirmed directly: a buy at 0.85889 and a sell at
0.85925 were open simultaneously under the same magic. On a hedging account an
opposing limit order does NOT close a position — it opens a new one.

fxgrind's `Grind_PlaceLimit` never set `req.position`, so every exit opened an
opposing position and left its layer naked. Invariant `I3_SHORT_NAKED` caught it
on the first fill and both EURGBP instances halted in place. Total cost across
eight unintended positions: **-$0.23** — the failed exits hedged the layers they
failed to close, so the book drifted toward flat rather than accumulating risk.

**Fix (merged, `cda7679` + `8491d96`):**
- Ported v2's `TRADE_ACTION_CLOSE_BY` queue with per-side arrays, backward
  iteration, retry limit and halt-on-exhaustion (`ea/grind_closeby.mqh`)
- Exit fill (`EXT` + `DEAL_ENTRY_IN`) queues the pair; scalp and realised P&L
  now accrue on `DEAL_ENTRY_OUT_BY`, NOT `DEAL_ENTRY_OUT` which never occurs
- Invariants I3/I4 amended: a layer is covered by EITHER a resting `EXT` order
  OR an open `EXT` position awaiting CloseBy
- Reconstruction derives the CloseBy queue on init from paired `ENT`/`EXT`
  positions at the same slot/side/layer; idempotency guard inside
  `Grind_QueueCloseBy` because the dedup array is wiped on restart

**Architectural lesson worth keeping:** the retired SRE's CloseBy deal-pairing
was NOT legacy complexity to escape. It is the necessary second half of this
exit model on a hedging account. fxgrind kept the model and dropped the
machinery. Recorded in ADR-125.

## 3. RULED BUT NOT BUILT — next cycle

### 3.1 Add-pacing gate (RATIFIED 2026-09-07)

**Nothing currently limits how fast layers are added.** A single fast tick fills
every resting entry it passes. The layer cap bounds the destination, not the
velocity, and Gate A is equity-based so fast deep fills hit the $500 daily limit
immediately.

V1 had this and it was lost in the V1→V2 transition, not in the move to
fxgrind. Source: `ea/Globals.mqh:30`, `MinLayerIntervalSeconds = 300`, enforced
at `ExecutionEngine.mqh:1149` and `FXMatrix.mq5:274`.

**Ruling:** reinstate at **300 seconds** (one M5 bar).

**The argument that settled it:** pacing does not optimise entry price — it
throttles the *velocity of drawdown*. An unpaced grid absorbs its full layer cap
in one tick on a news break, taking a vertical equity hit before anyone can
react. A 300s pace takes layer 1 and waits, giving five minutes to observe and
halt.

**Statelessness (Gate 1 preserved):** derive from `POSITION_TIME` of the
previous layer, which MT5 records natively. Before placing `L03`, check
`TimeCurrent() - PositionGetInteger(POSITION_TIME)` of `L02`. No persistence,
survives restart.

**Also ratified:** keep deepening pace and re-engagement pace DISTINCT, as V1
did. `MinLayerIntervalSeconds` throttles accumulation of underwater inventory;
`ExitResetDelaySeconds` (V1 default 30s) prevents immediate re-entry after a
scratch at the same micro-level. Different failure modes; do not merge.

**Layer cap unchanged.** Cap and pacing are orthogonal — cap dictates solvency,
pacing dictates velocity. Do NOT raise the cap because accumulation is
rate-limited.

### 3.2 Widening ratchet — REJECTED (RATIFIED 2026-09-07)

V2 had a three-part mechanism (`fxmatrix_v2_engine.mqh:470-484, 670, 704, 722`):
widen spacing x1.304 beyond depth 3; partial reset anchoring the next add on the
**exit price** at the tight floor when a layer scalped out (the `V2_Reload` vs
`V2_Add` distinction); full reset when the side went flat.

Read as a regime heuristic: widen while a trend runs, tighten on the first
unwind.

**Ruling: rejected on all three counts.**

- **Pacing renders widening redundant.** Both attack toxic accumulation in a
  trend. Pacing is superior because it keys on exogenous time — widening just
  stretches the grid and buys the whole move anyway.
- **The reload anchor is permanently dead.** Reconstructing "a scalp recently
  completed" would require parsing `DEAL_ENTRY_OUT_BY` history in `OnInit`,
  destroying Gate 1's comment-only reconstruction.
- **Depth-derived widening rejected for this cycle** even though it IS
  derivable and would preserve Gate 1 — because fixed geometry is what allowed
  simulator/EA parity, and reintroducing widening invalidates the entire sweep
  that selected the current coordinates.

**Geometry stays fixed at `add = 2.0 x width`.**

### 3.3 OPT/ALT slot allocation — OPEN, needs a decision

Gemini's directive was to dedicate next cycle's OPT/ALT slots to **pacing vs
no-pacing** rather than the current exit-elasticity test (5/5 vs 5/7).

**This is worth pushing back on before accepting.** Pacing is a *risk control*.
If it works you want it on both arms; you do not A/B a circuit breaker by
running half the fleet without one. Exit elasticity is an *edge question* the
two-slot design was built for, and it has produced zero data so far.

Both are legitimate uses of two slots. Decide deliberately rather than inherit.

## 4. JPY ANALYSIS — COMPLETE, BRANCH PARITY VERIFIED

Merged as `8e48094`. The JPY pip-value branch in `sim_costs.py` had never
executed against real data; it now has assertions.

**Broker facts, observed live:** USDJPY 153.630, AUDJPY 110.883, CHFJPY 189.850
— all three decimals. So a JPY pip is 0.01.

**Verified independently, not just via the test suite:**

| Check | Result |
|---|---|
| USDJPY `pip_size` | 0.01 |
| Pip value in JPY @ 0.01 lots | 10.0 |
| Pip value in USD @ rate 153.63 | **0.0651** (vs 0.10 for a USD-quoted pair) |
| AUDJPY, CHFJPY | identical 0.0651 — base currency does not leak |
| Direction | higher rate gives LOWER USD value (divide, not multiply) |
| 3-pip scalp net | **0.1353** (not 0.24) |

**The JPY branch works. No reroute of the ring needed.**

**Two findings from reading the code:**

1. **`point` in this codebase means "one pip in price units", NOT the MT5 tick
   size.** Confirmed by usage — all P&L math uses `pip_size`, and
   `grid_sim_v4_fixed.py:56` comments "point already IS 1 pip in this
   codebase's convention". So USDJPY's `point=0.01` is internally consistent
   despite three-decimal quotes. Misleading name; correct behaviour. Worth
   renaming someday.

2. **`conversion_pair` is metadata that nothing reads.** Callers pass
   `conversion_rate` explicitly. Adding AUDJPY/CHFJPY specs needed no logic
   change — but it means **something will have to supply the USDJPY series** the
   way `load_aligned_gbpusd_closes` supplies GBPUSD for EURGBP, before any JPY
   pair can be swept. That is a real gap, not yet addressed.

**Spreads recorded as PROVISIONAL:** USDJPY 1.1, AUDJPY 1.6, CHFJPY 2.6 pips —
single-observation Labor Day snapshots, commented as such in source. Must be
re-measured before informing any deployment decision.

### 5.1 THE DATA CONSTRAINT — the important finding

**A live terminal only holds ~16 months of M5 history.** Confirmed empirically:
a chart-side `CopyRates` script returned ~100,000 bars per symbol reaching back
only to **2025.05.02**, despite "Max bars in chart" being set to Unlimited. So
the cap is not the chart setting and not chunking.

**The working route is the Strategy Tester**, which downloads its own history
independently of the chart cache. This is how the existing five regime windows
(including Truss 2022 and vaccine_rally 2020) were produced.

**The tool that did it was untracked.** `DataExporterEA.mq5` and
`fetch_truss_crisis.py` lived only in the gitignored `temp/` folder on one
machine. They produced every window the project has ever analysed. **Now tracked
at `scripts/`** as of `973d83d`.

Key mechanism in `DataExporterEA.mq5` — the retry loop on error **4401**
("history updating") is the Tester fetching on demand. That is what reaches
2022. Do not remove it.

## 7. STANDING DISCIPLINES THAT EARNED THEMSELVES TODAY

- **Verify against committed source, never a self-report.** Three of today's
  bugs were found by reading code rather than trusting output.
- **Fail closed.** The invariant caught a fundamental design defect on the first
  live fill and halted rather than compounding it. Total cost: 23 cents.
- **Report, do not fix, when the cause is unclear.** Cursor stopping to ask
  about `net_mtm` composition prevented a wrong-but-plausible P&L field.
- **Never adjust an expected value to match output.** That converts a test into
  a description, and it is how the flat-pip bug survived months.
- **One owner for shared logic, plus a cross-implementation parity test.** The
  cost model diverged across fourteen files precisely because it had neither.
