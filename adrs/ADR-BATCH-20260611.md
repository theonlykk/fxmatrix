## ADR-004 — Physical Ledger Ground Truth

**Status:** Accepted (Gemini ruling)
**Context:** Live globals (g_strongest/g_weakest, signal state) can
rotate between order placement and fill. Deriving a layer's identity
from globals at fill time recorded wrong instruments/directions.
**Decision:** At fill time, `HandleEntryFill()` derives instrument and
direction from the broker deal (`deal_symbol`, `deal_type`), never
from globals. Routing indices are reverse-derived from the physical
fill. `exit_symbol` always comes from `L.instrument`.
**Consequences:** Layers are immune to signal rotation races. Caveat
(audit F4): the layer-inheritance path for layer_idx > 0 still trusts
Layer 0 and must validate deal_symbol against it.

## ADR-005 — Highlander Rule

**Status:** Accepted
**Context:** Multiple simultaneous pending entry limits across symbols
caused orphan fills and cross-symbol pod corruption.
**Decision:** Exactly one pending entry limit may exist at any time,
tracked by `g_pending_entry_ticket`. New entries require the slot to
be free; pod teardown sweeps all EA-magic pendings.
**Consequences:** Eliminates competing-entry races. Cost: an
unfillable pending order (e.g. corrupted add_next, audit F1) blocks
all entry activity until invalidated.

## ADR-006 — CloseBy as the Approved Exit Mechanism

**Status:** Accepted
**Context:** Hedging account: an exit limit fill opens an opposing
position rather than closing the original. Netting the pair at market
pays spread twice.
**Decision:** All exits route through `TRADE_ACTION_CLOSE_BY` pairing
the original position with the hedge position. Tester retcode=10013
is retried via an async queue (max 10 retries); retcode=10025 (no
changes) is treated as success.
**Consequences:** Spread-free position netting. Requires ledger-desync
handling; queue retry pacing and closed-vs-desynced detection need
hardening (audit F8).

## ADR-007 — Linear Escalating Threshold

**Status:** Accepted (Patch 3.3 reverted exponential)
**Context:** Patch 3.2 introduced exponential spacing via
ThresholdMultiplier; backtests degraded vs the linear baseline.
**Decision:** Layer N enters at `BaseThreshold + N × ThresholdStep`
(0.0004 + N × 0.0002). Exponential code removed; if ever reintroduced
ThresholdMultiplier must be > 1.0.
**Consequences:** Run 39 baseline (+$122, PF 2.71) established on
linear spacing. Grid density predictable; deep dislocations add
layers at a constant rate.

## ADR-008 — Passivity Sign Convention: T Passed Directly (Patch 7)

**Status:** Accepted — partially invalidated by audit F2/F3
**Context:** Patch 4's MathAbs(T) and the earlier r_GB/r_EU
cross-contaminated formulas produced wrong USD-pair entry prices.
**Decision:** `InvertSpreadToPrice()` receives the signed spread T
(always negative; spread = scores[weakest] − scores[strongest]).
EURUSD/GBPUSD: BUY uses r_target = T, SELL uses r_target = −T, price
= anchor × MathExp(r_target). EURGBP retains MathExp(−T) on the
anchor ratio. Passivity guard returning −1.0 is never removed.
**Consequences:** USD-pair BUY/SELL entry math now reproduces current
market exactly (audit-verified). Open issues: EURGBP BUY case is
sign-wrong (F2) and bid-frame anchors break SELL passivity (F3) —
both awaiting Gemini re-ruling.

## ADR-009 — Value-Based Hysteresis Rotation Guard (Patch 6)

**Status:** Accepted
**Context:** A committed pending entry was being cancelled whenever
the per-bar signal flipped routing, churning orders on noise.
**Decision:** On routing change with a live pending order, rotate only
if the candidate's live |spread| exceeds the pending routing's live
|spread| by RotationThreshold. On rejection, lock g_strongest/
g_weakest/g_entry_spread/g_signal_active back to the pending routing
so the nudge block computes prices for the committed instrument.
**Consequences:** Order churn reduced; nudge consistency preserved.
CarryEngine unaffected (reads layer fields). Wart: MathAbs accepts a
sign-flipped dislocation as active (audit F12).

## ADR-010 — Pending Entry Invalidation on Signal Change (Patch 5)

**Status:** Accepted
**Context:** DeepSeek critical finding: a pending entry limit for a
faded signal could fill hours later into a stale dislocation.
**Decision:** Each bar close, if the pending order's symbol/direction
no longer matches the live routing and hysteresis approves rotation,
the order is cancelled via targeted TRADE_ACTION_REMOVE with
SaveInventoryState(); cancel failure (fill race) defers one bar.
**Consequences:** Stale fills largely eliminated; combined with
ADR-011 closes the orphan-source class behind the April 28 pass-1
corruption.

## ADR-011 — Cross-Symbol Cancel Sweep (Patch 5a)

**Status:** Accepted
**Context:** `CancelAllPendingEntries()` filtered by _Symbol (EURGBP
chart), so EURUSD/GBPUSD pendings survived pod teardown — log-proven
to fill later into foreign pods (April 28 incident).
**Decision:** The sweep cancels ALL orders carrying EA_MAGIC across
all symbols, no _Symbol filter.
**Consequences:** Orphan source closed. Residual gap (audit F7): the
early-return when g_pending_entry_ticket == 0 skips the sweep
entirely; to be removed.

## ADR-012 — Carry Spread Sign (ADR-003 fix)

**Status:** Accepted
**Context:** Carry recalculation originally rebuilt the spread with
inconsistent index order, flipping its sign for some routings.
**Decision:** `new_spread = scores_fwd[weakest_at_entry] −
scores_fwd[strongest_at_entry]`, the same convention as entry. Daily
17:00 recalc; same-day layers skipped; retcode 10025 = success;
SaveInventoryState() after the loop.
**Consequences:** Carry-adjusted exits move toward market when the
position pays carry (audit-verified economically coherent). Open
risk: OrderModify on unverified tickets can halt the pod (F9).

## ADR-013 — MaxLayers = 20

**Status:** Accepted
**Context:** Grid needs a hard cap; InitGlobals() validates 1..20.
**Decision:** A pod may hold at most 20 layers; the next-layer chain
stops at capacity (`capacity_ok` in HandleEntryFill).
**Consequences:** Bounds worst-case inventory to MaxLayers ×
BaseLotSize. Note (audit §12): 20 layers at scaled lot sizes can
breach FTMO daily DD — the effective cap must be derived from risk
math, not a constant, before sizing up.

## ADR-014 — No Delays as Canonical Test Mode

**Status:** Accepted
**Context:** "Random delay" tester mode is non-reproducible; patch
comparisons across runs were inconclusive.
**Decision:** All baseline and regression backtests run with
No delays, EURGBP M5, 2026.03.07–2026.06.07, $10k, 1:30. Random-delay
runs are exploratory only and never cited as baselines.
**Consequences:** Run-to-run diffs attributable to code changes.
Caveat (audit F15): one log file per run and a build identifier in
OnInit are required for the determinism guarantee to be auditable —
run46_patch7.log contained 13 passes from ≥3 binaries.
