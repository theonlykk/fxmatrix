## T-1 — A deal handled twice

**NEEDS-FIX.** The event path marks seen before processing: `Grind_ReplayMarkSeenIfOurs(trans.deal, magic); Grind_ProcessDeal(...)`. If `Grind_ReplayMarkSeenIfOurs` fails to select but `Grind_ProcessDeal` later succeeds, the deal is processed but not seen; the sweep then replays it. `Grind_ProcessDeal` unconditionally calls `Grind_ArchiveRecordFill(deal_ticket, magic);` before the handler idempotency checks, so a second replay produces a duplicate `fill_log` row even though `Grind_HandleSideDealFill` returns early on `if(Grind_DealWasProcessed(deal_ticket)) return;`. Smallest fix: have `Grind_ProcessDeal` return a status (selected/read/processed) and mark seen only after that status is true.

## T-2 — A deal never handled

**BREAKS.** The same pre-marking is the dangerous direction: `Grind_ReplayMarkSeenIfOurs(trans.deal, magic);` marks the deal seen after its own `Grind_DealSelect`, but before `Grind_ProcessDeal` calls `Grind_ArchiveRecordFill` and `Grind_HandleSideDealFill`, both of which call `Grind_DealSelect` again. If either later select fails, the deal is seen and never replayed. The ADR’s GQ2 condition is “mark seen only after the deal was selected and read”; the code satisfies that for the first select, not for the handler’s select. There is also an init-while-disconnected underflow: `const datetime margin_back = last_sweep_time - margin_s; return (init_time > margin_back ? init_time : margin_back);`. If `Grind_HistNow()` returns 0, `last_sweep_time - 120` wraps and the sweep can permanently fail. Smallest fix: make `Grind_ProcessDeal` return whether the deal was successfully selected/read, and mark seen only then; guard `init_time <= 0`.

## T-3 — Timer and tick replays vs the event path

**HOLDS** with caveat. The handler reads `g_grind_ent_sent_this_tick`: `if(g_grind_ent_sent_this_tick) { if(use_try_lock) Grind_Adr152SetDueForSide(is_long); return false; }`. A timer replay does not reset it, but the event path also sees whatever value the last tick left. A tick replay inside `OnTick` runs before `Grind_OnTickEngine` resets it, so it may defer an add to the later `Grind_EnsureAddNext` pass. No duplicate book effect proven.

## T-4 — The guards

**HOLDS.** ENT guard: `if(Grind_FindLayerByPosition(side, position_id) >= 0) { Print(... "ERROR duplicate ENT ignored"...); return; }`. Live position IDs are unique, so an entry position cannot equal an existing layer’s `exit_position_ticket`. EXT guard: `if(side.layers[layer_idx].exit_position_ticket == position_id && position_id != 0) return;`. Recon and C77 both queue the close-by when they set `exit_position_ticket`, so the guard does not swallow a legitimate first delivery. Marking processed before the guard only feeds `Grind_DealWasProcessed`, which is the idempotency check.

## T-5 — Tick path

**HOLDS.** `Grind_ReplayCheckInvariants` does `bool ok = Grind_ReplayInvariantOk(); ... return Grind_ReplayInvariantOk();`. The second call overwrites `g_grind_last_invariant_ok`, `g_grind_invariant_reason`, and `g_grind_invariant_detail`; on success the second call clears the reason via `Grind_CheckBookInvariants`. A same-tick re-check that passes calls `Grind_QuarantineStep(true, ...)` once, releasing quarantine without counting the transient failure. That matches D5/SQ2.

## T-6 — C77

**HOLDS** with cost note. `Grind_ExitQFindExitDealPosition` now reads by ticket: `const ulong deal_ticket = Grind_HistDealTicket(i); ... Grind_DealGetInteger(deal_ticket, DEAL_ORDER) ...`. This is valid live; no `HistoryDealSelect` replaces the list inside the loop. The 30-day window `Grind_HistSelect(now - 30 * 86400, now + 3600)` only runs on the miss branch, because `Grind_ExitQHoldCancelLayer` first tries `Grind_CancelPendingOrder(ticket, magic)` and then `Grind_SelectOurOrder(ticket, magic)`. Newest-first order returns the latest matching deal; for 0.01-lot limit orders there is normally exactly one deal per order.

## T-7 — Cost and bursts

**NEEDS-FIX.** The sort is O(n²): `for(int a = 0; a < snap_count - 1; a++) { for(int b = a + 1; b < snap_count; b++) {`. Phase 1 also calls `Grind_ReplayIsSeen(t)` inside the history loop, and `Grind_ReplayIsSeen` is a linear scan: `for(int i = 0; i < g_grind_replay_seen_count; i++)`. After a long disconnect the sweep window can be large, making both costs grow badly. One sweep can also send many exit requests through `Grind_ExitQManageSide`; the per-tick `g_grind_ent_sent_this_tick` pacing only limits adds, not exits. Smallest fix: sort once with a non-bubble method or cap the sweep batch; at minimum document the resync burst.

## T-8 — Telemetry

**NEEDS-FIX.** Started disconnected: `if(!was && connected) { long down_ms = -1; if(g_grind_replay_down_since_ms != 0) down_ms = ...; }` emits `CONNECTION_RESTORED` with `down_ms=-1`. `DEAL_EVENT_MISSED` only considers replayed deals: `if(!g_grind_replay_seen[i].replayed) continue;`, so a deal seen by the event path but never processed is invisible.
