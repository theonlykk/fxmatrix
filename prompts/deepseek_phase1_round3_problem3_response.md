## Q1 — Can `max_spread_allowance` exceed 15pt?

No, with the current code constants.

`V2_SRE_NominalSpreadPoints()` returns:

| Symbol | Points |
|---|---|
| EURUSD | 10 |
| GBPUSD | 15 |
| EURGBP | 15 |
| unknown/default | 10 |

So the maximum allowance is `15 * point`. The arithmetic:

```
G           = 90 * point
base_tol    =  2 * point
allowance   = 15 * point
margin      =  1 * point

pass implies max_shift < 90 - 2 - 15 - 1 = 72 * point
reach = max_shift + base_tol + allowance < 72 + 2 + 15 = 89 * point < 90 * point
```

That part is correct, *provided the guard constant and the allowance are always sourced from the same symbol-specific value*. That is a maintainability risk, not an immediate arithmetic break.

---

## Q2 — Does SHORT create a LONG/SHORT asymmetry?

Not in the simple envelope arithmetic. `V2_RolloverShiftedExitPrice()` reflects direction, but the distance to the adjacent grid layer is still `G` in absolute price terms, so the `max_shift + base_tol + allowance < G` bound is direction-symmetric.

The real asymmetry is not LONG vs SHORT. It is:

> The guard uses the **paired entry’s** max_shift, but the hedge may actually belong to a **different layer** whose own rollover shift is not bounded by that value.

Both LONG and SHORT have a mirror construction for that failure.

## Q3 — Is `MaxPossibleRolloverShift` a strict upper bound?

**No.**

`V2_SRE_MaxPossibleRolloverShift()` does:

```mql5
units = V2_SRE_CountRolloverMultiplierUnits(open_time, now);
swap  = V2_SRE_QuerySwapForDirection(symbol, direction); // current swap
return V2_RolloverShiftPrice(swap, units, point);
```

`V2_SRE_QuerySwapForDirection()` returns the **current** `SYMBOL_SWAP_LONG` / `SYMBOL_SWAP_SHORT`. MT5 does not provide historical swap rates through this call.

Therefore:

- If the swap rate was **higher** during the hold than it is at reconstruction time, actual accumulated drift exceeds the computed `max_shift`.
- The midnight counter itself is not the primary problem; the **magnitude multiplier** is the problem.
- The guard therefore does **not** guarantee `actual drift < 72pt`.
- Worse: in a crossed CloseBy group, the hedge may have been produced by an adjacent layer whose actual drift is even further outside the paired entry’s computed max_shift.

This is exactly the under-estimation path the question asks about.

- Current swap at reconstruction time: `1 pt/day`
- Historical swap during `L1`’s hold: `10 pt/day`

Then:

- `L1`’s actual exit-target shift:
  ```
  9 days * 10 pt/day = 90 pt
  ```
- `L1`’s adjusted exit / hedge price:
  ```
  P = E1 + 90 = (E0 - 90) + 90 = E0
  ```

Now suppose the CloseBy group is crossed: it pairs `L0`’s entry with `L1`’s hedge.

The check computes for `L0`:

```
max_shift = current swap 1 pt/day * 10 days = 10 pt
guard: 10 < 72  → does not halt
expected_adj = E0 + 10
```

With the proposed uniform allowance:

```
T = 2 + 15 = 17
acceptance interval = [E0 + 10 - 17, E0 + 10 + 17]
                   = [E0 - 7, E0 + 27]
P = E0  → inside interval
```

**HALT_30 passes on a genuinely wrong cross-pair.**

Under the current ADR-108 zero-rollover gate, `L0` has `rollover_units > 0`, so `A = 0`, `T = 2`, and the interval is `[E0 + 8, E0 + 12]`. `P = E0` is outside, so it halts. The proposed change is what turns this fail-closed case into a silent pass.

The SHORT mirror is identical with signs reversed: a later/higher short layer’s hedge shifted downward by ~90pt lands on an earlier/lower layer’s expected target.

---

## Why the safety proof fails

The proof says:

> Any pair reaching the check has `max_shift < 72`, so `max_shift + T < 89 < 90`.

That is true **only for the paired entry’s modeled center**. It does not bound the actual price of the hedge if the hedge comes from a different layer. The crossed hedge price is:

```
P = E_pair ± G + S_actual_hedge_layer
```

The guard only bounds `max_shift` of `E_pair`, not `S_actual_hedge_layer`. If swap rates were higher historically, `S_actual_hedge_layer` can be large enough to cancel the `±G` grid offset, and the spread allowance provides the extra room needed for the residual to fit inside the acceptance band.

---

## Recommended disposition

Do **not** ship the proposed uniform spread allowance with the lowered 72pt guard, unless you can replace `MaxPossibleRolloverShift` with a genuine upper bound on the actual hedge-origin drift. MT5 does not expose historical swap rates through `SymbolInfoDouble`, so the current function cannot provide that bound.

The zero-rollover gate is not redundant; in the construction above it is the only thing preventing the crossed pair from passing. If you want to fix the availability false-positives for genuine overnight covers, the safe path is to derive the actual accumulated swap from deal-level data (e.g., `DEAL_SWAP` on the actual positions / CloseBy deals) rather than from the current symbol swap rate.
