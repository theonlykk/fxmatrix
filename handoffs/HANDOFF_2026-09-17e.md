## 6. PASSIVE ROLL -- PREFERRED MECHANISM (operator, 17:20Z)

Instead of closing the oldest layer at market, **re-target its exit to the
passive side of the market** (long: sell limit a tick above bid) and let it
be lifted. Same slot freed, no spread crossed.

Why it is better than the market close:
- **Keeps ARCHITECT s1 / ADR-125 "never crosses the spread".** The ejection
  is an exit re-target, which ADR-135b's carry pass already does; only the
  size of the shift is new. Removes most of Gemini's "spread-crossing stop
  loss" objection; it stays a stop loss in the realised-loss sense.
- **Saves ~1 pip per roll** (spread) plus slippage risk.
- **Self-timing (the operator's point).** The engine adds only after a layer
  leaves, so:
  - ejection fills = price ticked up = exactly when a fresh bid below makes
    sense, and the slot frees at that moment;
  - ejection does not fill = free fall = we keep the deep layer (nothing
    realised) and do NOT add into the move. Exposure is identical either way
    (P layers, ~$0.10/pip at 0.01): 7 old + 1 new vs the 8 already held
    differ by a constant already in MTM.
- **Both legs become passive:** removing the oldest layer does not move the
  deepest, so the add target is unchanged and rests as a bid instead of
  clamping to market (unless price is already >1 add step below the ladder).

Mechanics to settle in the ADR:
- Reuse `Grind_CarryShiftSet` / shift-aware I6, but the carry shift bound
  ((nights+7) x nightly max x 2 pips, grind_carry.mqh ~502) is far too small
  for a ~90-pip ejection: needs its own bound and its own telemetry.
- The ejected layer is deep and currently HELD, so giving it a live exit adds
  one order outside the K/H rule -- one more guard unit while it rests (s3).
- Manual execution today is NOT recommended: held layers have no exit order
  to move, hand-placed orders carry magic 0 (recon will not own them), and a
  fill while attached looks like a vanished position (quarantine -> halt).
  Keep using detach -> close -> reattach until the EA supports it.

**Simulator:** add a fourth mode `roll_passive`. Its distinctive outputs are
the ejection fill rate and time-to-fill; that is the number this idea turns
on. The running sweep stays useful: stall vs roll-at-cap vs roll-on-fill and
P=4 vs P=8 are unaffected -- passive changes HOW the slot is freed, not
whether freeing it pays.

## 6a. PASSIVE ROLL CHANGES THE EXIT QUEUE (ADR-151 amendment)

With passive roll, a side's live exits become **ranks 0-1 (required) + rank 2
(allowed) + the ejected oldest layer**. The middle layers stay held. The
shape is "newest few plus one oldest", and the hidden middle is temporary in
both directions. Four consequences the ADR must state:

1. **Exemption from the trim.** Today the ranking cancels any exit that falls
   to rank 3 or deeper; the ejected layer is the deepest on its side, so the
   next fill would cancel it. It needs an explicit `EJECTED` state that
   ranking and trimming skip.
2. **Slot accounting becomes K + H + 1 per side** -- one more order and one
   more guard unit per ejection while it rests (s3).
3. **Reconstruction must accept a non-formula exit.** The ejected exit is far
   from entry +/- exit_pips, so I6 fails unless the offset is stored per
   ticket (as the carry shift already is) with its own, much larger bound.
4. **Un-eject rule.** If price recovers and the ejected layer climbs back to
   rank 0-2, its exit returns to the formula price. And **at most one
   ejection per side at a time**, or several deep layers stack at market.

Docs to correct when this lands: `MEMO_2026-09-16_order_purgatory.md` and
ADR-151 both state that only the nearest ranks hold live exits.
