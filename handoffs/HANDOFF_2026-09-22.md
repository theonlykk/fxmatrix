## 1. ADR-156 -- STARTUP EXIT SHORTFALL (C2) -- DONE

**The problem (found at boot, confirmed by the previous chat).** F1 requires
an exit on rank 0 AND rank `depth - 1`. At `OnInit` a missing required
exit failed I3 and halted PERMANENTLY; the retry ran only on success.
EVERY manual roll produced one (the new deepest was an uncovered middle
layer); so could a restart in a fill gap or while a gate held an exit.
Both reviews had judged the migration test moot because the account would
start flat. It was not.

**The fix.** Startup rebuilds tolerating a missing required exit,
`Grind_RetryMissingExits` places it, the OnTick check stays strict. Per-side
counters; `WARN STARTUP_EXIT_SHORTFALL long=a short=b`; CRITICAL telemetry
`STARTUP_EXIT_SHORTFALL_SIDE` when a side is missing both. No halt.

**No re-quote -- and why.** The entry guard counts
`positions + orders + resting_entries` (entries twice: each needs a slot
for its exit) and allows an entry only at <= 194. It stood at 195, so
EVERY entry in the fleet was blocked; `api_count` stayed flat (381 -> 383

freed by cancelling ALT's L01 ENT (#547124584) was taken **0.3 s later**
by GBPUSD OPT (S L04 #547150684).

**Behaviour at the ceiling:** one scalp out, one entry in; exits never
compete (they need `used <= 199`, used was 169); the free slot goes to
whichever instance ticks first, so busy symbols win. A roll only moves
layers around the fleet. **Not a bug -- ADR-151 working as designed.**
