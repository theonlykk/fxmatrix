## 3. ROOT CAUSES

### 3a. Phantom layers AND missing short scalp events -- FIXED (ADR-127)

One defect, two symptoms.

- `Grind_OnTradeTransactionEngine` offers every DEAL_ADD to the long handler,
  then the short handler.
- The OUT_BY branch of `Grind_HandleSideDealFill` called
  `Grind_MarkDealProcessed` BEFORE checking whether a layer on that side owned
  the deal. The processed set is shared by both sides.
- So the long pass consumed every short CloseBy deal. The short pass returned
  early: no `scalp_closed` event, and the short layer was never removed.
- Introduced in `1b9e255` (2026-09-07). V2 used per-side processed sets.
- Tests missed it: S1 closes a long through the dispatcher; S3 called the short
  handler directly.

Evidence: all 13 SHORT scalps on 2026-09-10 were never emitted (backfilled,
`stack_depth: null`). The 14th missing event was a LONG on a halted instance
(3b). Four phantom short layers at 03:11Z on 09-11, each matching a short
CloseBy with no event.

Fix: mark processed only inside the loop, after a layer on this side matches.

- `d45d341` tests only (CB1-CB4 through the real dispatcher).
  Operator GUI run: **614/628**, exactly CB1, CB3, CB4 failing as predicted.
- `e486bb9` fix + `docs/architecture/ADR-127-closeby-out-by-mark-on-match.md`.
  Operator GUI run: **628/628**.
- Gemini: approved, no amendments. Fast-forward merged, deployed 05:04Z.

**ADR-127 status stays Proposed until live confirmation:** the first short
scalp after 05:04Z must appear in `/scalps/` with a non-null `stack_depth`
and leave no phantom. Likely first candidates: AUDCHF_ALT, EURGBP_ALT,
EURGBP_OPT (short exits resting).

### 3b. GBPUSD_OPT LONG scalp at 16:42:14 broker -- EXPLAINED, not a defect

A short on the same instance filled at 16:42:08 broker with no exit and halted
it (`I3_SHORT_NAKED`). A halted EA returns early from `OnTradeTransaction`, so
the scalp six seconds later was never queued. The invariant runs on EVERY
tick in `OnTick`, not on the heartbeat, so the halt was near-immediate.

### 3c. I5_SHORT_DUP on EURUSD_OPT, 2026-09-10 -- MECHANISM CONFIRMED

From the VPS Journal (times UTC; broker = +3h):

    14:25:17.708  EA sends modify on long L0 #539505969
    14:25:45.174  short L0 #538969489 FILLS 1.16231 (deal #517147122)
    14:26:09.431  modify returns "done in 51722 ms"
    14:26:09.431  NEW sell limit sent at 1.16277       <- same millisecond
    14:26:34.920  exit for the 1.16231 layer sent
    14:26:46.073  L01 add sent at 1.16371
    14:31:57      recompile of all twelve (deinit reason=2)
    14:35:50.738  stray #539592770 FILLS 1.16282 (deal #517163065)
    14:35:50.739  exit sent at 1.16161 -- the FIRST layer's price
    14:36:58      heartbeat shows I5_SHORT_DUP, two exits at 1.16161

Defects this exposes (none fixed yet):

1. **Stale state after a blocking send.** `OrderSend` blocked 52 s. The fill
   arrived meanwhile; the same `OnTick` continued with tracker depth 0.
2. **`Grind_TryPlaceL0` treats "cannot select my order" as "order gone"** and
   places a new L0. It cannot tell filled from cancelled.
3. **The fill's transaction only clears the tracked pending if tickets match**
   -- by then they don't, so order B stays live under a side with a layer.
4. **Exit placement finds the layer by index**, so the second L00 fill placed
   a second exit at the first layer's price, leaving the new position naked.
5. **Reconstruction adopts a lone L0 pending without checking the side is
   empty** (and an add on an empty side). The 14:31 recompile carried the
   stray forward rather than rejecting it.

### 3d. Missing exits (I3_*_NAKED) -- HYPOTHESIS, NOT PROVEN

- The invariant rebuilds from the broker book every tick, with no grace window.
- Exit placement happens in `OnTradeTransaction`.
- If a tick is processed after a fill is visible but before its transaction,
  I3 fires, `g_grind_halted` is set, and the transaction handler returns early:
  the exit is **never attempted** (answering the 09-10 open question).
- Fits: non-deterministic, twins in the same second diverging, three of four
  I3 halts at 15:30-15:32 broker (08:30 New York, densest ticks).
- 3c's 10-50 s sends make stale-state windows far wider than assumed.
- Testable once the send log exists: the CRITICAL line should precede any
  exit attempt for that ticket.

Also established: **the invariant only checks the broker book's
self-consistency; it never compares against the EA's tracker.** That is why
phantom layers kept `invariant_ok: true`.

## 5. OPEN ITEMS

**7. Timestamps.** `close_time` is broker time labelled `Z`. Decision: broker
time stays the source of truth; the EA drops the `Z`; Postgres stores
`*_broker` plain `timestamp` columns plus `received_at timestamptz`. Convert to
UTC only in analysis, from `received_at` minus broker time rounded to the hour.
Ships with the Postgres action endpoint.

**8. Cap would block every entry if enabled.** `grind_cap.mqh`: instances
publish exposure keys only for their own two legs; the reader sums a leg across
six hardcoded magics and treats an absent key as MAXED. EURUSD summing EUR reads
GBPUSD's `_EUR` key, which never exists, so it blocks. `GRIND_CAP_ALL_MAGICS`
also omits the AUD/CAD/CHF magics. Every enabled-threshold test asserts BLOCK;
T29 and M3 pre-seed all six keys, masking it. Inert today (thresholds 0.0).
Gate: thresholds stay 0 until fixed; a failing ALLOW test in a realistic
topology is the prerequisite. Design choice for Gemini: publish zero for
non-traded currencies, or sum only peers trading that currency. Combine with the
16-instance ring magic change.

**12. Send latency.** Journal "done in" times, 14:16-14:36 UTC on 09-10, 13
sends (modifies and placements): 9.9 s to 51.7 s. Broker, or twelve EAs
queueing through one terminal? Enabling condition for 3c and probably 3d.

**13. A fill worse than its limit.** Sell limit #538969489 modified to 1.16244
(done 14:17:21 UTC); no further lines for that ticket; filled 1.16231 at
14:25:45 UTC. A sell limit should fill at or above its price: 1.3 pips worse.
Matters a great deal for a market maker.

**14. Statics survive a parameter reinit.** `OnTimer` switches from the 1 s
startup timer to `TelemetryIntervalSec` behind a `static` flag. A reinit
(reason 5) keeps statics, so the heartbeat stays at 1 s -- roughly 1.9 GB/day
of extra log for three instances. Workaround: remove and reattach, or
recompile.

**15. API counter.** Counts sends the terminal rejected locally (Algo off):
167 -> 1287 in about nine minutes. `GRIND_DAILY_API_LIMIT` (2000) is defined
but never enforced; only a warning at 1800. FTMO's rule is more than 2,000
server requests per day on opening, modifying or closing orders; rejected-local
attempts never reach the server. Real server requests on 09-11 are far below.

**16. Daily counters are in-memory only.** `scalps` survives the day boundary
while P&L resets (EURGBP_OPT showed scalps 1, P&L 0). Every recompile zeroes
both. Dashboard "today" figures are unreliable after a deploy; `scalp_history`
in Postgres becomes the durable record.

**17. Scalp P&L read from one OUT_BY deal.** The backfill script found the
broker can book CloseBy profit on either leg; the EA reads only the entry-leg
deal. Emitted values so far look right for EA-issued CloseBys. Recorded in
ADR-127, not addressed.

## 8. OPERATIONAL LESSONS AND TRAPS (new this session)

**Phantom signature:** layers with `has_exit_position: true` while
`book.positions` is empty and `net_mtm` is 0.

**Phantom cleanup procedure** (now needed only for non-CloseBy causes):
fresh status read; Algo off; delete any add orders anchored on phantom layers;
reinit the affected instances; status read; Algo on; status read.

- **Deleting a stray add with Algo on is futile:** while a phantom layer remains,
  `Grind_EnsureAddNext` re-places it on the next tick.
- **Pressing OK in EA properties without a change does NOT reinit.** Change a
  harmless input (e.g. append to `InpConfigWarning`) to get `deinit reason=5`.
- **A parameter reinit keeps statics** (item 14). Remove/reattach or recompile
  resets them.
- **Repo presets have a blank `TelemetryAPIKey`** (public repo). If a dialog
  shows it blank, the instance goes dark on pipshed. Do not share screenshots of
  the properties dialog; the key is visible.
- **Grep VPS logs by price, not time** -- log times are UTC. The Journal is the
  only current source for send latency ("done in N ms") and fills.
- **Pipshed fetches:** the chat UI converts pasted URLs into links whose hidden
  target can differ from the visible text; paste on its own line or in a code
  block. A fetch can fail transiently (ROBOTS/SERVER error) -- retry once before
  diagnosing. Cloudflare AI Crawl Control shows Claude-User allowed; managed
  robots.txt is off.
- **Cursor:** reported the prompt's line count as its own twice, and abbreviated
  diffs despite instructions. Always verify the branch itself.
