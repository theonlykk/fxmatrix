**Two implementation defects found before deploy, both in
`Grind_ApplyEntryHorizon`, both in the same direction -- a side silently
losing its ability to add.**

D1 (found by review, `3cfdd6c`): `in_place` cleared `add_held` BEFORE the
send. `Grind_SendNextAddEnt` returns false on guard refusal, the normal case
at 195, leaving the side neither held nor resting. The branch gates on
`add_held`, so it never retried. First placement attempt would have disabled
adds on that side for the session.

D2 (found by the suite, `9269ffd`): `in_place` gated on `add_held` at all.
`add_held` is only ever set true inside `in_cancel`, so a side that had never
been held could not place while in the place band. Same production path:
guard refuses in the floor band, price drifts into the place band, side stuck.
Fixed by dropping the gate and charging a transition only when
`was_held` -- an ordinary placement is not a D3 transition and must not burn
the 20/day budget.

Also corrected: T10 was testing a gradual approach through the floor, not a
gap, and asserted a gap count from a side the engine had correctly un-held.
Rewritten to keep the add held across the crossing, plus T10b for a gap that
lands inside the floor.

## 4. THE EVENING: PHASE 2 IS OFF, AND THE GUARD HAS NO LEVERS LEFT

Phase 2 worked. It is off because it does the wrong thing, and establishing
that closed off every remaining option for relieving the guard.

**The arithmetic problem.** ADR-152's own Context measured the clog at "adds
8-16 pips from mid". On GBPUSD `add_pips` is 10, so at
`InpEntryHorizonPips = 20` the floor rests everything inside 10 and the hold
threshold sits at 40. Nothing in the measured problem range could be held.
Gemini ruled it "mathematically inert" and had it narrowed to 12.

**At 12 it produced an unanticipated state.** Both GBPUSD long sides ended
with no resting add and `add_held` false. Their add target sat 14.2 pips from
mid, inside the 12-24 hysteresis band, where the rule is "keep whatever state
you are in". The state was "no order, not held", because an earlier placement
had been refused by the guard. The band faithfully preserved it. Not stuck --
it resolves on the next material price move -- but it is a third state the
hysteresis was not designed around.

**Operator ruling, and it is a strategy decision, not a preference.** A
resting add must ALWAYS be on the book, on every side. A missed spike is a
fill that never existed and cannot be chased, because the engine never
crosses the spread and `Grind_Adr013ClampBuy` prices a late order below the
new bid. `InpEntryHorizonPips` set to `0` on both GBPUSD charts.

**Then the exit side closed too.** The operator first said a missed exit was
"fractionally" the lesser loss, then reconsidered unprompted: "I would rather
be out of a trade wanting to be in, than in a trade wanting to be out."
Missed entry costs opportunity; missed exit leaves a position open in a
market moving away, and this fleet carries layers 70 pips underwater opened
16-Sep. Being out wanting in is a feeling; being in wanting out is a
drawdown.

**A transmission error worth recording.** The first K=1 consult was sent on
the superseded preference and Gemini ruled on it, approving K=1 AND
tightening it to H=0. The ruling was overturned on correction. The lesson is
mine: a marginal call was transmitted as settled. Gemini's rulings are only
as good as the operator position he is given.

## 5. MECHANICS LEARNED TODAY

- **A compile does NOT reload presets.** MT5 reuses inputs stored on the
  chart. Confirmed twice. A deploy is a compile PLUS a manual reattach of
  every chart, with the API key copied out and pasted back because the preset
  carries it blank. Sixteen dialogs.
- **D3 is adds only; L0 is never held.** L0 re-quotes toward mid every tick
  outside the deadband and is untouched by the horizon.
- **An add is priced off the DEEPEST LAYER, not off mid**
  (`deepest_entry -/+ add_pips`), which is how a gap between an add target and
  mid opens at all. As a ladder's deep end exits, the anchor climbs and the
  target tracks mid without any re-quote.
- **Heartbeat fields are per SIDE**, not per instance: `add_held_long` /
  `add_held_short` and so on. Better than the spec asked for.
- **The terminal log is UTF-16.** Reading it as UTF-8 silently parses zero
  rows. `scripts/fill_to_placement.py` sniffs the encoding and prints what it
  decoded.
- **Trades lines are in `Terminal\<hash>\logs`**, expert `Print` output in
  `Terminal\<hash>\MQL5\Logs`. They are different files.
- **`logs/` is gitignored.** Derived measurements belong in
  `docs/baselines/`, not there.
