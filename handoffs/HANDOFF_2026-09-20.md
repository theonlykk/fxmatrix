## 1. F1 HALTED THE FLEET -- AND THE FIRST WRITE-UP WAS WRONG

F1 (barbell exit queue) was deployed 01:08Z. **All 16 halted on
`I3_LONG_NAKED`.** Reverted 01:20Z (compiled 01:18:50Z); all recovered.

**Mechanism, verified in source (`2111eef` corrects BOOT and TRAPS):**
the barbell requires an exit on `rank == depth - 1`; every book was built
under the prefix rule, so none had one. `OnInit` -> failed
`Grind_ReconstructState` -> halted in place. `Grind_RetryMissingExits` is
in the `else` branch (`fxgrind.mq5:170`); `OnTick` does nothing while
halted; OnInit never enters quarantine. **Permanent in ANY market.** The
`[Market closed]` lines were `Grind_CancelOwnEntryOrders` on the halt
path, not exits being refused. The first write-up ("self-heals in one
tick; only the shut market stopped it") was never checked against source.

**F1 on a flat account is safe from this** (no book to fail). F1 on any
existing book needs a migration path (place-before-check, or route the
startup shortfall to quarantine). F1 also costs one extra resting exit per
side of depth >= 2: 30 slots on Friday's book, guard 195 -> 225. And the
guard under-reserves by one at the depth 1 -> 2 transition (inferred from
the rule, not read in code).

Quarantine facts (`grind_quarantine.mqh`): escalation needs BOTH >= 3000
ms AND >= 3 checks, and checks run only in `OnTick`, so a shut market does
not escalate a quarantine.
