## 1. ADR-135b BUILT AND MERGED -- DEPLOY IS GATED ON WEDNESDAY

Carry exit adjustment. Merged at `b1e0b47`; ADR status **Proposed**.

**The Wednesday test:** run `archive_counts.py --carry` Tuesday evening and
again Wednesday evening; compare `accrued_swap_long` / `accrued_swap_short`
for the same instance. The size of the overnight change identifies which
rollover carried the triple charge.

**COUPLING TO WATCH.** `deploy.ps1` pulls main, and main now contains
ADR-135b. **Any VPS deploy from now until Wednesday ships the carry pass.**
That includes adding a pair. Either wait, or deploy from a pinned commit,
which breaks the "VPS tracks main" rule.

### What it does

- Adjusts resting EXIT limits only, in the existing 23:50-23:59 broker
  window (16:50-16:59 New York), once per broker day.
- Symmetric: cost moves the exit AWAY from entry, credit moves it TOWARD.
- Amount recomputed from scratch each pass: `POSITION_SWAP` ledger (converted
  account-ccy -> pips via tick_value/tick_size/volume) plus tonight's pending
  charge at `mult_tomorrow`. Recomputing is what makes it idempotent.
- Never marketable: clamped to stay passive by `max(point, stops, freeze)`,
  reusing `Grind_Adr013ClampSell` (long exits) / `ClampBuy` (short exits).
- Sign guard before the clamp: never move an exit to the wrong side of entry.
- **I6 is now carry-aware.** `Grind_ReconExitMatchesEntry` gained a `shift`
  parameter defaulting to 0.0; both call sites look up
  `GRIND_CARRY_SHIFT_<position_ticket>`. An absent GV reads 0.0, so every
  unshifted layer behaves exactly as before. Without this, the first pass
  would halt every instance holding a shifted layer on the next tick.
- Gate persists only AFTER the pass completes (was: wrote the day then
  returned true, so a partial pass burned the day).
- Session guard: `SymbolInfoTick` ok, bid > 0, ask >= bid,
  `TimeTradeServer() - tick.time < 120s`, trade mode FULL. Uses its OWN last
  tick variable -- calling `Grind_FeedStaleAfterTick` would mutate the
  engine's global.
- Chunked 2 layers per timer call; no `Sleep()`.
- Telemetry: `CARRY_EXIT_SHIFT` per shift (with BOTH the ledger figure and a
  points-native cross-check), `CARRY_PASS_SUMMARY`, `CARRY_PASS_INCOMPLETE`.

### 2b. THE STRUCTURE IN THE DATA: SCORE TRACKS HOLD TIME INVERSELY

The ranking is almost exactly the inverse ranking by hold time. Harvesting is
about TURNOVER: quick round trips compound, slow ones do not. The four JPY
pairs hold L0 layers for ~1 day (CHFJPY 2.2 days) against AUDCHF's 26
minutes -- two orders of magnitude. **The JPY crosses are not scalping on
this grid at all.**

This also makes carry decisive for them rather than marginal: with ~1-day L0
holds a large fraction of layers cross a rollover, so carry applies broadly
instead of to a tail. At CHFJPY's 2.2-day mean hold and 0.441 markup that is
~0.97 pips per layer against a 5-7 pip exit. The four JPY pairs score
104-156 BEFORE carry and could plausibly be negative after it.

**Claude's earlier "these pairs need wider exits" call was wrong** (see
HANDOFF_2026-09-12 s3b) and so was the follow-up guess that spread would be
the discriminator. Hold time is.

Dropping CADCHF (score 1,932, ratified geometry, already live) to close the

**We have never measured that.** The sweep scores pairs independently and
never asks how their P&L co-moves. Computable from per-instance scalp history
once a few weeks exist.

### 3b. THE CAP ARGUMENT IS WEAKER THAN IT LOOKED

`grind_cap.mqh` keys exposure per `(magic, leg)` GlobalVariable, not per
currency, so a chord does not corrupt the accounting -- a currency simply
appears in three pairs instead of two and its total sums over three
instances.

**More importantly: `GRIND_CAP_ALL_MAGICS` is a HARDCODED array of the six
original triangle magics.** It does not include AUDCAD, AUDCHF or CADCHF,
which are already live, so the cap's peer-read is ALREADY incomplete for the
current fleet, chord or no chord. Any pair addition requires editing it.
(The cap remains inert: thresholds 0.0, item 8.)

## 5. CARRY MEASUREMENT ON THE LIVE FLEET

`archive_counts.py --rollovers` shipped (pipshed `b6919f0`). SQL written and
fixture-tested by Claude against real Postgres, covering 0, 1 and 3
crossings, a midnight straddle and an unclosed position.

**Why this is the right measurement:** `deal_time_broker` is NAIVE BROKER
time, so a rollover crossing is a DATE CHANGE in that column -- no timezone
arithmetic. And `fill_logs.swap` records what the broker ACTUALLY charged, so
the estimate (crossings) and the ground truth (swap_usd) appear side by side.

First run returned one row (GRIND_EURGBP_ALT, 2 layers, 0 crossings), which
is correct: `fill_logs` only starts at the ADR-131 deploy on 2026-09-11
18:04Z.

**`mean_hold_min` reads 0.0 for CloseBy pairs** because both legs close in
the same second and `deal_time_broker` has second resolution.
`deal_time_broker_msc` is available if that ever matters. The crossing count
is unaffected.

**The number to read on Friday: `pct_crossed`, split by arm.** If OPT and ALT
are both low, carry is a rounding error for this geometry and the sweep
rankings stand. If ALT is materially higher, the cycle 2 A/B bias is real and
`swap_usd` says what it cost.

## 6. CARRY IN THE SWEEP -- STILL NOT DONE, AND A POST-HOC FIX IS RULED OUT

HANDOFF_2026-09-12 s4 proposed correcting the sweep post-hoc using
`mean_l0_hold_min` x markup. **That is now ruled out for two reasons:**

1. **Carry is a STEP function on rollover crossings, not proportional to
   elapsed time.** A 19-minute trade pays nothing; a 5-minute trade
   straddling midnight pays a full day. Duration barely matters, timing does.
2. **`l0_hold_mins` covers L0 unwinds only, not adds.** In a cell with
   `cap_reached_rate` 100% and `mean_max_layers` 8.0, the layers that sit for
   days are the ADDS, which the field excludes. A correction built on it
   would return ~0.005 pips and falsely validate an uncorrected sweep.

**So carry must go into `sim_costs.py` as a real cost**, applied per layer at
exit using each layer's own rollover count -- which only the simulator knows.
That is a re-run, not an adjustment.

**Cheap first step:** export per cell the FRACTION of layers crossing at
least one rollover and the mean crossings per layer. That sizes the problem
before spending hours on the answer, and it is the same code change as adding
the cost properly.

## 7. NEW MQL5 / PROCESS FACTS

- **`(void)expr;` is NOT valid MQL5.** There is no cast to void. Cursor used
  it to suppress an unused-parameter warning in the ADR-135b stub commit;
  MetaEditor rejected it with "illegal use of 'void' type". MQL5 does not
  warn on unused parameters, so the suppression was unnecessary anyway.
- **A test that builds its own payload tests nothing.** If a test constructs
  the JSON and hands it to the emitter, it validates the emitter's wrapper,
  not the production code that would have built it. Any test for a new event
  must DRIVE the production path and assert on what IT emitted. (CX14, and
  before it the CARRY_SNAPSHOT brace bug.)
- **A branch rebuild changes every hash.** Cursor rebuilt the 135b branch
  twice; always `git fetch` and re-read the hashes before checking out.
- **Check `git branch --show-current` before committing.** The 09-12 handoff
  went to a research branch and needed a cherry-pick onto main.
